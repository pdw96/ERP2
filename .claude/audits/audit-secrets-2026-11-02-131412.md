## 관찰

### OB-1 · 서버 메시지 경로는 앞으로 입력값을 로그에 실을 수 있다
- 위치: `src/db/status.ts:36-46`(export 된 범용 함수)
- 무엇: PostgreSQL 서버 메시지 가운데에는 입력값을 그대로 담는 것이 있다(예: `invalid input syntax for type integer: "…"`).
- 왜 부적합이 아닌가: 지금 이 함수를 지나는 질의는 `select now()` 하나뿐이다.
- 알아 둘 값: 조각 「기준정보」에서 방문자 입력을 받는 질의 오류를 이 함수로 남기면, 입력값이 Vercel 로그에 실린다. 그때는 코드와 severity 만 남기거나 따로 가려야 한다. 지난 회차 OB-4(「기준정보」 회차에 audit-secrets 를 넣자는 제안)와 같은 때 다시 본다.

### OB-2 · `tlsFor` 와 드라이버가 접속할 host 를 읽는 방법이 다르다
- 위치: `src/db/client.ts:15` 와 `node_modules/postgres/src/index.js:577-586`
- 무엇: `tlsFor` 는 URL 의 authority 부분만 본다. 드라이버는 `?host=` 쿼리를 authority 보다 앞세운다. 그래서 `postgres://u:p@localhost/db?host=<원격>` 같은 값이면 원격 서버에 평문으로 접속한다. authority 가 비어 있으면(그때 드라이버는 PGHOST 를 쓴다) `tlsFor` 가 `verify-full` 을 고르므로 안전하다.
- 왜 부적합이 아닌가: 이 값을 넣을 수 있는 것은 운영자(Vercel 환경변수)뿐이다. Neon 연동이 만든 URL 은 authority 가 Neon host 라서 언제나 `verify-full` 이다. 운영 데모도 `verify-full` 로 연결됐다(호출자 관찰).
- 알아 둘 값: 코드 주석의 「내 컴퓨터의 DB 말고는 암호화」에는 이 예외가 있다. 막으려면 `searchParams.get("host")` 도 함께 본다.

### OB-3 · 미리보기 분기는 운영 데이터의 사본을 들고, 역할도 같을 수 있다
- 위치: `docs/deploy.md:29-31`, `docs/adr/0002-hosting.md:10,22`
- 무엇: 미리보기 분기는 부모 `main` 에서 만들어진다(호출자 관찰). 그래서 분기를 만든 시점의 운영 데이터를 그대로 든다. Neon 은 분기에 부모의 역할(role)을 복사한다고 알고 있다. **비밀번호까지 같은지는 확인하지 못했다(전제).** 같다면, 미리보기 배포가 쥔 `DATABASE_URL` 의 host 만 바꾸면 운영 DB 에도 접속된다.
- 왜 부적합이 아닌가: ADR 0002 가 요구하는 것은 「미리보기가 데모 DB 를 건드리지 않는다」이다. 미리보기는 분기 endpoint 를 쓰므로 그 요구는 지켜진다. 데이터도 지금은 샘플뿐이다.
- 알아 둘 값: 미리보기 배포 보호가 꺼져 있으므로(지난 OB-2), 미리보기에서 접속값이 한 번이라도 새면 운영 DB 까지 이어질 수 있다. 「기준정보」 전에 메인 세션이 Neon 커넥터로 두 분기 접속 문자열의 비밀번호가 같은지만 비교해 두면(값은 출력하지 않고) 이 전제가 갈린다.

### OB-4 · 이력 검사의 기준 문구가 이제 문자 그대로는 맞지 않는다
- 위치: `src/db/__tests__/client.test.ts:5`
- 무엇: U-1 의 근거는 「`neon.tech` 0건」이었다. PR C 가 `postgres://u:p@ep-x.us-east-1.aws.neon.tech/...` 라는 자리표시자를 더했다. `u:p` 와 `ep-x` 는 실제 endpoint 꼴이 아니다.
- 왜 부적합이 아닌가: 이 값으로는 아무 자원에도 접속되지 않는다.
- 알아 둘 값: 레포를 공개로 바꾸기 전(조각 「포트폴리오 정리」)에 이력 검사를 다시 돌린다. 그때 이 줄이 걸리므로 `u:p@` 를 예외로 두고 본다.
