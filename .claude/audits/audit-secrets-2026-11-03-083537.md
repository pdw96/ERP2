## 확인불가 항목

### U-11 · PR C 가지의 커밋에 접속값이나 비밀값이 들어간 적 있는가
- 체크 항목: 1
- 위치: `.git` (`47b57ea..d7a103f`). 압축 오브젝트라 이 도구로 읽을 수 없다.
- 판정하려면: `git log -p 47b57ea..d7a103f | grep -nE 'postgres(ql)?://[^ "]*@|npg_|CRON_SECRET=.+|[0-9a-f]{64}'` 의 결과에서 자리표시자를 뺀 줄이 0건이면 된다.
  - 자리표시자: `db.example`, `u:p@ep-x`, `s3cret-value`, `u:secret@db.example`
  - 커밋 수와 걸린 줄 수를 함께 적어 주면 좋다.
- 누가 줄 수 있는가: Bash 가 있는 메인 세션
- 틀렸을 때 잃는 것: **높음**. 레포는 조각 「포트폴리오 정리」에서 공개로 바뀐다.

## 관찰

### OB-1 · 수정 입구가 바인딩된 `code` 의 꼴은 보지만 문자열인지는 보지 않는다
- 위치: `src/app/master/items/actions.ts:29`, `src/db/items.ts:70-72`
- 무엇: 서버 액션의 인자는 화면을 건너뛰어 아무 값으로나 보낼 수 있다. `ITEM_CODE.test(code)` 는 문자열이 아닌 값도 글자로 바꿔 시험한다(예: 원소 하나인 배열).
- 왜 부적합이 아닌가: ADR 0004 에 따라 누구나 모든 품목을 고친다. 그래서 위조로 더 얻는 것이 없다. 이상한 값이면 「없는 품목」이 되거나, DB 오류가 코드만 남기고 거절된다.
- 알아 둘 값: 조각 「인사」에서 로그인이 생기면, 이 인자가 권한을 가르는 열쇠가 된다. 그때는 `typeof code === "string"` 과 소유 · 권한 확인을 서버 액션 안에 둔다. 이 버전 Next.js 문서도 같은 것을 권한다(`server-actions.md:87-91`).

### OB-2 · 거절 응답이 보낸 사람의 입력을 그대로 되돌려 준다
- 위치: `src/db/items.ts:98-99,151`, `src/app/master/items/actions.ts:23,36,40`
- 무엇: 거절되면 `values` 에 아는 칸의 글자를 받은 그대로 담아 돌려준다. 1MB 본문 상한 안이면 칸 하나가 수백 KB 여도 그대로 되돌아온다.
- 왜 부적합이 아닌가: 되돌아가는 곳은 보낸 사람 자신이다. 다른 방문자의 데이터나 DB 행은 실리지 않는다.
- 알아 둘 값: `serverActions.bodySizeLimit` 를 올리면 이 되돌림도 함께 커진다. 칸 길이를 자르고 돌려주면 이 성질이 없어진다.

### OB-3 · postgres 드라이버의 소스 파일이 공개 경로 `/_next/static/media/` 로 나간다
- 위치: `.next/static/media/index.1e5nkbo5efwka.js` (이 PC 의 빌드 결과)
- 무엇: 이 PC 의 빌드에 오픈소스 드라이버 소스가 정적 파일로 들어 있다. 서버 쪽 조각들이 그 파일을 가리킨다.
- 왜 부적합이 아닌가: 라이브러리 코드일 뿐이다. 설정값 · 접속값 · 앱 코드는 들어 있지 않다.
- 전제: 이 `.next` 가 `d7a103f` 로 빌드됐는지는 확인하지 못했다. PR C 화면의 문구가 들어 있어서 PR C 무렵의 빌드라는 것만 안다.
- 알아 둘 값: 공개 전에 정적 파일에서 접속 문자열을 찾으면 이 파일의 `postgres://x` 가 걸린다. 자리표시자로 본다.

### 담당 없음 — 호출자 판단 필요
- **누구나 부를 수 있는 쓰기 입구에 호출 빈도 제한이 없다**
  - 위치: `src/app/master/items/actions.ts:29`, `src/db/request.ts:13-21`
  - 무엇: 서버 액션을 한 번 부를 때마다 DB 접속을 새로 연다. 수정은 행이 늘지 않아 등록 상한에 걸리지 않으므로, 반복 호출로 Neon 무료 계산 시간과 접속 수를 소진할 수 있다.
  - 어느 항목에도 안 걸리는 이유: 항목 3 은 인증 유무를 본다. 이 입구는 ADR 0004 로 일부러 열려 있다. 남는 것은 가용성 · 비용이고, 성능처럼 여섯 감사자 누구의 담당 문구에도 걸리지 않는다.
  - 누가 봐야 하나: 저자. 데모를 채용 담당자에게 건네기 전에 남용 대책(Vercel 방화벽 · 호출 제한)을 둘지 정한다. 처음 올린다.
- **배포물 · 개발 의존성의 알려진 취약점(CVE)** — **4회째**
  - 위치: `package.json:24`(`zod` 추가). 호출자는 `npm audit --omit=dev` 0건이라고 알렸다. 이 감사는 실행하지 못해 보지 않았다.
  - 어느 항목에도 안 걸리는 이유: 9번은 자격증명 설정만 본다.
  - 누가 봐야 하나: 지난 회차에서 이미 체크 항목이 비어 있다는 신호라고 적었다. 아직 정해지지 않았으므로 다시 제안한다 — 「의존성 취약점」 항목을 어느 감사자에 세울지, 아니면 CI 에 `npm audit` 을 둘지 정한다.
