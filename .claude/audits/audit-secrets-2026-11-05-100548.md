- 요구사항 「감사 회차」 줄이 이 회차에 맡긴 세 가지:

### U-16 · 저자 컴퓨터의 `.env.local` 이 이 Neon 프로젝트의 접속 문자열을 들고 있는가
- 체크 항목: 2. 레포 쪽은 적합이지만 행을 쪼개지 않는다.
- 위치:
  - `scripts/migrate.ts:11,14` — `loadEnvConfig` 가 `.env.local` 을 읽는다.
  - `.env.example:2-3`
  - `docs/adr/0010-shared-db-password.md:25` — 받아들이는 근거 「접속값은 서버의 환경변수에만 있다」
- 무엇:
  - ADR 0010 에 따라 모든 가지가 같은 역할 · 비밀번호를 쓴다. 그래서 `.env.local` 에 미리보기 가지의 주소만 있어도 그 비밀번호는 데모 DB 의 비밀번호다.
  - 그렇다면 ADR 0010 의 근거가 틀린다. 데모 DB 전권 접속값이 서버 밖(저자 컴퓨터)에도 있고, 그 컴퓨터의 `npm run build` · `next dev` 가 데모 DB 에 닿는다.
  - U-14(`audit-data`)는 마이그레이션이 **운영 `main` 끝점**에 닿는지만 본다. 이 줄은 **어느 가지든 이 프로젝트의 끝점**이면 걸린다.
  - 고칠 자리도 다르다. U-14 는 `scripts/migrate.ts` 이고, 이 줄은 ADR 0010 의 근거 줄과 `.env.example` 의 안내다.
- 판정하려면: **U-14 와 같은 저자의 답 하나면 된다.** 한 번만 물어 주세요.
  - 묻는 것: `.env.local` 이 있는가. 있으면 `DATABASE_URL` · `DATABASE_URL_UNPOOLED` 의 **호스트가 `localhost` 꼴인가, `ep-…`(Neon) 인가.** 값과 비밀번호는 옮기지 않는다.
  - 파일이 없거나 `localhost` 꼴이면 적합이다.
  - `ep-…` 이면 부적합이다. 제안은 둘 중 하나다 — (a) 내 컴퓨터는 로컬 DB 나 따로 만든 역할을 쓴다고 `.env.example` 에 적는다, (b) 받아들인다는 저자 판정을 ADR 0010 결과에 덧붙인다.
- 심각도의 전제: `ep-…` 이면 **보통**이다. 데이터는 가상 샘플이고 매일 밤 되돌려 되돌릴 수 있다. 다만 결정 기록의 근거가 틀린 채 남는다.
- 누가 줄 수 있는가: 저자(호스트 이름). 끝점 이름은 대장 U-14 에 이미 있다 — `ep-jolly-block-bbr3gj1i`.

- 무엇: 대표자 · 전화 · 이메일 · 담당자 · 담당자 연락처 · 주소 칸이 생겼다. 그래서 방문자가 자기 회사나 자기 연락처를 넣으면 되돌림 전까지 다른 방문자가 조회 · 찾기 · 시트 불러오기로 그대로 본다.
- 왜 부적합이 아닌가:
  - 설계 「보장하지 않는 것」(`design.md:53`)과 ADR 0004 가 「그날 밤까지 다른 방문자에게 보인다」를 받아들였다.
  - 매일 밤 다섯 테이블을 비운다(`reset.ts:15`).
  - 로그 · Vercel 기록에는 남지 않는다(항목 7).
  - 「실데이터를 넣지 않는다」(INTENT 1)는 저자의 규칙이지 방문자에게 건 요구가 아니다.
- 알아 둘 값: 「이상한 글」과 달리, 연락처는 넣은 사람이 공개되는 줄 모르고 넣는 정보다. 데모를 채용 담당자에게 건네기 전(조각 「포트폴리오 정리」)에 입력 화면 · 시트 위에 한 줄을 둘지 정할 만하다 — 「누구나 보고 매일 밤 지워집니다. 실제 정보를 넣지 마세요」. 실제 데이터를 넣게 되는 때(ADR 0010 결과)에는 이 성질 자체를 다시 본다.

## 안 본 것
- **브리핑이 자른 파일 가운데 읽지 않은 것:**
  - 화면 부품 본문 — `item-form` · `partner-form` · `warehouse-form` · `code-form` · `*-list` · `*-inquiry` · `sheet-grid` · `sheet-load-filters` · `form-parts` · `saved-notice`. 가져오는 모듈만 grep 으로 봤다.
  - `schema.ts` · `numbering.ts` · `deploy.ts` · `sample.ts` 본문(`sample.ts` 는 grep 만)
  - 마이그레이션 SQL · 스냅숏, `package-lock.json`, 시험 본문 대부분
  - 고친 문서 — `architecture.md` · `schema.md` · `master-plan.md` · 설계의 대부분
- **실행:** 시험 · 빌드 · `npm audit` 을 돌리지 않았다. `node_modules` 가 없어 이 버전 Next.js 의 서버 액션 문서와 `@next/env` 의 로그 동작은 직접 보지 않았다.
- **저장소 밖:** GitHub 비밀값 · Actions 의 fork 설정, Vercel 환경변수(`CRON_SECRET` 이 Production 에만 있는지), 미리보기 배포 보호.
- **`audit-quality`:** 「방문자 글자가 로그에 없다」 시험이 `savePartnerSheetAction` · `loadItemSheetAction` · `loadPartnerSheetAction` 에는 없다. 코드는 같은 꼴(`code-only`)이라 이번 판정은 코드를 읽어서 했다. CI 의 `npm audit` 통과 여부도 이쪽이다.
- **`audit-data`:** NC-9 · U-13 · U-14 그대로.
- **`audit-internal`:** 샘플 · 시험의 이름 · 연락처가 실제 회사 · 사람과 겹치지 않는지(CLAUDE.md 금지 규칙). 이 회차는 비밀값 꼴만 봤다.
- **`audit-ops`:** `deploy.md` 의 말머리 실패 줄 목록에 시트 저장 · 불러오기 줄이 「따위」로만 묶인 것이 운영자에게 충분한지.
