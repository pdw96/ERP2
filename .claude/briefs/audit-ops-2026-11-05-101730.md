+# ADR 0014 — PR 이 닫히면 GitHub 자동 작업이 미리보기 DB 가지를 지운다
+
+- 날짜: 2026-11-05
+- 상태: 정함
+- 조각: 기준정보
+
+## 맥락
+
+Vercel 의 Neon 연동은 PR 의 미리보기 배포마다 Neon 에 DB 가지(`preview/<가지 이름>`)를 만든다 — 미리보기가 데모 DB 를 건드리지
+않게 하는 장치다(`docs/deploy.md` 2 의 5). 이 레포의 연동은 Vercel 화면에서 이은 방식(Vercel-Managed)이라, DB 가지는 Git 가지가
+아니라 **Vercel 의 미리보기 배포가 지워질 때** 지워진다. Vercel 은 최근 미리보기 배포 20개를 보관 기한과 상관없이 남겨, 이 레포처럼
+PR 이 드문 곳에서는 DB 가지가 사실상 지워지지 않는다(Neon 문서 「Managing Vercel preview branch cleanup」).
+
+2026-11-05 에 가지가 무료 요금제의 한도 10개(데모 1 + 미리보기 9)에 차서, PR #20 의 미리보기 배포가 「Resource provisioning
+failed」로 시작도 못 했다. 저자가 「GitHub 에서 가지를 지우면 Neon 도 지워지지 않나」를 물었다 — 위 까닭으로 아니다.
+
+## 대안
+
+1. **PR 이 닫히면 GitHub 자동 작업이 Neon API 로 그 가지를 지운다** — Neon 이 권하는 방법. Neon 의 API 키를 GitHub 비밀값으로 둔다.
+2. **머지할 때마다 Neon 콘솔에서 손으로 지운다** — 비밀값을 늘리지 않는다. 잊으면 PR 아홉마다 다시 막힌다.
+3. **Neon-Managed 연동으로 바꾼다** — Git 가지를 지우면 다음 미리보기 배포 때 DB 가지를 지운다. 연동을 다시 잇고 환경변수가 바뀐다.
+4. **Vercel 의 미리보기 보관 기한을 줄인다** — 「최근 20개」 보존이 있어 이 레포에서는 효과가 없다.
+
+## 결정
+
+1 을 고른다(저자 판정, 2026-11-05).
+
+- 작업 파일은 `.github/workflows/preview-db-cleanup.yml`. `pull_request_target` 의 `closed`(머지 · 닫힘 둘 다)에 돈다 —
+  PR 쪽이 아니라 `main` 의 작업 파일이 돌아, PR 의 가지가 **이 작업 파일을 고쳐** 열쇠를 꺼내지 못하고(push 권한자가 다른 작업
+  파일로 꺼내는 길은 남는다 — 아래 「결과」), 머지 충돌이 있는 PR 을 닫아도 돈다. PR 의 코드는 받지도 돌리지도 않는다.
+- 열쇠는 **이 Neon 프로젝트 하나로 좁힌 API 키**(project-scoped)다. 비밀값 `NEON_API_KEY`, 프로젝트 ID 는 변수 `NEON_PROJECT_ID`.
+  조직 전체 열쇠 · 개인 열쇠는 쓰지 않는다. 넣는 순서와 만든 뒤 범위를 확인하는 단계는 `docs/deploy.md` 「5. 미리보기 DB 가지 지우기」.
+- 지우는 것은 이름이 `preview/<그 PR 의 가지>` 와 꼭 같고 기본(데모) 가지가 아닌 것 하나뿐이다. 없으면 할 일 없이 끝난다.
+- 남의 레포(fork)에서 낸 PR 에는 돌지 않는다 — `pull_request_target` 은 fork PR 에도 비밀값을 주므로, 작업의 조건 한 줄이 fork 를
+  막는 유일한 장치다(지우지 않는다). fork 에는 미리보기 DB 도 없다.
+- 외부 액션을 쓰지 않고 `curl` · `jq` 로 Neon API 를 직접 부른다 — 받아 오는 코드가 없고, 지우는 조건을 이 파일에서 읽을 수 있다.
+
+## 결과
+
+- 머지한 PR 의 DB 가지가 쌓이지 않아 다음 PR 의 미리보기가 막히지 않는다. 이미 쌓인 가지는 한 번 손으로 지운다.
+- 머지한 PR 의 미리보기 주소는 DB 가 없어져 「연결 안 됨」이 된다 — 머지한 뒤에는 데모 주소를 본다.
+- **GitHub 에 Neon 의 열쇠가 하나 는다.** ADR 0004 는 매일 밤 되돌림을 GitHub 예약 작업으로 하지 않은 까닭으로 「DB 접속 정보를
+  GitHub 에도 두게 된다」를 들었다. 이 열쇠는 그보다 힘이 세다 — Neon 의 프로젝트 **Editor** 권한이라, 이 프로젝트의 가지 ·
+  DB · 역할을 만들고 지우며, 접속 문자열을 **비밀번호를 바꾸지 않고** 받아 DB 에 들어갈 수도 있다. 프로젝트 자체를 지우거나 누가
+  다룰지를 바꾸지는 못한다(Neon 문서 「User permissions」 · 「Manage API keys」). 그래서 새도 데모가 깨지지 않아 드러나지 않을 수 있다.
+  열쇠를 꺼낼 수 있는 것은 이 레포에 push 할 수 있는 사람(저자와, 가지를 올리는 Claude 세션)이다 — 이 레포의 첫 GitHub 비밀값이다.
+  받아들이는 근거 — 이 프로젝트 하나로 좁혔고, 데모 DB(`main`)는 Vercel 이 지우기를 막아 두었으며(Neon 의 restricted actions),
+  데모 데이터는 가상 회사의 샘플이라 매일 밤 되돌리고 테이블은 다음 배포가 다시 만든다(ADR 0004 · 0010). 새었다고 생각되면
+  Neon 에서 그 열쇠를 **Revoke** 한다.

+async function main(): Promise<number> {

+  const url = process.env.DATABASE_URL_UNPOOLED || process.env.DATABASE_URL;
+  if (!url) {

+  const { db, close } = connect(url);
+  try {
+    await prepareDatabase(db, {
