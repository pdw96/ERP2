# 조각 시작 · 닫기

조각은 가볍게 간다(ADR 0029) — 조각 문서 한 장을 대화로 보이고, 저자가 좋다고 하면 구현한다. 착공 PR 을 따로 머지하지 않고, 감사 회차 ·
부적합 대장은 없다. 규칙의 원천은 `CLAUDE.md` · `Profile.md` 와 ADR 이다 — 어긋나면 `CLAUDE.md` 를 따르고 어긋났다고 알린다.

## 시작

### 1. 어느 조각인가

- 인자로 이름을 받았으면 그 조각, 없으면 `docs/master-plan.md` 「만드는 순서」에서 상태가 「예정」이고 의존이 모두 「닫힘」인 가장 앞 조각.
- 「진행」인 조각이 남아 있으면 먼저 알리고, 닫고 갈지 저자에게 묻는다(추천과 결과를 함께).
- 가지는 `origin/main` 에서 새로 세운다.

### 2. 넘어온 물음을 모은다

앞 문서들이 「<이 조각>의 착공에서 정한다」로 넘긴 것이 흩어져 있다. 이름으로 찾는다.

```bash
grep -rn "「<조각 이름>」" docs INTENT.md | grep "착공\|정한다\|넘긴"
```

- `docs/master-plan.md` 의 이 조각 줄(목표 · 의존)과 「모듈과 메뉴」에서 이 조각이 짓는 메뉴.
- `docs/adr/` 에서 이 조각을 든 것(끝의 대체 · 덧붙임까지).
- 의존하는 조각 문서의 「닫으며」 · 「넘긴 것」.

### 3. 저자에게 묻는다

`Profile.md` 「결정을 가르는 법」대로 가른다 — 애매하면 업무 결정으로 다뤄 묻는다.

- **업무에 영향**(장부 · 화면 · 재고에 무엇이 남나)과 **앵커볼트**(재고 계산 규칙 · 업무 용어 · 코드 체계) — 저자가 정한다. 업무 장면으로 묻고,
  재고 · 생산은 선택지 먼저 · 추천은 뒤, 회계 · 인사는 일반적인 ERP 흐름을 근거로 추천 먼저.
- **업무에 영향이 없는 기술** — Claude 가 정하고 한두 줄로 알린다.
- `AskUserQuestion` 으로 한 번에 넷 이하. 물음마다 혼자 읽어도 알 수 있게.
- 샘플에 새 회사 · 사람 · 품목 이름이 들 것 같으면 그 목록을 보인다(실제와 겹치지 않게).

### 4. 조각 문서를 쓰고 보인다

- `tools/doc-check/templates/slice.md` 를 `docs/slices/<순서>-<이름>/slice.md` 로 베낀다(이름의 띄어쓰기는 붙인다). 다섯 제목은 그대로, 주석과
  `<…>` 는 지운다. 짧게 — 한 화면에 들어오게.
- 앵커볼트에 닿는 결정은 ADR 하나로도 남긴다(`docs/adr/` 의 다음 번호, 맥락 · 대안 · 결정 · 결과).
- 마스터플랜 「만드는 순서」의 상태를 「진행」, 조각 폴더 칸을 `docs/slices/<순서>-<이름>/` 로. 메뉴 · 목표 · 의존을 바꿨으면 「범위 변경」에 한 줄.
- 조각 문서를 **대화로** 저자에게 보인다 — 화면 흐름 · 정한 것 · 하지 않을 것 · PR 나눔. 저자가 좋다고 하기 전에는 구현 코드를 쓰지 않는다.

### 5. 구현

- 저자가 좋다고 하면 PR 나눔의 첫 PR 부터. 조각 문서 · ADR · 마스터플랜은 첫 PR 에 같이 싣는다.
- 진행 중에 바뀐 것은 조각 문서를 그 자리에서 고친다(살아 있는 문서).
- PR 마다 올리기 전에 `/pr-check`.

## 닫기

1. 조각 문서 끝에 `## 닫으며 (<YYYY-MM-DD>)` 를 더한다 — 몇 줄로:
   - 무엇을 했나(데모에서 어디를 누르면 보이나)
   - 넘긴 것(뒤 조각 · 「포트폴리오 정리」로 넘긴 일)
   옛 꼴(요구사항 · 설계 둘)의 조각이면 요구사항 끝에 적는다.
2. 마스터플랜의 상태를 「닫힘」으로.
3. 닫는 PR 에서도 `/pr-check` — 대조표 · 재감사는 없다.
4. 문서 검사가 통과하는지 본다: `python3 tools/doc-check/scripts/verify-docs.py --repo .`
