# ADR 0005 — 마이그레이션은 배포 빌드가 적용한다

- 날짜: 2026-11-02
- 상태: 정함
- 조각: 기준정보

## 맥락

조각 「기준정보」가 첫 테이블을 만든다. 테이블을 바꾸는 SQL(마이그레이션)을 언제 · 무엇이 DB 에 적용할지 정해야 한다.
PR 미리보기는 Neon 분기 DB 를, `main` 은 운영 DB 를 쓴다(ADR 0002). 업무에 영향이 없는 기술 결정이라 Claude 가 정했다.

## 대안

1. **배포 빌드가 배포 전에 적용** — Vercel 이 빌드할 때 그 배포의 `DATABASE_URL` 로 적용한다. 미리보기는 분기 DB 에, `main` 은
   운영 DB 에 저절로 간다. 실패하면 빌드가 실패해 배포가 나가지 않는다.
2. **앱이 켜질 때 적용** — 서버리스라 요청마다 켜질 수 있어, 여러 곳이 동시에 적용하려 할 수 있다.
3. **사람이 손으로 적용** — 저자가 명령을 쳐야 하고, 잊으면 코드와 DB 가 어긋난다.

## 결정

1 을 고른다. SQL 은 drizzle-kit 이 TypeScript 스키마에서 만들어 레포에 올린다(`docs/schema.md`).

## 결과

- 머지만 하면 DB 가 코드에 맞춰진다 — 저자가 칠 명령이 없다.
- 배포를 앞 배포로 되돌려도(Instant Rollback) DB 는 돌아가지 않는다. 그래서 마이그레이션은 앞 배포의 코드와도 함께 돌 수
  있게(더하기만, 이름 바꾸기 · 지우기는 두 번에 나눠) 쓴다 — 규칙은 `docs/schema.md` 가 든다(조각 「기준정보」 PR A 가 적는다).
- 빌드에 DB 접속이 생긴다 — 빌드가 DB 에 닿지 못하면 배포가 멈춘다. 그때 데모는 앞 배포에 남는다.
