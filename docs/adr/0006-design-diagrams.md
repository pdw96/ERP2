# ADR 0006 — 설계도를 데모 안의 그림으로 본다

- 날짜: 2026-11-02
- 상태: 정함
- 조각: 기준정보

## 맥락

저자는 코드보다 화면으로 판단하고(`Profile.md`), 글로 쓴 설계만으로는 전체가 잘 보이지 않는다고 했다(2026-11-02). 데모 안
어딘가에서 전체 설계를 그림으로 보고 싶다고 요청했다. 채용 담당자에게도 「무엇을 어떻게 지었나」를 보이는 자리가 된다
(`INTENT.md` What — AI 로 지은 과정이 보인다).

## 대안

어디에 두나는 저자가 「앱 안 어딘가」로 맡겼고, 어떻게 그리나는 업무에 영향이 없는 기술 결정이라 Claude 가 정했다.

1. **Mermaid 글을 앱이 그린다** — 그림을 글(Mermaid)로 써 두고, 설계도 화면이 열릴 때 브라우저가 그린다. 글이라 PR 의 바뀐 줄로
   그림의 변화가 보이고, GitHub 도 같은 글을 그림으로 보인다. 그리는 도구는 그 화면에서만 내려받는다.
2. **손으로 그린 SVG** — 모양은 마음대로지만, 조각마다 고치기가 무겁고 PR 에서 무엇이 바뀌었는지 읽기 어렵다.
3. **그림 파일(PNG)** — 고칠 때마다 다른 도구로 다시 그려야 하고, 바뀐 것이 PR 에서 보이지 않는다.

## 결정

1 을 고른다. 화면은 데모의 메뉴 판 아래 「설계도」(주소 `/design`)이고, 그림은 셋이다.

- **업무 흐름** — 영역 여섯(재고 · 생산 · 구매 · 영업 · 회계 · 인사)과 그 사이로 흐르는 데이터, 조각마다 진행 상태.
- **데이터 모델** — 테이블과 그 관계. 지금 있는 테이블과 뒤 조각이 더할 테이블을 가른다.
- **시스템 구성** — 브라우저 · 앱(Vercel) · DB(Neon) · 자동 검사 · 정기 확인 · 매일 밤 되돌림.

그림의 글은 한 파일(`src/content/diagrams.ts`)에 둔다. 테이블 · 부품 · 흐름을 바꾸는 PR 이 같은 PR 에서 그림도 고친다.

## 결과

- 저자와 채용 담당자가 데모에서 바로 전체 그림을 본다.
- 그림은 손으로 고치는 것이라 코드와 어긋날 수 있다 — 리뷰와 닫기 전 감사가 본다.
- 그리는 도구(Mermaid)는 설계도 화면에서만 내려받아 다른 화면을 무겁게 하지 않는다.
