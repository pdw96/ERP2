# ADR 0010 — 미리보기 DB 와 데모 DB 의 비밀번호를 지금은 나누지 않는다

- 날짜: 2026-11-03
- 상태: 정함
- 조각: 기준정보

## 맥락

조각 「기준정보」 PR B 의 감사(대장 회차 9, 확인불가 U-9)가 물었다 — 미리보기 분기 DB 와 운영(데모) 분기 DB 의 접속 비밀번호가
같은가. 저자가 Neon 콘솔에서 견주어 「같다」고 답했다(2026-11-03). Vercel 의 Neon 연동은 미리보기 분기를 운영 분기에서 떠
만들고, 그때 DB 역할과 비밀번호도 그대로 따라온다. 미리보기 주소는 로그인 없이 열린다(`docs/deploy.md` 1 의 6). 그래서
미리보기에서 접속값이 한 번 새면 데모 DB 도 열린다 — 행 상한 · 서버의 입력 검사를 건너뛰고 테이블을 지울 수도 있다.

## 대안

1. **지금은 받아들인다** — 결정으로 남기고, 로그인이 생기는 조각에서 다시 본다.
2. **지금 나눈다** — 미리보기 전용 역할 · 비밀번호를 따로 둔다. 연동이 분기를 만들 때 역할을 복사하므로, 저자가 Neon · Vercel
   화면에서 설정을 바꿔야 하고 PR 마다 저절로 나뉘는지는 해 봐야 안다.

## 결정

1 을 고른다(저자 판정, 2026-11-03). 받아들이는 근거:

- 데모 DB 에는 가상 회사의 샘플만 있고, 매일 밤 샘플로 되돌린다(ADR 0004). 실제 회사 · 사람의 정보는 넣지 않는다(`CLAUDE.md`).
- 접속값은 서버의 환경변수에만 있다 — 브라우저로 보내지 않고, 로그에 남기지 않는다(`src/db/client.ts`, `src/db/status.ts` 의
  실패 줄, 대장 NC-6). 레포의 이력에도 없다(대장 U-1 · U-10).
- 데모 DB 를 망가뜨려도 매일 밤 되돌림이나 `docs/deploy.md` 3 의 **Run** 으로 샘플로 돌아온다. 테이블을 지우면 다음 배포의
  마이그레이션이 다시 만든다.

## 결과

- 미리보기에서 새는 일이 생기면 Neon 콘솔에서 운영 역할의 비밀번호를 바꾸고(**Roles** → **Reset password**) Vercel 의 Neon
  연동이 넣는 환경변수가 바뀌었는지 본 뒤 다시 배포한다.
- 다시 볼 때: 조각 「인사」에서 로그인 · 사용자가 생길 때, 또는 실제 데이터를 넣게 될 때. 그때 나누지 않으면 사용자 정보까지
  열린다.
