# ADR 0011 — 거래처에 국가와 해외 사업자번호를 둔다

- 날짜: 2026-11-03
- 상태: 정함
- 조각: 기준정보

## 맥락

거래처의 사업자등록번호는 한국 꼴(`000-00-00000`)만 받는다(ADR 0003, 설계 ③). 해외 거래처는 번호를 비워야 등록되고, 그
나라의 세금 번호(미국 EIN · 일본 법인번호 · EU VAT 번호 등 — 나라마다 꼴이 다르다)를 둘 자리가 없다. 저자가 PR D 를 검토하며
물었다(2026-11-03). 가상 반도체 후공정 회사는 해외 고객 · 공급처가 흔한 업종이고, 국가는 뒤 조각의 흐름(영업의 수출 · 영세율,
구매의 수입 · 외화 단가, 회계의 전표)이 기댄다.

## 대안

1. **국가 칸을 이 조각에서, PR F 앞에** — 거래처에 국가(공통코드)와 해외 사업자번호(글자 그대로)를 둔다. 시트형 등록(PR F)의 칸이
   거래처 칸에 기대므로 그 앞에 짓는다.
2. **국가 칸을 PR D 에** — 같은 내용을 검토 중인 PR D 에 더한다. 테이블 변경 · 설계도 · 샘플까지 실려 PR 이 커진다.
3. **조각 「영업」 · 「구매」에서** — 수출 · 수입 · 외화 단가와 함께 정한다. 그때까지 해외 거래처는 번호를 비운다.
4. **해외 거래처를 다루지 않는다** — 데모는 국내 거래만.

국가 코드의 꼴 — (1) 국제 표준 두 글자(ISO 3166-1 alpha-2: `KR` · `US` · `JP`), (2) 세 글자(`KOR` · `USA`), (3) 이 레포가 정한 약어.

## 결정

1 을, 국가 코드는 (1) 을 고른다(저자 판정, 2026-11-03). 앵커볼트 「업무 용어 · 코드 체계」의 값이다.

- 거래처에 **국가**를 둔다 — 공통코드 묶음 `COUNTRY` 의 값을 고른다. 처음 값은 `KR`(한국)이고 새 거래처의 기본값이다.
- 국가가 `KR` 이면 **사업자등록번호**를 지금처럼 비우거나 `000-00-00000` 꼴로 받는다.
- 국가가 `KR` 이 아니면 **해외 사업자번호**를 나라마다 꼴이 달라 글자 그대로 받는다(비워도 된다). 사업자등록번호 칸은 쓰지 않는다.
- 같은 번호를 쓰는 거래처가 있으면 경고만 한다 — 사업자등록번호와 같다(설계 ④).
- 샘플 데이터에 해외 거래처를 하나 이상 더한다 — 이름은 「(가상)」으로 시작한다.
- 짓는 것은 설계 ⑥ 의 PR G(PR F 앞)다. 묶음 `COUNTRY` 가 시스템 코드인지 사용자 코드인지(화면에서 나라를 늘리는지), 처음 넣는
  나라의 목록, 해외 사업자번호의 길이는 PR G 를 열기 전에 정한다.

## 결과

- 해외 거래처도 번호와 함께 등록되고, 목록에서 국가가 보인다.
- 수출 · 수입 · 영세율 · 외화는 이 결정이 정하지 않는다 — 조각 「영업」 · 「구매」 · 「회계」가 국가를 읽어 정한다.
- 테이블 `partners` 에 칸이 더해진다 — 마이그레이션 · 되돌림 · 설계도(데이터 모델)를 PR G 가 함께 고친다.
