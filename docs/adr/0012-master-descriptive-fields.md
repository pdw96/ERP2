# ADR 0012 — 품목 · 거래처에 설명용 칸을 더하고, 규칙이 걸린 칸은 쓰는 조각에서 둔다

- 날짜: 2026-11-04
- 상태: 정함
- 조각: 기준정보

## 맥락

품목 · 거래처는 「그 칸을 읽는 조각이 생길 때 칸을 더한다」로 짰다(ADR 0003 — 계획 정보는 MRP 가 읽어서 넣었다). 그래서 품목은
유형 · 품명 · 규격 · 단위 · 조달구분 · 검사 대상 · 계획 정보, 거래처는 거래처명 · 구분 · 국가 · 사업자번호뿐이다. 저자가 PR F 를
보며 「보통의 ERP 는 품목 · 거래처에 훨씬 많은 정보가 들어간다」고 물었다(2026-11-04).

보통 ERP 에 더 있는 칸은 둘로 갈린다.

- **설명용 칸** — 적어 두고 보이기만 하고 계산이 읽지 않는다. 품목군 · 재질 · 도면번호 · 바코드 · 비고, 대표자 · 업태 · 종목 ·
  주소 · 전화 · 이메일 · 담당자.
- **규칙이 걸린 칸** — 다른 화면의 동작을 바꾼다. LOT 관리 여부(재고 수불), 기본 입고 · 출고 창고(재고 수불), 과세구분(회계),
  표준 단가 · 원가(구매 · 영업 · 생산 원가), 구매 · 판매 단위 환산(ADR 0003 이 두지 않기로 함), 결제조건 · 거래 통화 · 여신한도 ·
  세금계산서 받을 이메일(구매 · 영업 · 회계).

## 대안

- **A. 설명용 칸을 지금 더한다** — 규칙이 걸린 칸은 따로 정하지 않는다.
- **B. 그대로 둔다** — 칸은 그것을 쓰는 조각에서만 더한다.
- **C. 둘로 나눈다** — 설명용 칸은 지금 이 조각에서, 규칙이 걸린 칸은 그 칸을 읽는 조각의 착공에서 규칙과 함께 정한다.

품목군의 꼴 — (1) 대 · 중 · 소 분류를 따로(각각의 목록에서 고르고 서로 잇지 않는다), (2) 한 단계, (3) 대 → 중 → 소 를 이어서(중분류는
고른 대분류 아래 것만 — 공통코드에 「위 코드」 칸이 더 든다).

## 결정

C 를, 품목군은 (1) 을 고른다(저자 판정, 2026-11-04).

- **품목** — 대분류 · 중분류 · 소분류(각각 공통코드의 사용자 코드 묶음에서 고른다, 비워도 된다), 재질, 도면번호, 바코드, 비고.
- **거래처** — 대표자, 업태, 종목, 주소, 전화, 이메일, 담당자(한 사람 — 이름 · 연락처), 비고.
- 모두 비워도 저장된다 — 설명용이라 계산이 기대지 않는다. 목록에서 찾기 · 거르기는 품목의 분류만 더한다.
- 시트형 등록에도 같은 칸이 붙는다 — 칸의 규칙은 한 건 등록과 같다(성공 기준 11). 칸 순서는 한 건 등록 화면의 순서다.
- **규칙이 걸린 칸은 이 조각에서 두지 않는다** — LOT 관리 여부 · 기본 창고는 조각 「재고 수불」(앵커볼트 「재고 계산 규칙」), 과세구분은
  「회계」, 단가 · 원가는 「구매」 · 「영업」 · 「생산 원가」, 결제조건 · 통화 · 여신한도 · 세금계산서 이메일은 「구매」 · 「영업」 · 「회계」의
  착공에서 저자에게 묻는다.
- 짓는 것은 설계 ⑥ 의 PR H(PR F 뒤)다. 분류 묶음의 코드 이름 · 처음 값 · 샘플의 값은 앵커볼트 「업무 용어 · 코드 체계」라 PR H 를 열기
  전에 저자에게 보이고 정한다. 칸의 길이 · 전화 · 이메일의 꼴 검사는 업무에 영향이 없는 기술 결정이라 Claude 가 PR H 를 열기 전에 정한다.

## 결과

- 데모의 품목 · 거래처 화면이 보통 ERP 처럼 품목의 분류 · 사양과 거래처의 사업자 · 연락 정보를 든다.
- 규칙이 걸린 칸은 아직 없다 — 그 칸을 읽는 화면이 없는데 칸만 있으면 무엇을 바꾸는지 보이지 않는다. 뒤 조각의 착공이 칸과 규칙을 함께 더한다.
- 품목 분류가 대 · 중 · 소 를 잇지 않으므로 어긋난 조합(중분류가 다른 대분류의 것)이 저장될 수 있다. 이어야 하면 새 ADR 로 (3) 으로 바꾼다.
