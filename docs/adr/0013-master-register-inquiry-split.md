# ADR 0013 — 품목 · 거래처의 메뉴를 등록 · 조회로 나누고, 시트에서 기존 데이터를 고친다

- 날짜: 2026-11-04
- 상태: 정함
- 조각: 기준정보

## 맥락

품목 · 거래처는 메뉴 하나(「품목」 · 「거래처」)에 목록 · 한 건 등록 · 수정 · 시트형 등록을 두었다(설계 「PR C 를 열기 전에 정한 것」 —
그때 Claude 가 업무에 영향이 없는 결정으로 보고 정했다). 목록이 조회를 겸하므로 휴대폰 폭을 위해 칸을 줄였고, PR H 가 더한 분류 ·
연락처 · 비고는 목록에서 일부만 보이거나 보이지 않는다. 시트형 등록(PR F)은 새 줄만 받아, 여러 건을 한꺼번에 고칠 길이 없다.

저자가 PR H 를 보며 두 가지를 물었다(2026-11-04) — 등록 화면과 조회 화면이 따로 없는 까닭, 시트에서 기존 데이터를 고칠 수 없는 것.

## 대안

조회 —
- **A. 메뉴를 등록 · 조회로 나눈다** — 「○○ 등록」은 지금의 목록 · 한 건 등록 · 수정 · 시트, 「○○ 조회」는 모든 칸을 넓은 표로 보는 읽기 전용 화면.
- **B. 한 화면에 목록 + 상세** — 왼쪽 목록, 오른쪽 상세(바로 고침).
- **C. 그대로** — 목록에 보일 칸만 늘린다.

시트 —
- **A. 시트에서 고치기도 한다** — 찾기 · 거르기로 기존 데이터를 시트에 불러와 고치면 바뀐 줄만 저장한다.
- **B. 등록만** — 고치기는 한 건 수정 화면에서만.

## 결정

조회는 A, 시트는 A 를 고른다(저자 판정, 2026-11-04).

- 메뉴 「기준정보」 아래 「품목 등록」 · 「품목 조회」 · 「거래처 등록」 · 「거래처 조회」. 조회는 고칠 수 없고, 코드를 누르면 등록의 수정 화면으로 간다.
- 시트는 기존 데이터를 불러와 고친다. 코드 · 품목 유형은 고칠 수 없는 칸이다(등록 뒤 바뀌지 않는다 — ADR 0003). 칸의 규칙은 한 건 수정과 같다.
- 짓는 것은 설계 ⑥ 의 PR I(조회) · PR J(시트 수정)이고 PR H 뒤다. 창고는 메뉴 「재고 › 재고 기준정보」의 그대로 둔다 — 넷뿐이라 목록이 모든 칸을 보인다.

## 결과

- 보통의 국내 ERP 처럼 등록과 조회가 갈려, 조회에서 모든 칸을 한눈에 본다. 메뉴가 둘 늘고 화면이 둘 는다.
- 시트에서 여러 건을 한꺼번에 고칠 수 있다. 불러온 뒤 다른 사람이 같은 줄을 고쳤을 때의 처리 · 「사용 안 함」을 시트에서 바꾸는지는
  PR J 를 열기 전에 저자에게 묻는다(설계 ④ 의 열어 둔 것). → 정함(2026-11-05) — 다른 사람이 고친 줄은 시트 · 한 건 수정 둘 다 저장하지
  않고, 「사용 여부」는 시트에서 바꾼다. 설계 「2026-11-05 — PR J 를 열기 전에 정한 것」.
