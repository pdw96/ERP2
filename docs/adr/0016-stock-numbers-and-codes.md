# ADR 0016 — 수불의 번호와 코드: 전표 번호 · LOT 번호 규칙 · 수불 유형 · 조정 사유

- 날짜: 2026-11-05
- 상태: 정함 — 「Claude 가 낸 안」으로 적은 값은 착공 PR 검토에서 저자가 본다
- 조각: 재고 수불 · 생산실적(생산 LOT) · 구매 · 영업 · 품질(수불 유형을 더함)

## 맥락

`CLAUDE.md` 의 앵커볼트 「업무 용어 · 코드 체계」다. 수불 전표와 LOT 에 번호가 붙고, 수불 유형 · 조정 사유가 화면의 닫힌 목록이 된다.
원자재의 LOT 는 거래처가 붙인 번호를 그대로 쓰기로 이미 정했다(마스터플랜 「범위 변경」 2026-11-02). 마스터플랜에는 후보 메뉴
「시스템 관리 › 번호 규칙」이 있었다. 저자에게 물었다(2026-11-05 착공 인터뷰).

## 대안

- **수불 전표 번호** — (1) 머리 + 날짜 + 일련 `IV-20261105-001`, (2) 머리 + 연월 + 일련 `IV-2611-0001`, (3) 머리 + 전체 일련 `IV-000001`.
- **우리가 붙이는 LOT 번호** — (1) 날짜 + 일련, (2) `L` + 날짜 + 일련, (3) 품목코드 + 날짜, (4) 늘 사람이 넣음. 저자는 넷 대신
  「LOT 번호 부여 모듈을 만들어 설정한 룰로 자동 부여」를 골랐다. 그 뒤 규칙을 두는 자리로 (a) 「번호 규칙」 메뉴, LOT 만,
  (b) 같은 메뉴에서 LOT · 전표 둘 다, (c) 품목에 칸으로 — 가운데 (a) 를 골랐다.
- **회사마다 다른 꼴** — 저자가 물었다(착공 PR 검토): 하이픈이 들어가는 LOT, 숫자만인 LOT 도 담기나. (1) 규칙마다 구분자 칸 하나를 더한다,
  (2) 고정 글자 · 날짜 · 일련 · 품목코드 · 창고코드 같은 조각을 마음대로 늘어놓는다, (3) 구분자 없이 그대로. 저자가 (1) 을 골랐다.

## 결정

### 수불 전표 번호

- `IV-YYYYMMDD-NNN` — 머리 `IV`, **수불 일자**, 그날의 일련(001 부터, 999 를 넘으면 자리가 는다). DB 꼴 `^IV-[0-9]{8}-[0-9]{3,}$`.
  취소 전표도 새 번호를 받고 원래 전표를 가리킨다.
- 재고 실사의 번호도 같은 꼴이다 — `PI-YYYYMMDD-NNN`(실사를 연 날). **Claude 가 낸 안**(머리 `PI` = Physical Inventory).

### LOT 번호

- 메뉴 **「시스템 관리 › 번호 규칙」**을 이 조각이 짓는다 — 지금은 LOT 번호의 규칙만 든다. 전표 번호는 위의 정한 꼴 그대로다.
- 규칙 하나는 **코드 · 이름 · 머리 · 구분자 · 날짜 꼴 · 일련 자릿수 · 사용 여부**다. 번호는 늘 머리 → 날짜 → 일련의 차례이고, 있는 조각
  사이에 구분자를 넣는다. 머리 `FG` · `YYMMDD` · 3자리라면 구분자 없음 → `FG261105001`, `-` → `FG-261105-001`. 머리를 비우고 구분자
  없음이면 숫자만 — `261105001`. 머리 · 날짜 꼴이 없으면 그 조각과 그 앞의 구분자가 빠진다.

| 칸 | 받는 값 |
|---|---|
| 코드 | 공통코드 값과 같은 꼴 — 영문 대문자로 시작해 대문자 · 숫자 · 밑줄 2 ~ 20자. 등록 뒤 바꾸지 않는다 |
| 머리 | 영문 대문자 · 숫자 0 ~ 6자 |
| 구분자 | 없음 · `-` · `_` · `.` |
| 날짜 꼴 | 없음 · `YYMMDD` · `YYYYMMDD` · `YYMM` — 날짜는 수불 일자 |
| 일련 자릿수 | 2 ~ 6. 일련은 날짜 꼴의 단위로 다시 센다(`YYMMDD` · `YYYYMMDD` 는 매일, `YYMM` 은 매달, 없음이면 다시 세지 않는다) |

- **품목 유형마다 기본 규칙** 하나(원자재 · 반제품 · 완제품)를 정하고, 품목에서 다른 규칙을 고를 수 있다(비우면 유형의 기본).
- LOT 관리 품목을 입고할 때 LOT 칸을 **비우면 규칙으로 저절로** 붙고, 넣으면 넣은 번호 그대로다 — 원자재는 거래처 LOT 를 넣는다.
  LOT 번호는 영문 · 숫자 · `-` · `_` · `.` 1 ~ 30자이고, 품목 안에서 같은 번호는 같은 LOT 다. 저절로 붙일 번호가 이미 있으면 다음 일련으로 넘어간다.
- 규칙은 지우지 않고 「사용 안 함」으로 바꾼다. 「사용 안 함」 규칙은 새로 고를 수 없고, 이미 고른 품목은 그 규칙으로 계속 받는다.
  유형의 기본 규칙은 「사용 안 함」으로 바꾸지 못한다. 머리 · 날짜 꼴 · 자릿수를 고치면 그 뒤에 붙는 번호부터 바뀐다.
- 샘플 규칙 — **Claude 가 낸 안**: `LOT_RM`(머리 `RM`) · `LOT_SF`(`SF`) · `LOT_FG`(`FG`), 셋 다 구분자 `-` · `YYMMDD` · 3자리(예: `RM-261105-001`), 각 유형의 기본.

### 수불 유형 · 조정 사유(공통코드)

ADR 0009 의 「뒤 조각이 자기 묶음을 착공에서 정해 더한다」에 따라 이 조각이 더한다. 값은 **Claude 가 낸 안**이다.

| Major | 이름 | 가름 | Minor |
|---|---|---|---|
| `MOVE_TYPE` | 수불 유형 | 시스템 | `IN` 기타입고 · `OUT` 기타출고 · `XFER` 이동 · `ADJ` 조정 |
| `ADJ_REASON` | 조정 사유 | 사용자 | `COUNT` 실사 차이 · `DAMAGE` 파손 · `LOSS` 분실 · `FOUND` 발견 · `ETC` 기타 |

- 수불 유형은 재고 계산이 기대므로 시스템 코드다. 구매입고 · 생산입고 · 자재투입 · 제품출고 · 폐기는 그 화면을 짓는 조각이 더한다(ADR 0008).
- `COUNT` 는 실사 확정이 쓰는 값이라 「사용 안 함」으로 바꾸지 못한다(국가 `KR` 과 같은 규칙, ADR 0011).

## 결과

- 전표 · 실사 번호만 봐도 날짜가 보인다. LOT 번호는 「시스템 관리」에서 프로그램을 고치지 않고 규칙을 바꾼다 — 구분자 · 머리 · 날짜 꼴로
  하이픈이 든 꼴 · 숫자만인 꼴을 다 담는다. 조각의 차례를 바꾸거나 품목코드 · 라인 코드를 LOT 에 넣는 꼴은 담지 않는다 — 그런 꼴이
  필요해지면 조각을 늘어놓는 방식(대안 (2))으로 바꾸는 새 ADR 을 쓴다.
- 발주 · 작업지시 같은 뒤 조각의 문서 번호를 번호 규칙에 얹을지는 그 조각의 착공에서 정한다 — 「번호 규칙」 메뉴의 나머지는 후보로 남는다.
- 바코드 · LOT 라벨은 이 조각에서 하지 않는다 — 마스터플랜의 후보 메뉴 「LOT 라벨 · 바코드」(저자 판정 2026-11-05).
- 이 결정을 바꾸려면 저자에게 먼저 묻는다(`CLAUDE.md` 앵커볼트).
