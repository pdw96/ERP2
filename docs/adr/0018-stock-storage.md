# ADR 0018 — 재고 수량을 담는 법: 수불 줄과 잔액 표

- 날짜: 2026-11-05
- 상태: 정함 — 업무에 영향이 없는 기술 결정(Claude 추천안)
- 조각: 재고 수불

## 맥락

ADR 0015 의 규칙(음수 막음 · 지난 날짜 · 취소 · 전표 단위 저장)을 DB 에 어떻게 담을지다. 화면에 보이는 것은 같고, 맞음과 빠르기가 갈린다.
데모는 무료 요금제(Neon Free 0.5GB)이고 누구나 저장할 수 있다.

## 대안

- **현재고를 무엇으로 아나** — (1) 수불 줄만 두고 늘 합을 낸다, (2) 수불 줄과 함께 **잔액 표**(품목 · 창고 · LOT · 상태마다 수량)를 같은
  트랜잭션에서 고친다.
- **동시 저장** — (1) 잔액 행을 잠그고(`SELECT … FOR UPDATE`) 정한 차례(품목 → 창고 → LOT → 상태)로 잡는다, (2) 트랜잭션 등급을
  `SERIALIZABLE` 로 올리고 실패하면 다시 시도한다.
- **LOT 없는 품목의 LOT 칸** — (1) 빈 글자 `''`, (2) `NULL`.
- **단위의 기준 · 배수 · 자릿수** — (1) 공통코드 값(`codes`)에 칸을 더한다, (2) 따로 **`unit_specs`** 표가 `UNIT` 값을 가리킨다.
- **번호의 일련** — (1) 같은 머리의 가장 큰 번호 + 1(`src/db/numbering.ts` 그대로), (2) 규칙 · 기간마다 마지막 일련을 든 표.

## 결정

- 현재고는 (2) **잔액 표**다. 수불 줄을 쓰는 같은 트랜잭션에서 잔액을 고치고, 잔액은 0 밑으로 가지 못한다(DB 검사). 시험이 「잔액 =
  수불 줄의 합」을 늘 견준다. 수불 줄은 지우거나 고치지 않는다 — 취소도 새 줄이다.
- 지난 날짜의 음수 검사는 그 키(품목 · 창고 · LOT · 상태)의 수불 줄을 (일자, 등록 차례)로 세운 누계에서, 넣는 날짜 뒤의 가장 작은 누계가
  줄일 수량 이상인지 본다 — 같은 트랜잭션에서 잔액 행을 잠근 뒤에 본다.
- 동시 저장은 (1) 잠금 차례다 — 지금 코드(잠금 안의 등록, `src/db/master-shared.ts`)와 같은 길이고 다시 시도가 없다.
- LOT 없는 품목은 (1) `''` — 유일 키 하나로 LOT 있는 품목 · 없는 품목을 다 덮는다(`NULL` 은 유일 검사에서 서로 다르게 친다).
- 단위는 (2) `unit_specs` — 공통코드 표는 모든 묶음이 같은 꼴이라 `UNIT` 만의 칸을 들이지 않는다.
- 전표 · 실사 번호는 (1) 가장 큰 번호 + 1(날짜마다), LOT 번호는 (2) 일련 표 — 넣은 LOT 번호와 섞여 「가장 큰 번호」를 읽을 수 없어서다.
- 수량은 `numeric(14,3)` — 자릿수는 단위가 정하고(ADR 0017), DB 는 셋째 자리를 넘지 않는다.

## 결과

- 재고 조회(조각 「재고 현황」)는 잔액 표를 읽어 빠르다. 잔액과 수불 줄이 어긋나면 시험이 잡는다.
- 수불 줄은 상한 없이 쌓이는 표라 검사 · 참조를 더하는 마이그레이션은 `docs/schema.md` 「잠금」의 규칙을 따른다. 매일 밤 되돌림(ADR 0004)이
  새 표도 비운다.
- 데모의 저장 쿼터를 지키려고 표마다 등록 상한을 둔다 — 수는 설계 ④ 의 열어 둔 것.
