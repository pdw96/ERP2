# ADR 0027 — 작업 규칙 둘: 착공 PR 에는 결정 문서만 · 절차 · 협업 도구의 결정을 묻는 법

- 날짜: 2026-11-12
- 상태: 정함
- 조각: BOM(착공 전에 정함) — 모든 조각이 따른다

## 맥락

조각 「재고 현황」의 감사 회차 31 이 「문서에 없어서 판정하지 못한 것」으로 둘을 올렸고(회차 32 · 33 도 넘겨 적었다), 그 조각의 「닫으며」가 「저자가 다음 조각 「BOM」의
착공 전에 `CLAUDE.md` · `Profile.md` 에 둘지 정한다」로 넘겼다.

- 「착공 PR 에는 결정 문서만 싣는다」가 레포 안에 없다 — claude-kit 의 절차 지도(`docs/procedure.md` 「설계 → 구현 관문」)와 스킬 `slice-docs` 에만 있어, 감사가 레포
  안의 글로 착공 PR 의 내용을 판정하지 못한다. `CLAUDE.md` 「금지」에는 「착공 PR 이 머지되기 전에 구현 코드를 쌓지 않는다」만 있다.
- git · PR · 절차처럼 협업 도구에 걸린 결정(감사 브리핑을 언제 커밋하나, 범위 변경에 무엇을 적나 같은 것)을 어떻게 묻는지가 `Profile.md` 에 없다. `Profile.md` 는 업무에
  영향이 있는 결정과 없는 기술 결정만 가른다. ADR 0024 의 넷은 Claude 가 추천과 근거를 먼저 보이고 저자가 골랐는데, 그 꼴이 프로필에 적혀 있지 않았다.

협업 도구 · 절차의 일이라 Claude 가 추천과 근거를 먼저 보이고 저자가 골랐다(2026-11-12 착공 인터뷰).

## 대안

- **착공 PR 의 내용** — (1) `CLAUDE.md` 「작업 방식」의 착공 줄에 「착공 PR 에는 결정 문서(요구사항 · 설계 · ADR · 마스터플랜, 범위를 고쳤으면 의도)만 싣는다」를 더한다,
  (2) 레포 밖 절차 지도를 따르는 것으로 두고 더하지 않는다.
- **절차 · 협업 도구의 결정** — (1) Claude 가 추천안과 그 결과(무엇이 어디에 남나)를 먼저 보이고 pdw96 이 고른다, (2) 업무에 영향이 없는 기술 결정처럼 Claude 가 정하고
  알린다, (3) 프로필에 두지 않고 애매하면 묻는다.

## 결정

저자가 고른 것 — 착공 PR (1) · 협업 결정 (1). 둘 다 Claude 의 추천과 같다.

1. **착공 PR 에는 결정 문서만** — `CLAUDE.md` 「작업 방식」의 착공 줄에 「착공 PR 에는 결정 문서(요구사항 · 설계 · ADR · 마스터플랜, 범위를 고쳤으면 의도)만 싣는다」를
   더한다. 구현 코드 · 시험 · 샘플 · 작업 규칙(`CLAUDE.md` · `Profile.md`) · 살아 있는 구조 문서(`docs/schema.md` · `docs/architecture.md`)의 고침은 착공 PR 에 싣지 않는다.
2. **절차 · 협업 도구의 결정은 저자가 고른다** — `Profile.md` 「결정을 가르는 법」에 「절차 · git · PR 처럼 협업 도구에 걸린 결정은 Claude 가 추천안과 그 결과(무엇이
   어디에 남나)를 먼저 보이고 pdw96 이 고른다」를 더한다. 업무에 영향이 없는 기술 결정(Claude 가 정하고 알림)과 가른다.

## 결과

- 두 줄은 이 결정의 규칙(1)대로 착공 PR 이 아니라, 조각 「BOM」의 착공 PR 이 머지된 뒤 따로 낸 문서 PR 이 `CLAUDE.md` · `Profile.md` 에 더한다(ADR 0024 결과와 같은 길).
- 규칙이 서기 전의 착공 PR 은 다시 가르지 않는다(대장 「규칙은 소급하지 않는다」).
- 감사가 착공 PR 의 내용과 협업 결정을 묻는 꼴을 레포 안의 글로 판정한다. 회차 31 · 32 · 33 의 「문서에 없어서」 가운데 이 둘은 이 결정으로 닫는다.
