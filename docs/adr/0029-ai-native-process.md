# ADR 0029 — AI-Native 로 진행: 사람은 꼭 필요할 때만 · 일 하나는 메뉴 하나 · 공식 도구만 · 덜어낸다

- 날짜: 2026-11-17
- 상태: 정함 — ADR 0027 의 1(착공 PR 에는 결정 문서만, 따로 먼저 머지)을 대체한다. ADR 0024 의 2(기록)는 범위를 좁히고, 4(감사 브리핑)는 쓸 일이 없어진다
- 조각: 「BOM」(이 결정으로 닫는다) · 그 뒤의 모든 일

## 맥락

조각 하나에 붙는 일이 무겁다. 조각 넷을 닫는 동안 감사가 33회차 돌았고 부적합 대장에 번호가 60개 넘게 쌓였다. 감사자를 주던 claude-kit(레포 밖
플러그인)이 은퇴한 뒤에는 레포 안에 전용 도구(착공 · PR 점검 스킬, 재고 계산 검토자, 기록 보호 · 형식 맞추기 훅, 문서 검사기)를 다시 지었다.

저자는 진행을 AI-Native 하게 바꾸려 한다(2026-11-17). 까닭은 넷이다.

1. 사람이 꼭 필요한 경우를 빼고는 AI 가 진행한다.
2. 조각 단위가 너무 크다 — 「BOM」은 요구사항 · 설계가 약 400줄, PR 셋에 범위 더하기까지 붙었다.
3. 프로젝트 전용 도구는 언젠가 낡는다 — 공식으로 주는 도구(Claude Code 에 든 명령, claude.ai 계정에 붙이는 플러그인 · 커넥터 · 스킬)를 쓴다.
4. 모델이 좋아지면 덜어낼 것은 덜어낸다.

## 대안

**사람이 손대는 자리** — 조각 문서 승인은 셋 다 없앤다. 다른 것은 PR 머지다.

- 가. 업무 결정만 저자 — 검사 · 시험을 지나면 AI 가 머지까지 한다.
- 나. 업무 결정 + 재고 · 생산 계산 PR 의 머지만 저자.
- 다. 업무 결정 + 모든 PR 의 머지를 저자 — 일이 작아질수록 누를 일이 는다.

**일의 단위**

- 가. 메뉴 하나가 일 하나 — PR 한두 개 크기.
- 나. PR 하나가 일 하나 — 업무 질문이 한 메뉴 안에서 흩어지고, 어느 화면이 다 됐는지가 안 보인다.
- 다. 조각은 두고 문서만 줄인다 — 까닭 2 를 못 푼다.

**도구** — 전용 도구를 남기거나, 공식 도구로 갈음하고 덜어낸다. 공식 플러그인 Vercel 은 이미 붙은 Vercel 커넥터와 겹치고 스킬 37개와 훅이 같이
들어와, AI 가 일에 맞는 스킬을 고르기 어려워져 뺐다. typescript-lsp 는 따로 까는 언어 서버가 환경마다 있어야 하고, 타입 오류는 CI 「타입」이 이미
잡아 뺐다. 플러그인을 계정에 붙이면 다른 프로젝트에도 켜지므로 레포 설정에서만 켠다(저자).

**샘플 데이터** — 메뉴마다 그 PR 이 넣거나, 묶음이 끝날 때 한 번에 넣는다(그때까지 새 화면이 데모에서 빈다).

## 결정

저자 판정(2026-11-17) — 손대는 자리는 **나**, 일의 단위는 **가**, 도구는 공식 도구로 갈음하고 덜어냄, 샘플 데이터는 메뉴마다. 모두 추천대로.

**남기는 것** — 업무가 틀리지 않게 지키는 것.

- 앵커볼트(재고 계산 규칙 · 업무 용어 · 코드 체계)는 바꾸기 전에 저자에게 묻고, 정한 값은 ADR 로 남긴다.
- 재고 · 생산 계산을 바꾸는 PR 은 시험 없이 머지하지 않는다.
- 업무에 영향이 있는 결정은 저자가, 없는 기술 결정은 Claude 가 정한다(`Profile.md`).
- 범위 변경 한 줄(ADR 0024 의 1) · 샘플 이름 규칙(ADR 0024 의 3).

**바꾸는 것**

1. **일 하나는 메뉴 하나** — 마스터플랜 「만드는 순서」의 한 줄은 왼쪽 메뉴의 화면 하나다(「라우팅」은 「공정 등록」 · 「작업장 등록」 · 「불량 유형」 ·
   「품목별 라우팅」 넷). 메뉴가 아닌 일(「포트폴리오 정리」 같은 것)은 한 줄로 둔다. 옛 조각 이름은 줄마다 「묶음」으로 남아, 다른 문서가 조각
   이름으로 가리킨 것이 이어진다. 줄의 차례 · 의존은 Claude 가 매긴다. 조각 문서 · 요구사항 · 설계는 더 쓰지 않는다.
2. **한 일의 흐름**
   1. Claude 가 의존이 다 닫힌 다음 줄을 꺼낸다.
   2. 그 메뉴의 열린 업무 결정을 ADR · 닫힌 조각 문서 · 마스터플랜에서 묶음 이름(「○○의 착공에서 정한다」 꼴)과 메뉴 이름으로 찾아 모은다. 열려
      있으면 저자에게 대화로 묻고, 답을 받기 전에는 그 결정에 기대는 부분을 짓지 않는다. 없으면 묻지 않고 짓는다.
   3. PR 한두 개로 짓고, 그 메뉴의 샘플 데이터도 같은 PR 이 넣는다. PR 본문은 「무엇을 · 왜」 · 「정한 것」(저자 판정 · Claude 의 기술 결정과
      그 대안) · 「하지 않을 것」 · 리뷰 결과.
   4. 머지 전에 `/code-review` 를, 입력 · 접속 · 비밀값에 닿으면 `/security-review` 도 돌려 그 PR 안에서 고친다. 고치지 않는 지적은 본문에 까닭을 적는다.
   5. 머지 — 재고 · 생산 계산 PR 이 아니면 CI 가 다 지나고 리뷰 지적을 고친 뒤 Claude 가 머지한다. 재고 · 생산 계산 PR 은 본문 맨 위에
      「저자 머지」를 적고, 시험 결과와 미리보기 화면을 대화로 보인 뒤 저자가 머지한다. 작업 규칙(`CLAUDE.md` · `Profile.md` · ADR)을 바꾸는
      PR 도 저자가 머지한다. 재고 · 생산 계산 PR 은 수불 · 현재고 · 실사 · LOT · BOM
      필요량 · MRP · 할당 · 생산실적의 자재 차감을 셈하는 코드, 그 입력 검사, 그 표의 마이그레이션 중 하나라도 바꾸는 PR 이다. 애매하면 저자 머지다.
   6. 그 메뉴의 마지막 PR 이 마스터플랜의 그 줄을 「닫힘」으로 바꾼다. 머지 뒤 데모 화면을 대화로 저자에게 보인다.
3. **공식 도구** — 레포의 전용 도구(착공 · PR 점검 스킬, 재고 계산 검토자, 기록 보호 · 형식 맞추기 훅, 문서 검사기)를 지운다. 그 일은 Claude Code 의
   `/code-review` · `/security-review`, 플러그인 Security Guidance, 시험 · 저자 머지 · CI 가 든다. 플러그인은 계정이 아니라 레포 설정
   (`.claude/settings.json`)에서만 켜서 다른 프로젝트에 닿지 않게 한다. 브라우저 도구(Playwright MCP)와 CI 는 남긴다. 쓰는 공식 도구를 `CLAUDE.md` 에 적는다.
4. **덜어낸다** — 새 전용 도구를 짓기 전에 공식 도구를 먼저 찾는다. 규칙 · 도구가 하는 일을 공식 도구나 모델이 대신하게 되면 지운다.
5. **기록** — 글자를 고치지 않는 기록은 ADR, 덮은 감사 기록 · 대장, 닫힌 조각의 문서다. 감사 회차는 2026-11-17(회차 34)에서 멈춘다. 그 밖의
   문서는 살아 있는 문서다.

## 결과

- 「왜 이렇게 했나」는 PR 본문과 ADR 에 남는다. 문서와 코드의 어긋남을 따로 짚는 눈이 줄고, 업무가 틀리지 않게 막는 것은 앵커볼트 · 시험 · 저자
  머지가 든다.
- 저자는 업무 질문을 받을 때와 재고 · 생산 계산 PR 을 머지할 때만 나온다.
- 진행 중이던 「BOM」은 짓는 일이 끝나, 요구사항 끝에 「닫으며」를 적고 닫는다. 닫기 전 감사 회차는 돌리지 않는다.
- 대장에 열려 있던 줄은 덮은 그대로 둔다. NC-2 · U-4(장애 기록 · 로그)는 이미 「포트폴리오 정리」로 넘겼다.
- 규칙이 서기 전의 조각 · PR 은 다시 가르지 않는다.
