# ADR 0029 — AI-Native 로 진행: 사람은 꼭 필요할 때만 · 일 하나는 메뉴 하나 · 공식 도구만 · 덜어낸다

- 날짜: 2026-11-17
- 상태: 정함 — ADR 0027 의 1(착공 PR 에는 결정 문서만, 따로 먼저 머지)을 대체한다. ADR 0024 의 2(기록)는 범위를 좁히고, 4(감사 브리핑)는 쓸 일이 없어진다
- 조각: 「BOM」(이 결정으로 닫는다) · 그 뒤의 모든 일

## 맥락

조각 하나에 붙는 일이 무겁다(저자, 2026-11-17). 조각 넷(기반 · 기준정보 · 재고 수불 · 재고 현황)을 닫는 동안 감사가 33회차 돌았고, 부적합 대장에
번호가 60개 넘게 쌓였다. 감사자들은 claude-kit(레포 밖 플러그인)에서 왔고, claude-kit 은 은퇴했다. 그 뒤 레포 안에 전용 도구를 다시 지었다 —
착공 스킬 · PR 점검 스킬 · 재고 계산 검토자 · 기록 보호 훅 둘 · 형식 맞추기 훅 · 문서 검사기(파이썬 563줄과 틀 일곱).

저자는 진행 방식을 AI-Native 하게 바꾸려 한다(저자, 같은 날). 까닭은 넷이다.

1. 사람이 꼭 필요한 경우를 빼고는 AI 가 진행한다.
2. 조각 단위가 너무 크다 — 「BOM」은 요구사항 · 설계가 약 400줄, PR 셋에 범위 더하기까지 붙었다.
3. 프로젝트 전용 도구는 언젠가 낡는다 — 공식으로 주는 도구(claude.ai 계정에 붙이는 플러그인 · 커넥터 · 스킬, Claude Code 에 든 명령)를 쓰고,
   필요하면 설치한다.
4. 모델이 좋아지면 덜어낼 것은 덜어낸다.

## 대안

**사람이 손대는 자리**(까닭 1) — 지금은 ① 조각 문서 승인 ② 업무 결정 · 앵커볼트 ③ 화면 캡처 확인 ④ PR 머지. 셋 다 ① 을 없애고 ③ 은 머지 뒤
데모에서 본다. 다른 것은 ④ 다.

- 가. 업무 결정만 저자 — 검사 · 시험을 지나면 AI 가 머지까지 한다. 잘못 들어간 것은 데모에서 보고 되돌린다.
- **나. 업무 결정 + 재고 · 생산 계산 PR 의 머지만 저자** — 나머지 PR 은 AI 가 머지한다.
- 다. 업무 결정 + 모든 PR 의 머지를 저자 — 일이 작아질수록 누를 일이 는다.

**일의 단위**(까닭 2)

- **가. 메뉴 하나가 일 하나** — PR 한두 개 크기. 조각 문서 없이 PR 설명에 몇 줄. 마스터플랜 「만드는 순서」가 메뉴를 줄로 든다.
- 나. PR 하나가 일 하나 — 가장 작지만 업무 질문이 한 메뉴 안에서 흩어지고, 「어느 화면이 다 됐나」가 마스터플랜에서 안 보인다.
- 다. 조각은 두고 문서만 줄인다 — 바꿀 것이 가장 적지만 까닭 2 를 못 푼다.

**전용 도구**(까닭 3 · 4) — 도구마다 공식 도구로 갈음하거나 덜어낸다(아래 「결정」 3). 붙일 공식 플러그인으로 Vercel 도 보았으나 뺐다 — 이미 붙은
Vercel 커넥터와 겹치고, 스킬 37개와 훅이 같이 들어와 AI 가 일에 맞는 스킬을 고르기 어려워진다(저자 지적). Next.js 문서는 `AGENTS.md` 가 가리키는
설치된 패키지 안의 문서와 Context7 커넥터가 든다.

**넣는 길**

- **가. 이 ADR(머지 전이던 「조각을 가볍게」)을 고쳐 써서 PR 하나로** — 「조각을 가볍게」를 위해 고쳤다가 쓸 일이 없어진 것(조각 문서 틀 · 문서 검사기 ·
  착공 스킬의 고침)은 지우는 것으로 끝난다.
- 나. 「조각을 가볍게」를 그대로 머지하고 ADR 0030 을 새로 — 결정이 두 장으로 보이지만, 막 고친 착공 스킬과 틀을 다음 PR 이 다시 지운다.
- 다. 규칙 · 도구만 먼저, 마스터플랜은 메뉴를 시작할 때마다 — 한동안 조각 줄과 메뉴 줄이 섞인다.

## 결정

저자 판정(2026-11-17) — 손대는 자리는 **나**, 일의 단위는 **가**, 전용 도구는 아래 3 대로, 넣는 길은 **가**. 모두 추천대로.

**남기는 것** — 업무가 틀리지 않게 지키는 것.

- 앵커볼트(재고 계산 규칙 · 업무 용어 · 코드 체계)는 바꾸기 전에 저자에게 묻고, 정한 값은 ADR 로 남긴다.
- 재고 · 생산 계산을 바꾸는 PR 은 시험 없이 머지하지 않는다.
- 업무에 영향이 있는 결정은 저자가, 없는 기술 결정은 Claude 가 정한다(`Profile.md`).
- 범위 변경 한 줄(ADR 0024 의 1) · 샘플 이름 규칙(ADR 0024 의 3)은 그대로다.

**바꾸는 것**

1. **일 하나는 메뉴 하나** — 마스터플랜 「만드는 순서」는 아직 짓지 않은 조각을 메뉴 단위 줄로 나눈다. 한 줄은 왼쪽 메뉴의 화면 하나다(「라우팅」은
   「공정 등록」 · 「작업장 등록」 · 「불량 유형」 · 「품목별 라우팅」 넷 — 저자가 고른 예). 메뉴가 아닌 일(「포트폴리오 정리」 같은 것)은 한 줄로 둔다.
   옛 조각 이름은 줄마다 「묶음」으로 남겨, 다른 문서가 조각 이름으로 가리킨 것이 그대로 이어진다. 닫힌 조각(기반 ~ BOM)의 줄과 조각 폴더는 그대로
   둔다. 조각 문서 · 요구사항 · 설계는 더 쓰지 않는다.
2. **한 일의 흐름**
   1. Claude 가 「만드는 순서」에서 의존이 다 닫힌 다음 줄을 꺼낸다.
   2. 그 메뉴의 열린 업무 결정을 모은다 — ADR · 닫힌 조각 문서 · 마스터플랜에서 그 묶음 이름(옛 조각 이름, 「○○의 착공에서 정한다」 꼴)과
      메뉴 이름으로 찾는다. 열려 있으면 `Profile.md` 대로 저자에게 대화로 묻는다. 답을 받기 전에는 그 결정에 기대는 부분을 짓지 않는다. 열린 업무
      결정이 없으면 묻지 않고 짓는다.
   3. PR 한두 개로 짓는다. PR 본문은 「무엇을 · 왜」 · 「정한 것」(저자 판정 · Claude 의 기술 결정과 그 대안) · 「하지 않을 것」 · 리뷰 결과.
   4. 머지 전에 `/code-review` 를, 입력 · 접속 · 비밀값에 닿으면 `/security-review` 도 돌려 그 PR 안에서 고친다. 고치지 않는 지적은 본문에 까닭을 적는다.
   5. 머지 — 재고 · 생산 계산 PR 이 아니면 CI 가 다 지나고 리뷰 지적을 고친 뒤 Claude 가 머지한다. 재고 · 생산 계산 PR 이면 본문 맨 위에
      「저자 머지」를 적고, 시험 결과와 미리보기 화면을 대화로 보인 뒤 저자가 머지한다.
   6. 그 메뉴의 마지막 PR 이 마스터플랜의 그 줄을 「닫힘」으로 바꾼다. 머지 뒤 데모 화면을 대화로 저자에게 보인다.
3. **전용 도구를 덜어내고 공식 도구를 쓴다**

   | 지금 | 이 뒤 |
   |---|---|
   | 착공 스킬 `/slice-kickoff` | 지운다 — 조각이 없다. 메뉴를 시작할 때 대화로 묻는다(2-2) |
   | PR 점검 스킬 `/pr-check` | 지운다 — `/code-review` 가 `CLAUDE.md` 의 규칙도 본다 |
   | 재고 계산 검토자 `stock-rule-reviewer` | 지운다 — 시험 없이 머지 금지 · 저자 머지(2-5) · `/code-review` |
   | 기록 보호 훅 둘(`protect-records` · `check-records-on-stop` · `records-rules`) | 지운다 — `CLAUDE.md` 의 규칙 · git 이력 · `/code-review` |
   | 형식 맞추기 훅 `format-on-edit` | 지운다 — CI 「형식」이 PR 에서 잡는다 |
   | 문서 검사기 `tools/doc-check/` · CI 의 「문서 모양」 | 지운다 — 검사할 틀이 없다 |
   | 브라우저 도구(Playwright MCP, `.mcp.json`) | 남긴다 — 마이크로소프트의 공식 도구. 이 클라우드 환경의 브라우저와 판을 묶어 둔다 |
   | CI 의 형식 · 린트 · 타입 · 시험, 데모 상태 검사 · 미리보기 DB 정리 | 남긴다 — AI 도구가 아니라 기반이다 |

   계정에 붙이는 것 — 플러그인 Security Guidance(Anthropic — 고칠 때 위험한 꼴을 경고하고, 일을 마칠 때 바뀐 부분을 보안으로 본다) ·
   typescript-lsp(Anthropic — 코드를 정확히 읽는다). 쓰는 공식 도구의 목록을 `CLAUDE.md` 에 한 줄로 적는다 — 계정에 붙인 것은 레포에서 안
   보이기 때문이다.
4. **덜어낸다** — 새 전용 도구를 짓기 전에 공식 도구를 먼저 찾는다. 규칙 · 도구가 하는 일을 공식 도구나 모델이 대신하게 되면 지운다.
5. **기록** — 글자를 고치지 않는 기록은 ADR, 덮은 감사 기록 · 대장(`.claude/audits/` · `.claude/briefs/` · `docs/audit/`), 닫힌 조각의 문서다.
   감사 회차는 2026-11-17(회차 34)에서 멈추고 새 회차를 받지 않는다. 그 밖의 문서는 살아 있는 문서다.

## 결과

- 「왜 이렇게 했나」는 PR 본문 · ADR 에 남고, 문서와 코드의 어긋남을 따로 짚는 눈이 줄어든다. 업무가 틀리지 않게 막는 것은 앵커볼트 · 시험 ·
  저자 머지가 든다.
- 이 결정의 PR 은 작업 규칙을 바꾸는 PR 이라 저자가 머지한다. 2-5 의 Claude 머지는 이 PR 이 머지된 뒤부터다.
- 「BOM」은 PR A ~ C 가 머지되어 짓는 일이 끝났다 — 요구사항 끝에 `## 닫으며 (2026-11-17)` 몇 줄(무엇을 했나 · 넘긴 것)을 적고 마스터플랜의
  상태를 「닫힘」으로 바꾼다. 닫기 전 감사 회차(요구사항 「제약」)는 돌리지 않는다.
- 함께 고치는 문서 — `CLAUDE.md`(작업 방식 · 금지 · 쓰는 공식 도구), `Profile.md`(「정한 것」의 자리), `INTENT.md`(What 의 「그 과정」),
  마스터플랜(가리키는 문서의 「절차」 · 「만드는 순서」 · 범위 변경 한 줄), ADR 0024 · 0027 끝의 「대체」 항목, 대장 · 대장 이력 끝의 항목.
- 대장에 열려 있던 줄은 덮은 그대로 둔다. NC-2 · U-4(장애 기록 · 로그)는 이미 「포트폴리오 정리」로 넘겼다(마스터플랜 「범위 변경」 2026-11-02).
- 규칙이 서기 전의 조각 · PR 은 다시 가르지 않는다.

## Claude 가 정한 것

- 이 ADR 이 이 일의 설계 문서다 — 작업 규칙의 결정은 ADR 로 남기는 레포의 길을 따른다. superpowers 의 설계 · 계획 파일(`docs/superpowers/`)은
  레포에 싣지 않는다 — 한 일의 설계는 PR 본문에 둔다(2-3).
- 「재고 · 생산 계산 PR」은 수불 · 현재고 · 실사 · LOT · BOM 필요량 · MRP · 할당 · 생산실적의 자재 차감을 셈하는 코드, 그 입력 검사, 그 표의
  마이그레이션 중 하나라도 바꾸는 PR 이다. 애매하면 「저자 머지」로 다룬다.
- `/security-review` 의 규칙은 그대로 둔다 — Security Guidance 가 저절로 돌아도, 입력 · 접속 · 비밀값의 PR 은 한 번 더 본다.
- 마스터플랜에서 메뉴 줄의 차례 · 의존은 지금의 조각 차례와 「모듈과 메뉴」를 따라 Claude 가 매긴다(업무 결정이 아니다 — 무엇을 짓는지는 바뀌지 않는다).
