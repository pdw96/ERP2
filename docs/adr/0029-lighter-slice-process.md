# ADR 0029 — 조각을 가볍게: 조각 문서 한 장 · 대화로 보고 바로 구현 · 공식 리뷰 · 대장을 덮음

- 날짜: 2026-11-17
- 상태: 정함 — ADR 0027 의 1(착공 PR 에는 결정 문서만, 따로 먼저 머지)을 대체한다. ADR 0024 의 2(기록)는 범위를 좁히고, 4(감사 브리핑)는 쓸 일이 없어진다
- 조각: 「BOM」(진행 중 — 닫기를 이 결정으로) · 「라우팅」부터 모든 조각

## 맥락

조각 하나에 붙는 일이 무겁다(저자, 2026-11-17). 조각 넷(기반 · 기준정보 · 재고 수불 · 재고 현황)을 닫는 동안 감사가 33회차 돌았고, 부적합 대장에
부적합 · 확인불가 번호가 60개 넘게 쌓였다. 조각 하나에 —

- 요구사항 · 설계(칸 열하나)를 착공 PR 로 따로 먼저 머지하고(ADR 0027 의 1),
- 구현 PR 마다 본문에 변조본 표 · 잰 화면 폭 · 되돌릴 때 주의를 싣고,
- 감사자 넷이 회차를 돌며 지적마다 대장에 번호를 받아 재감사로 닫고,
- 머지된 문서는 글자를 못 고쳐 날짜 항목으로만 잇고(ADR 0024 의 2),
- 닫는 PR 의 「닫으며」에 실제 수를 대조한 표를 넣고 다시 감사했다.

감사자들은 claude-kit(레포 밖 플러그인)에서 왔고, claude-kit 은 은퇴했다. 저자는 그 플러그인 없이 가려 한다.

## 대안

- **가. 지금 그대로** — 감사자를 레포 안 파일로 다시 쓰고, 대장 · 착공 PR · 기록 규칙을 지킨다.
- **나. 가볍게** — 업무가 틀리지 않게 지키는 것(앵커볼트 · 계산의 시험 · 앵커볼트 ADR)만 남기고, 문서 한 장 · 대화로 보고 바로 구현 · 공식
  리뷰 도구로 바꾼다.
- **다. 더 가볍게** — 조각 문서도 없이 PR 설명만 쓴다.

## 결정

**나** 를 고른다(저자 판정 2026-11-17, 추천대로).

**남기는 것** — 업무가 틀리지 않게 지키는 것.

- 앵커볼트(재고 계산 규칙 · 업무 용어 · 코드 체계)는 바꾸기 전에 저자에게 묻는다(`CLAUDE.md`).
- 재고 · 생산 계산을 바꾸는 PR 은 시험 없이 머지하지 않는다(`CLAUDE.md` 「금지」).
- 앵커볼트에 닿는 결정과 작업 규칙을 바꾸는 결정은 ADR 로 남긴다.
- 범위 변경 한 줄(ADR 0024 의 1) · 샘플 이름 규칙(ADR 0024 의 3)은 그대로다.

**바꾸는 것**

1. **조각 문서 한 장** — 조각마다 `docs/slices/<순서>-<이름>/slice.md` 하나. 칸은 「무엇을 · 왜」 · 「화면 흐름」 · 「정한 것」 · 「하지 않을 것」 ·
   「PR 나눔」(틀 `tools/doc-check/templates/slice.md`). 업무에 영향이 없는 기술 결정의 대안도 「정한 것」에 적는다.
2. **대화로 보고 바로 구현** — Claude 가 조각 문서를 써서 저자에게 대화로 보이고, 저자가 좋다고 하면 구현을 시작한다. 조각 문서는 첫 구현 PR 에
   같이 싣는다. 착공 PR 을 따로 머지하지 않는다.
3. **공식 리뷰** — PR 마다 머지 전에 Claude Code 의 `/code-review` 를 돌리고, 입력 · 접속 · 비밀값에 닿으면 `/security-review` 도 돌린다. 재고 ·
   생산 계산을 바꾸면 레포의 재고 계산 검토자(`stock-rule-reviewer`)도 돌린다. 지적은 그 PR 안에서 고치거나, 고치지 않으면 PR 본문에 까닭을
   적는다. 회차 · 번호 · 재감사는 없다.
4. **대장을 덮는다** — 부적합 대장(`docs/audit/nc-ledger.md` · `nc-ledger-history.md`)과 감사 기록(`.claude/audits/`) · 브리핑(`.claude/briefs/`)은
   2026-11-17(회차 34)에서 멈춘다. 새 회차를 받지 않고 열린 줄을 더 따라가지 않는다 — 다시 볼 것은 그 조각 문서의 「넘긴 것」이나 마스터플랜으로
   옮긴다. 레포 안 감사자(`audit-internal`)는 지운다.
5. **기록** — 글자를 고치지 않는 기록은 ADR 과 덮은 감사 기록 · 대장이다. 이미 닫힌 조각의 요구사항 · 설계도 그대로 둔다. 진행 중이거나 새 조각의
   문서는 늘 지금에 맞게 고친다.
6. **닫기** — 조각 문서 끝에 `## 닫으며 (<YYYY-MM-DD>)` 몇 줄(무엇을 했나 · 넘긴 것)을 적고, 마스터플랜의 상태를 「닫힘」으로 바꾼다. 대조표 ·
   재감사는 없다.
7. **PR 본문** — 무엇이 바뀌고 어디서 보이나, 공식 리뷰의 결과. 화면은 캡처를 대화로 저자에게 보인다.

## 결과

- 「왜 이렇게 했나」의 흔적이 지금보다 적게 남고, 문서와 코드의 어긋남을 따로 짚는 눈이 줄어든다. 업무가 틀리지 않게 막는 것은 앵커볼트와 시험이 든다.
- `CLAUDE.md` 「작업 방식」 · 「금지」, `Profile.md` 「결정을 가르는 법」, 착공 스킬(`/slice-kickoff`) · PR 점검 스킬(`/pr-check`), 문서 검사기
  (`slice.md` 를 받음), 기록 보호 훅(조각 요구사항 · 설계를 풀어 줌 — ADR · 감사 기록 · 마이그레이션은 그대로 지킨다)을 이 결정대로 고친다.
- 진행 중인 「BOM」은 요구사항 · 설계 두 문서를 그대로 쓴다. 닫기 전 감사(요구사항 「제약」의 `audit-data` · `audit-secrets` · `audit-internal`)는 3 의
  공식 리뷰로 바꾸고, 닫을 때는 6 대로 요구사항 끝에 「닫으며」를 적는다. 그 요구사항 끝에 날짜 항목으로 남긴다.
- 대장에 열려 있던 줄은 덮은 그대로 둔다. NC-2 · U-4(장애 기록 · 로그)는 이미 「포트폴리오 정리」로 넘겼다(마스터플랜 「범위 변경」 2026-11-02).
- 규칙이 서기 전의 조각 · PR 은 다시 가르지 않는다.
