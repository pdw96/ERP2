# ADR 0030 — AI-Native 다듬기: 일마다 새 세션 · Codex 리뷰 · 리뷰를 멈추는 기준 · 머지 뒤 오류 확인 · 권한 막기

- 날짜: 2026-11-18
- 상태: 정함 — ADR 0029 에 더한다(바꾸지 않는다)
- 조각: 메뉴 「공정 등록」부터 모든 일

## 맥락

ADR 0029 를 머지한 뒤, 같은 날 같은 목표로 AI-Native 작업 방식을 세운 저자의 다른 프로젝트 둘(job-hunter · Trip-Planner)과 견줬다(2026-11-18).
셋 다 「사람은 꼭 필요할 때만 · 공식 도구 · 덜어낸다」는 같다. ERP2 에 없던 것이 여섯 있었다.

1. `docs/status.md` 한 장(끝난 것 · 다음 할 일 · 알아 둘 것 · 남은 확인)과, 일 하나가 끝나면 새 세션을 권하는 것 — 긴 대화는 매번 다시 읽혀 비용이
   들고 집중이 흐려진다. ADR 0029 를 정한 대화가 이틀에 걸쳐 길어졌다.
2. 머지 조건에 Codex 리뷰 — 이 레포에도 Codex 가 붙어 있어, PR 을 「Ready for review」로 바꾸면 저절로 돈다(PR #52 에서 돌았다).
3. 리뷰를 멈추는 기준 — 횟수가 아니라 막는 지적이 남았는지로.
4. 머지 뒤 운영 오류 확인 — Claude 가 머지하는 만큼 안전망.
5. Claude Code 의 권한 막기(공식 기능) — ADR 0029 가 지운 기록 보호 훅의 몫 가운데 올라간 마이그레이션을 공식 기능으로 지킨다.
6. 「저자 머지」를 GitHub Actions 스크립트로 강제(위험 경로를 바꾼 PR 은 사람이 라벨을 붙여야 통과).

## 대안

- 가. 1 ~ 6 모두 넣는다.
- **나. 1 ~ 5 를 넣고 6 은 뺀다** — 1 ~ 5 는 문서 몇 줄이거나 공식 기능이다. 6 은 효과가 크지만 전용 스크립트가 커진다(Trip-Planner 에서 승인 해시 ·
  라벨 떼기 · 시험 파일). GitHub 의 필수 리뷰는 PR 을 여는 계정이 저자 계정이라 본인이 승인할 수 없어 쓰지 못한다.
- 다. 1 · 2 만 넣는다.

## 결정

저자 판정(2026-11-18) — **나**, 추천대로.

1. **일 하나는 세션 하나** — 새 세션은 `CLAUDE.md` 와 `docs/status.md` 를 읽고 「다음 할 일」부터 한다. 한 메뉴의 일(구현 · 리뷰 · 머지 · 머지 뒤 확인 ·
   그 배포에서 나온 버그 고침)은 한 세션으로 잇는다. 메뉴가 닫히면 `docs/status.md` 를 고치고 저자에게 새 세션을 권한다. 이미 정한 것을 다시
   묻거나 같은 실수가 되풀이될 때도 권한다. 새 세션은 저자가 연다.
2. **Codex 리뷰** — Claude 는 PR 을 초안으로 열고, `/code-review` 를 고친 뒤 「Ready for review」로 바꿔 Codex 리뷰를 받는다. 머지 조건에 「head 커밋의
   Codex 리뷰가 끝났고 남은 지적이 없다」를 더한다 — `chatgpt-codex-connector[bot]` 의 요약 댓글 속 `codex-review-state` 에서 `code_review` 의
   `commit_sha` 가 head 커밋이고 `status` 가 `completed`, `has_unresolved_findings` 가 `false`. 고친 뒤 다시 받으려면 `@codex review` 를 남긴다.
3. **리뷰를 멈추는 기준** — 막는 지적은 효과로 가린다: 그대로 머지하면 업무가 틀리거나(재고 · 생산의 셈, 장부에 남는 것), 데이터가 망가지거나,
   보안이 뚫리는 지적이다. 불편 · 문구 · 모양은 막지 않는다. 직전 리뷰(`/code-review` · Codex)에 막는 지적이 0건이면 멈춘다. 있으면 고치고 다시
   받는다. 같은 메뉴에서 막는 지적이 세 번 연속 나오면 혼자 이어 가지 않고 저자에게 넘긴다. 막지 않는 지적은 맞으면 고치되 다시 받지 않고,
   고치지 않은 것은 PR 본문에 적는다.
4. **머지 뒤 오류 확인** — 머지 뒤 Vercel 에서 운영 배포가 끝났는지와, 배포 시각 뒤에 처음 생긴 운영 오류(`get_runtime_errors`)를 본다. 데모의
   `/health` 가 「연결됨」인지도 본다. Claude 가 머지한 PR 탓이면 되돌리는 PR 을 한 번만 열어 CI 만 보고 머지하고 저자에게 알린다. 되돌린 뒤에도
   오류가 나거나, 원인이 분명하지 않거나, 저자가 머지한 PR 이면 저자에게 묻는다. Vercel 에서 앞 배포로 되돌리지 않는다(main 과 운영이 어긋난다).
   오류는 이름 · 횟수 · 경로만 적는다.
5. **권한 막기** — `.claude/settings.json` 의 `permissions.deny` 로 올라간 마이그레이션(`drizzle/`)을 손으로 고치지 못하게 하고, 비밀값 파일(`.env*`,
   `.env.example` 은 빼고)을 읽거나 고치지 못하게 한다. 새 마이그레이션은 `npm run db:generate` 가 만든다.

## 결과

- 저자가 나오는 자리는 그대로다(업무 결정 · 재고 · 생산 계산 PR 과 작업 규칙 PR 의 머지). 새로 더해지는 것은 메뉴마다 새 세션을 여는 일이다.
- 리뷰가 하나 늘고(Codex), 멈출 때가 정해지고, Claude 가 머지한 뒤의 운영 오류를 Claude 가 본다.
- 「저자 머지」를 지키는 것은 여전히 Claude 의 판단과 「애매하면 저자 머지」다. 저자 머지여야 할 PR 을 Claude 가 머지한 일이 한 번이라도 생기면
  6(기계로 강제)을 다시 본다.
- `CLAUDE.md` 「작업 방식」 · 「도구」와 `docs/status.md` 를 이 결정대로 쓴다.
