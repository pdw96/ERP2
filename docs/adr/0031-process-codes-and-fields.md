# ADR 0031 — 공정의 코드 체계와 칸

- 날짜: 2026-11-18
- 상태: 정함
- 조각: 메뉴 「공정 등록」(묶음 「라우팅」, pdw96/ERP2#55)

## 맥락

메뉴 「공정 등록」을 시작하며 묶음 「라우팅」의 열린 업무 결정을 모았다. 공정코드는 작업장 · 품목별 라우팅 · 작업지시 · 생산실적이 모두 가리키므로
앵커볼트 「업무 용어 · 코드 체계」다. 공정에 담을 칸과, ADR 0026 이 「라우팅」의 착공으로 넘긴 「BOM 자품목 줄의 투입 공정」도 함께 열려 있었다.
생산은 저자가 잘 아는 영역이라 선택지를 먼저 보이고 추천을 붙여 물었다(2026-11-18).

## 대안

- **공정코드의 꼴** — (가) 사람이 짧은 영문 약어를 직접 넣는다(`DA` · `WB` · `MD`), (나) 저절로 붙는 일련번호(`OP-01`, 창고 `WH-01` 과 같은 꼴).
- **공정의 칸** — (가) 코드 · 공정명 · 비고 · 사용 여부만, 검사 공정 · 실적 보고 · 외주 표시는 그 칸을 읽는 메뉴에서 정한다, (나) 지금 표시 칸까지 넣는다.
- **BOM 자품목 줄의 투입 공정** — (가) 메뉴 「품목별 라우팅」에서 정한다, (나) 지금 BOM 자품목 줄에 칸을 더한다, (다) 두지 않는다(생산실적이 자재를 한 번에
  출고).

## 결정

저자가 모두 (가)를 골랐다. Claude 의 추천과 같다.

1. **공정코드는 사람이 넣는 영문 약어다** — 영문 대문자로 시작하고 영문 대문자 · 숫자 2 ~ 6자(`^[A-Z][A-Z0-9]{1,5}$`). 소문자를 대문자로 바꾸지 않고 꼴을
   알린다. 등록한 뒤 바꾸지 않고, 지우지 않고 「사용 안 함」으로 둔다(ADR 0003 과 같다). 품목에 일련번호를 고른 ADR 0003 과 다른 까닭 — 공정은 열 개
   남짓으로 거의 늘지 않아 일련번호의 이점이 작고, 라우팅 · 작업지시처럼 공정이 줄줄이 늘어서는 화면에서 약어가 바로 읽힌다.
2. **공정의 칸은 코드 · 공정명(50자) · 비고(500자) · 사용 여부 넷이다.** 검사 공정 · 실적 보고 · 외주 표시는 그 칸을 읽는 메뉴(공정 검사 · 생산실적,
   외주는 후보)에서 정해 더한다 — 품목의 칸을 정한 방식(ADR 0012)과 같다. 표준시간은 품목마다 달라 「품목별 라우팅」에 둔다.
3. **투입 공정은 메뉴 「품목별 라우팅」에서 정한다** — 그때 품목마다 공정 순서가 있어, BOM 줄에 적을지 라우팅의 공정 줄에 자재를 붙일지를 화면을 보며
   고른다.
