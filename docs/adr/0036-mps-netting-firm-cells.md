# ADR 0036 — MPS 는 재고를 빼고 안을 내며, 담당자가 칸을 고정한다 · 고정한 칸만 저장 · 판매계획 확정 취소 막기

- 날짜: 2026-11-20
- 상태: 정함
- 조각: 메뉴 「MPS」(마스터플랜 순서 11, 묶음 「MPS」)

## 맥락

메뉴 「MPS」를 시작하며 묶음 「MPS」와 메뉴 이름으로 열린 업무 결정을 모았다. ADR 0007 은 MPS 를 완제품의 주별 생산계획으로 두고 「완제품의 총소요는 MPS」라고
적었지만, MPS 가 재고를 빼는지 · 시스템이 안을 내는지 · 담당자가 어떻게 굳히는지는 정하지 않았다. ADR 0035 는 「MPS 가 확정한 품목 × 주의 판매계획은 확정 취소를
막는다」 · 「확정 구간(frozen period)을 둘지는 MPS 착공에서 정한다」를 넘겼다. 이 ADR 은 ADR 0007 을 고치지 않고 그 「완제품의 총소요는 MPS」를 아래 결정 1 처럼 읽기로
잇는다. ADR 0035 의 넘김은 이 ADR 이 받는다. 재고 · 생산 계산이라 선택지를 먼저 보이고 추천을 붙여 물었다(2026-11-20).

## 대안

- **MPS 가 하는 일**(저자 판정 (가)) — (가) 확정한 수요에서 재고를 빼고 로트 크기를 지켜 생산량 안을 낸다, (나) 수요를 그대로 생산량으로 옮긴다(재고는 MRP 가 뺌).
- **MRP 가 읽는 값**(저자 판정 ②) — ① 고정한 칸만, ② 고정한 칸 + 미확정 안 모두.
- **확정 방식**(저자 판정 (A)) — (A) 수량을 치면 곧 고정(상태 「안」 · 「고정」 둘, 메뉴 하나), (B) 넣는 화면과 확정하는 화면을 가른다(판매계획처럼).
- **확정 구간**(저자 판정 (1)) — (1) 두지 않는다(지난 주만 잠김), (2) 가까운 몇 주를 묶어 고치지 못하게 한다.
- **음수 예상재고**(저자 판정 A-(a)) — (a) 다음 주로 넘긴다(밀린 생산을 다음 미확정 주의 안이 메움), (b) 0 으로 자르고 넘기지 않는다.
- **[확정]이 안이 0 인 주를 대하는 법**(저자 판정 B-(a)) — (a) 건너뛴다, (b) 0 으로 고정한다.
- **「사용 안 함」 완제품**(저자 판정 (다), 2026-11-23) — (가) 그대로 계산한다(안전재고까지 채움 — 단종 품목에 재고가 쌓임), (나) 안을 내지 않는다(남은 확정 수요를 아무도 채우지 않음),
  (다) 안전재고를 0 으로 보고 남은 확정 수요만 채운다.
- **안을 두는 자리**(Claude 의 기술 결정) — (채택) 고정한 칸만 저장하고 안은 화면 · MRP 가 같은 순수 함수로 계산한다, (버림) 안을 모두 저장하고 [다시 계산] 버튼을 둔다 —
  결정 2 의 「미확정은 읽을 때마다 지금 값」과 어긋난다.
- **MPS 쓰기의 잠금**(Claude 의 기술 결정) — (채택) 판매계획의 잠금을 같이 쓴다, (버림) MPS 만의 잠금을 따로 둔다 — 판매계획 확정 취소의 「MPS 고정 칸 대어 보기」와 MPS 고정이 서로 어긋나 지나칠 수 있다.

## 결정

저자가 (가) · ② · (A) · (1) · A-(a) · B-(a)를 골랐다(2026-11-20). 「사용 안 함」 완제품은 (다)를 골랐다(2026-11-23).

1. **MPS 는 재고를 빼고 생산량 안을 낸다**(저자 판정 (가)). 시스템이 안을 내고 담당자가 고쳐 굳힌다. MRP 는 MPS 수량을 완제품의 생산량(공급량)으로 받아 자재로만 펼치고,
   완제품을 다시 넷팅하지 않는다 — ADR 0007 의 「완제품의 총소요는 MPS」를 이렇게 읽는다.
2. **MRP 는 고정한 칸 + 미확정 안을 모두 읽는다**(저자 판정 ②). 고정한 칸은 다시 계산하지 않고, 미확정은 읽을 때마다 지금의 수요 · 재고로 다시 계산한다.
3. **수량을 치면 곧 고정이다**(저자 판정 (A)). 상태는 「안」 · 「고정」 둘이다. 고정한 칸도 바로 다시 고칠 수 있고(이력), [확정]은 화면에 보이던 안을 그대로 고정하며,
   [확정 취소]는 고정을 풀어 안으로 되돌린다. 메뉴는 「MPS」 하나다(넣는 사람과 확정하는 사람이 갈리지 않는다).
4. **확정 구간은 두지 않는다**(저자 판정 (1)). 가까운 주를 묶는 일은 뒤 메뉴 「작업지시」의 몫이다. 지난 주 칸만 잠긴다.
5. **음수 예상재고는 다음 주로 넘긴다**(저자 판정 A-(a)). 담당자가 안보다 줄여 고정해 예상재고가 음수가 되면 다음 미확정 주의 안이 그 부족 + 안전재고까지 채운다.
   MRP 는 음수여도 MPS 수량만 펼친다 — 부족은 화면에 빨강으로 보이고 담당자 판단으로 남는다.
6. **[확정]은 안이 0 보다 큰 주만 고정한다**(저자 판정 B-(a)). 안이 0 인 주는 건너뛴다. 담당자가 「이 주는 만들지 않음」을 굳히려면 0 을 쳐서 고정한다(0 도 고정이다).

설계 승인으로 저자가 받은 Claude 의 안(2026-11-20):

7. **처음 재고는 지금 가용재고다**(실재고 − 검사대기 − 불량) — 「품목별 재고」의 가용재고(`src/db/stock-status.ts`)와 같은 값이다.
8. **주마다 예상재고 = 지난주 예상재고 + MPS − 수요**다. 수요는 `salesPlanDemand`(확정한 판매계획의 품목 × 주 합)다. 고정 칸은 그 수량이다. 미확정 칸은 (지난주 예상재고 − 수요)가
   안전재고보다 작으면 모자란 만큼(안전재고 − (지난주 예상재고 − 수요))을 최소 생산량까지 올리고, 배수가 있으면 배수로 올리고, 품목 단위의 소수 자릿수에서 올림한다. 아니면 0 이다.
   이번 주 수요는 한 주 몫 전부이고, 달력상 지난 주(이번 주 이전)의 미충족 수요는 넘기지 않는다. 리드타임은 쓰지 않는다 — MPS 수량은 완성할 주다(시작 주는 MRP 가 정한다).
9. **기간은 판매계획과 같다** — 이번 주(한국 시각, 월 ~ 일)부터 13주를 보이고 ◀ ▶ 로 13주씩 넘긴다. 입력은 이번 주 ~ 51주 뒤, 보기는 52주 전까지다.
   계산은 늘 이번 주부터 시작한다(보이는 창이 미래면 이번 주부터 그 창까지 계산해 이어 쓴다).
10. **지난 주는 수요와 고정 수량만 읽기 전용으로 보인다** — 예상재고 · 안은 비운다.
11. **품목은 완제품(FG) 가운데 확정 수요 · 고정 칸 · 0 이 아닌 안 중 하나라도 있는 것**이다(계산 범위 이번 주 ~ 51주 뒤, 또는 보이는 창).
12. **화면** — 품목마다 세 줄(수요 · MPS · 예상재고), 품목 머리에 가용 · 안전 · 최소 · 배수를 둔다. 미확정 안은 흐린 글씨, 고정은 「고정」 표시, 예상재고 음수는 빨강, 안전재고 밑은 주황이다.
    MPS 칸에 숫자를 치고 [저장]하면 고정이고, 칸을 비우면 확정 취소와 같다. 품목 앞 체크박스 + 표 아래 [확정] [확정 취소]는 고른 품목의 보이는 13주 가운데 고칠 수 있는 주(이번 주부터)에 건다.
13. **고친 이력은 「일시 · 품목 · 주 · 종류(고침 · 확정 · 확정 취소) · 전 → 후」다** — 최근 100줄을 보인다. 「누가」는 조각 「인사」 뒤에 더한다.
14. **수량은 0 이상 99,999,999 이하이고 품목 단위의 소수 자릿수를 따른다**(ADR 0017).
15. **판매계획과 잇는다** — MPS 가 고정한 품목 × 주의 판매계획 칸은 확정 취소를 거절한다(「MPS 가 고정한 주입니다 — MPS 에서 확정 취소한 뒤 하세요」). 고정 칸이 수량 0 이거나 그 주에 수요가
    없어도 막고, 막히는 칸이 하나라도 있으면 그번 확정 취소 전체를 거절한다. MPS 에 고정 칸이 있는 품목은 단위 변경 · 자릿수 줄이기를 막는다(판매계획과 같은 자리 — `src/db/items.ts` · `src/db/codes.ts`).
16. **샘플** — 매일 밤 되돌림이 FG-0001 의 이번 주 · 다음 주를 그날의 안대로 고정한다. 새 이름은 없다.
17. **재고 · 생산 계산이라 이 PR 은 저자가 머지한다.**
18. **「사용 안 함」 완제품은 남은 확정 수요만 채운다**(저자 판정 (다), 2026-11-23). 안전재고를 0 으로 보고 계산한다 — 최소량 · 배수 · 자릿수 · 고정 칸은 그대로이고, 담당자가 직접 고정할 수도 있다.
    화면 머리는 「안전 0(사용 안 함)」으로 보인다. 다시 「사용」으로 바꾸면 평소대로 안전재고까지 채운다.

Claude 의 판단(검토 뒤 저자에게 알림):

- **조달구분 「구매」인 완제품도 MPS 에 든다** — MRP 가 조달구분으로 생산 · 구매 계획오더를 가른다(ADR 0007). MPS 수량은 공급량이다.
- **[확정]은 화면이 보던 안을 고정한다** — 화면을 연 뒤 재고 · 수요가 바뀌어 안이 달라져도 막지 않는다. 같은 칸의 상태(고정 · 미확정)가 화면이 본 것과 다를 때만 `STALE` 이다.
  저장(숫자 치기)은 칸마다 화면이 본 고정 상태 · 수량이 지금과 다르면 `STALE` 이다(판매계획과 같은 문구).
- **음수는 다른 재고 화면처럼 참 마이너스 부호로 보인다.**
- **예상재고는 보이는 창이 미래여도 이번 주부터 계산해 잇는다** — 먼 주의 안이 앞 주의 안 · 고정을 무시하지 않게 한다.

Claude 의 기술 결정(업무에 영향 없음):

- **표 둘** — `mps_fixed`(품목 · 주 시작일(월요일 date) · 수량 numeric(15,3) · 고정한 일시, 유일 (품목, 주), 월요일 · 수량 범위 check) ·
  `mps_changes`(일시 · 품목 · 주 · 전 · 후 · 종류 `kind` EDIT · CONFIRM · UNCONFIRM). 고정한 칸만 저장한다 — 안은 저장하지 않는다.
- **마이그레이션** `0026`(표) · `0027`(데이터가 있는 DB 의 샘플 값 — 주는 Asia/Seoul 의 오늘로 센다. FG-0001 이번 주 7,000 · 다음 주 9,000. 그 품목에 고정 칸이 이미 있으면 건너뜀).
  값은 `src/db/sample.ts` 의 `SAMPLE_MPS_FIXED` 와 같다(시험이 견준다).
- **잠금** — 저장 · 확정 · 확정 취소는 `lockSalesPlans`(`REGISTER_LOCK.salesPlans`)를 쥐고 돈다. 품목 단위 검사와 겹치는 잠금 순서(재고 → BOM → 판매계획)는 그대로다.
- **동시에 고침** — 칸마다 화면이 본 고정 수량을 함께 보내 서버가 지금과 견준다. 다르면 그 저장 전체를 막는다(`STALE`, ADR 0035 와 같다).
- **상한** — 고정 칸 전체 20,000, 고친 이력 50,000(매일 밤 되돌림이 비운다), 한 번 저장 · 확정 · 확정 취소에 바뀐 칸 2,000, 화면에 보이는 이력 100줄.
  바뀐 것이 없는 저장은 아무것도 쓰지 않는다.
- **MRP 가 읽는 함수는 `mpsSupply(db, toWeek, today)` 다** — 품목 코드 · 주 · 수량 · 고정 여부(`{ item, week, qty, fixed }`)를 이번 주부터 `toWeek` 까지, 수량이 0 이 아닌 칸만 낸다.
  화면과 같은 계산 함수(`computeMps`)를 쓴다.

## 결과

- 화면 「생산 › 생산계획 › MPS」(`src/app/production/mps/`), 표 `mps_fixed` · `mps_changes`(0026), 샘플 FG-0001 이번 주 · 다음 주 고정(0027, 매일 밤 되돌림이 그날의 안대로 다시 고정).
- 「MRP」는 `mpsSupply(db, toWeek, today)` 로 고정한 칸 + 미확정 안을 읽고, 완제품을 다시 넷팅하지 않는다. 조달구분으로 생산 · 구매 계획오더를 가르고, 리드타임으로 시작 주를 정한다.
  ADR 0007 의 계산 뼈대는 MRP 착공에서 저자에게 다시 확인한다.
- 판매계획의 확정 취소는 MPS 가 고정한 주의 칸에서 막힌다(ADR 0035 의 넘김을 받음). 품목의 단위 변경 · 자릿수 줄이기도 MPS 고정 칸이 있으면 막힌다.
- 「수주」는 생기면 MPS 의 수요를 주마다 max(수주, 판매계획)로 더한다(ADR 0007). 능력 검토 · 차수(버전) · 반제품 MPS · 지난 주 미충족 수요 넘기기는 두지 않는다.
- 이 규칙을 바꾸려면 저자에게 먼저 묻는다(`CLAUDE.md` 앵커볼트).
