# ADR 0039 — 문서 덜어내기: 덮은 기록은 main 밖으로, 구조 · DB 문서는 지도와 규칙만

- 날짜: 2026-11-25
- 상태: 정함 — ADR 0024 · 0029 의 「기록은 글자를 고치지 않는다」는 그대로다. 덮은 기록을 두는 곳과, 살아 있는 문서가 드는 범위를 바꾼다
- 조각: 모든 일

## 맥락

2026-11-25 비판 검토(이슈 #66)에서 다음이 나왔다.

- 덮은 감사 기록 · 브리핑 · 대장(`.claude/audits/` · `.claude/briefs/` · `docs/audit/`, 58개 · 약 2.6MB)이 코드(약 2.7MB)만큼 크다. 2026-11-17 에
  덮어 새 회차를 받지 않는데도, 레포를 찾을 때마다 함께 걸려 컨텍스트를 먹는다.
- `docs/architecture.md` · `docs/schema.md`(약 59KB)는 화면 · 표 · 제약을 말로 옮겨 적었다. 메뉴마다 같이 고쳐야 했고, architecture.md 는 아홉 메뉴를
  놓쳤다(이슈 #66 ⑥). 코드를 되풀이하는 문서는 반드시 낡는다.
- `docs/status.md` 의 「넘긴 결정」이 한 문단으로 길어져, 착공할 때 자기 메뉴 몫을 찾으려면 다 읽어야 했다.

## 정한 것(저자 판정 2026-11-25)

1. 덮은 기록은 main 에서 뺀다. 지우기 전 main 의 커밋 `61a9885` 에 그대로 있다 — `https://github.com/pdw96/ERP2/tree/61a9885/<옛 경로>` 로 연다.
   보관 태그를 쓰려 했으나 이 세션은 작업 가지 밖으로 올릴 수 없어 커밋으로 가리킨다.
2. 살아 있는 문서는 코드에 없는 것만 든다 — 왜(ADR), 업무 규칙, 다음 할 일, 어디를 보면 되는지. `architecture.md` 는 폴더 지도와 흐름만,
   `schema.md` 는 「DB 규칙」(잠금 · 샘플과 되돌림 · 이름 · 접속 · 마이그레이션)만 든다. 메뉴 하나를 더하는 것으로는 둘을 고치지 않는다.
3. `status.md` 의 「넘긴 결정」은 받는 메뉴마다 한 줄인 표로 둔다. 결정을 닫은 PR 이 그 줄을 지운다.

## 대안

- 그대로 둔다 — 문서와 덮은 기록이 메뉴마다 커지고, 낡은 구조 문서가 새 세션을 틀린 길로 이끈다.
- 덮은 기록을 레포 안 다른 폴더로 옮긴다 — 찾을 때 여전히 걸린다.

## 결과

- 늘 실리는 문서(CLAUDE.md · Profile.md)는 그대로, 착공 때 읽는 문서와 찾을 때 걸리는 양이 줄어든다.
- ADR 0024 · CLAUDE.md 가 가리키던 옛 경로는 위 커밋으로 연다. ADR 0024 의 글자는 고치지 않는다.
- 업무 규칙을 한 곳에 모으는 「업무 규칙표」와 ADR 을 짧게 쓰는 규칙은 다음 PR 이 정한다.
