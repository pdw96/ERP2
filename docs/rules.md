# 업무 규칙표

**살아 있는 문서**다. 지금 지키는 업무 규칙을 모듈마다 한 줄씩 든다 — 장부 · 재고 · 계획에 무엇이 어떻게 남는지와 업무 용어 · 코드의 꼴. 착공할 때는
자기 모듈의 절만 읽고, 까닭이 궁금하거나 여기에 없으면 그 줄의 ADR 을 연다(ADR 0040). 화면의 모양 · 칸 · 상한 · 메시지는 코드가 든다.

- ★ 는 앵커볼트(재고 계산 규칙 · 업무 용어 · 코드 체계)다. 바꾸려면 저자에게 먼저 묻는다(`CLAUDE.md`).
- 업무 규칙을 정하거나 바꾼 PR 이 그 줄을 같이 고친다. ADR 이 규칙을 바꾸면 옛 줄을 지우고 새 줄에 새 ADR 을 적는다.
- 「아직 정하지 않은 것」은 맨 아래에 있다. 받는 메뉴가 정할 것은 `docs/status.md` 「넘긴 결정」이 든다.

## 코드 체계 · 용어

| 규칙 | ADR |
|---|---|
| ★ 화면의 이름은 「품목」 · 「창고」 · 「거래처」다 | 0003 |
| ★ 품목코드는 유형 머리 + 네 자리 일련(유형마다 따로 셈): `RM-0001` · `SF-0001` · `FG-0001` · `SM-0001` · `CS-0001` | 0003 · 0019 |
| ★ 창고코드 `WH-01`(두 자리) · 거래처코드 `BP-0001`(네 자리). 일련이 자리를 넘으면 자릿수가 는다 | 0003 |
| ★ 코드와 품목 유형은 등록한 뒤 바꾸지 않는다(유형이 코드의 머리) | 0003 |
| ★ 공통코드 묶음(Major)은 영문 대문자로 시작, 대문자 · 숫자 · `_` 2~20자. 값(Minor)은 대문자나 숫자로 시작 1~20자, 묶음 안에서 겹치지 않고 바꾸지 않는다 | 0009 |
| ★ 국가코드는 ISO 3166-1 두 글자. 사업자등록번호(`KR`)는 `000-00-00000` 이거나 비움, 해외 사업자번호는 글자 그대로 | 0011 |
| ★ 수불 전표 `IV-YYYYMMDD-NNN`(수불 일자 + 그날 일련) · 재고 실사 `PI-YYYYMMDD-NNN`(실사를 연 날) · MRP 계획오더 `PL-YYYYMMDD-NNN`(실행한 날). 999 를 넘으면 자리가 는다 | 0016 · 0037 |
| ★ LOT 번호는 영문 · 숫자 · `-` · `_` · `.` 1~30자. 한 품목 안에서 같은 번호는 같은 LOT 다 | 0016 |
| ★ LOT 번호 규칙 = 머리(대문자 · 숫자 0~6자) → 날짜 꼴(없음 · `YYMMDD` · `YYYYMMDD` · `YYMM`) → 일련(2~6자리), 구분자는 없음 · `-` · `_` · `.`. 일련은 날짜 꼴 단위로 다시 센다 | 0016 |
| ★ 공정코드는 영문 대문자로 시작, 대문자 · 숫자 2~6자. 작업장 · 불량유형코드는 영문 대문자로 시작, 대문자 · 숫자 · `-` 2~10자(`-` 는 끝 · 연속 불가). 모두 사람이 넣고 바꾸지 않는다 | 0031 · 0032 · 0033 |
| ★ 주는 월요일~일요일(ISO 주)이고 한국 시각의 오늘로 이번 주를 정한다 | 0035 |

## 기준정보 — 품목 · 거래처 · 창고 · 공통코드

| 규칙 | ADR |
|---|---|
| ★ 품목 유형은 원자재 `RM` · 반제품 `SF` · 완제품 `FG` · 부자재 `SM` · 소모품 `CS` 다섯. 상품은 두지 않는다. 사 오는 것은 원자재 · 부자재 · 소모품, 만드는 것은 반제품 · 완제품 | 0019 |
| ★ 조달구분은 구매 `BUY` · 생산 `MAKE` 둘(외주 없음). 사 올지 만들지는 유형이 아니라 조달구분이 가른다 | 0003 · 0009 |
| 유형을 고르면 기본값이 붙고 품목마다 바꾼다: 원자재(구매 · LOT · 수입검사 켬), 반제품(생산 · LOT), 완제품(생산 · LOT · 출하검사), 부자재 · 소모품(구매, 나머지 끔) | 0019 |
| 수입검사 · 출하검사 대상은 품목마다 켬 · 끔, 표시된 품목만 검사한다 | 0003 |
| 품목의 계획 정보: 리드타임(일) · 안전재고 · 최소 발주 · 생산량 · 배수(품목 단위, 소수 셋째 자리까지) | 0003 · 0007 · 0017 |
| 거래처는 매입처 · 매출처 가운데 하나 이상을 표시한다. 국가가 있고 새 거래처의 기본은 `KR`. 같은 사업자번호는 경고만 한다 | 0003 · 0011 |
| 창고 안 위치(랙 · 선반)는 두지 않는다. 불합격품은 「불량창고」 표시가 있는 창고에 격리한다 | 0003 |
| ★ 기준정보는 지우지 않고 「사용 안 함」으로 돌린다 — 새 입력에서 빠지고 지난 기록은 그대로 가리킨다 | 0003 |
| ★ 공통코드의 시스템 코드(계산 · 코드 꼴이 기대는 값)는 화면에서 보기만 한다. 사용자 코드는 값 추가 · 이름 · 정렬 · 「사용 안 함」만 된다 | 0009 |
| ★ 시스템 묶음 `ITEM_TYPE` · `PROC_TYPE` · `MOVE_TYPE`(`IN` 기타입고 · `OUT` 기타출고 · `XFER` 이동 · `ADJ` 조정). 사용자 묶음 `UNIT` · `COUNTRY`(`KR` 은 「사용 안 함」 불가) · `ADJ_REASON`(`COUNT` 실사 차이 · `DAMAGE` · `LOSS` · `FOUND` · `ETC`, `COUNT` 는 「사용 안 함」 불가) · `DEFECT_CLS` | 0009 · 0011 · 0016 · 0033 |
| 한 모듈만 쓰는 기준정보(불량 유형 · 계정과목)는 공통코드가 아니라 그 모듈의 「○○ 기준정보」에 둔다 | 0009 |
| ★ LOT 번호 규칙은 만드는 품목에만 쓴다. 유형마다 기본 규칙이 있고 품목이 다른 규칙을 고를 수 있다. 규칙을 고치면 그 뒤 번호부터 바뀐다 | 0016 |

## 단위 · 수량

| 규칙 | ADR |
|---|---|
| ★ 단위는 품목마다 하나, 재고는 늘 품목 단위로 쌓는다 | 0003 · 0017 |
| ★ 단위마다 기준 단위 · 배수 · 소수 자릿수가 있다: EA(EA ×1, 0) · M(M ×1, 3) · KG(G ×1000, 3) · G(G ×1, 0). 기준 단위 · 배수는 등록 뒤 바꾸지 않는다 | 0017 |
| ★ 수불은 기준이 같은 다른 단위로 넣을 수 있다(KG 품목에 500 G → 0.5 KG). 기준이 다른 단위 · 품목별 환산(1 BOX = 100 EA)은 없다 | 0017 |
| ★ 수량이 단위의 자릿수를 넘으면 반올림하지 않고 저장하지 않는다 | 0017 |
| ★ 수불 · 작성 중 실사 · BOM · 판매계획 · MPS 고정 칸에 든 품목은 단위를 바꾸지 못하고, 단위의 자릿수는 그 수량들이 맞을 때만 줄인다 | 0015 · 0017 · 0021 · 0026 · 0035 · 0036 |

## 재고 계산

| 규칙 | ADR |
|---|---|
| ★ 재고는 품목 × 창고 × LOT × 상태로 센다(LOT 관리를 끈 품목은 LOT 없이) | 0015 |
| ★ 수불은 저장하면 바로 실재고에 반영된다(승인 단계 없음). 등록 한 번이 전표 하나이고, 한 줄이라도 틀리면 아무 줄도 저장되지 않는다 | 0015 |
| ★ 음수 재고를 막는다. 지난 날짜 수불도 그날부터 지금까지 어느 때든 0 밑으로 가면 막는다. 같은 날은 등록한 차례로 센다 | 0015 · 0018 |
| ★ 수불 일자는 지난 날과 오늘만 받는다. 달 마감은 없다(「회계」가 정한다) | 0015 |
| ★ 수불 줄은 고치거나 지우지 않는다. 잔액은 늘 수불 줄의 합이다 | 0018 |
| ★ 상태: 불량창고의 재고는 다 불량, 그 밖은 상태 칸이 검사대기면 검사대기, 아니면 가용. 실재고 = 검사대기 + 불량 + 가용 | 0015 · 0023 |
| ★ 가용재고 = 실재고 − 검사대기 − 불량 − 할당. 할당은 「작업지시」 · 「영업」이 짓기 전까지 0 이다 | 0008 · 0015 · 0023 |
| ★ 예상재고 = 가용재고 + 입고예정(작업지시 · 발주) − 아직 할당되지 않은 소요예정, 주별 | 0008 · 0023 |
| ★ 할당은 작업지시를 확정하면 들어갈 자재에, 출하요청을 확정하면 나갈 제품에 생기고, 실제로 출고되면 풀리며 실재고가 준다. 할당된 수요는 예상재고 · MRP 소요에 다시 넣지 않는다 | 0007 · 0008 |
| ★ 다른 화면은 재고를 따로 셈하지 않고 이 정의 하나를 쓴다 | 0008 · 0015 · 0023 |
| ★ 검사대기는 「구매」(수입검사 입고) · 「영업」(고객 반품)이 만들고 「품질」이 가용 · 불량으로 판정한다. 검사대기는 출고하지 못한다 | 0008 · 0015 |
| ★ 사 오는 LOT 관리 품목은 거래처 LOT 를 반드시 넣는다. 만드는 LOT 관리 품목은 비우면 번호 규칙으로 붙고, 이미 있는 번호면 다음 일련으로 넘어간다 | 0015 · 0016 |
| ★ LOT 의 단은 LOT 하나(Batch · 포장 단위 없음). 옮기면 같은 번호로 두 창고에 나뉜다. LOT 분할 · 병합은 하지 않는다 | 0015 |
| 품목의 기본 입고 창고는 기타입고에서 창고를 미리 채우고, 기본 출고 창고는 뒤 메뉴(생산실적 · 영업 출고)가 읽는다. 불량창고는 고르지 못한다 | 0015 · 0022 |

## 수불 등록 · 취소

| 규칙 | ADR |
|---|---|
| ★ 수불관리의 등록 메뉴는 기타입고 · 기타출고 · 재고이동 · 재고조정 넷이고, 메뉴가 수불구분을 정한다 | 0020 |
| ★ 구매입고 · 생산입고 · 자재투입 · 제품출고 · 폐기는 각 모듈 화면이 넣고 그 유형으로 남는다. 짓는 메뉴가 `MOVE_TYPE` 에 더한다. 수불관리의 등록 메뉴는 늘리지 않는다 | 0008 · 0016 · 0020 |
| ★ 폐기는 품질의 불량 처분 때 불량창고에서 나가며 사유 · 불량 유형 · LOT 를 남긴다. 재고 조정과 섞지 않는다 | 0008 |
| ★ 기타입고와 늘리는 조정은 늘 가용으로 들어온다. 수불관리는 불량창고에서 내보내지 않는다(불량창고 안의 조정은 받는다). 이동은 상태를 그대로 싣고, 불량창고로 옮기면 불량이 된다 | 0015 |
| ★ 조정은 사유가 반드시 있다. 사유 「실사 차이」(`COUNT`)는 실사 확정만 쓴다 | 0008 · 0021 · 0022 |
| ★ 틀린 수불은 「취소」만 한다 — 반대 수량의 새 전표(일자 = 취소한 날, 원래 사유 · 원래 전표를 가리킴)가 생기고 원래 전표에 「취소됨」. 두 번 · 취소의 취소는 못 하고, 취소로 음수가 되면 막는다 | 0015 · 0016 · 0022 |

## 재고 실사

| 규칙 | ADR |
|---|---|
| ★ 실사는 창고 하나를 골라 연다. 장부 재고(품목 · LOT · 상태)가 줄로 오고, 장부에 없는 것은 줄을 더한다(더한 줄은 가용, 「사용」 품목만). 창고 하나에 작성 중 실사는 하나, 한 건 100줄까지 | 0015 · 0021 · 0022 |
| ★ 장부 · 실물 · 차이를 보인다(블라인드 아님). 장부 줄인지는 서버가 정하고, 처음 저장 전에 새 장부 줄이 생기면 처음 저장을 막는다 | 0021 · 0022 |
| ★ 확정은 모든 줄의 실물을 넣어야 한다. 확정하는 순간의 장부와 견준 차이를 「실사 차이」 조정 전표 하나(일자 = 확정한 날)로 넘긴다. 음수 검사도 지난다 | 0015 · 0021 |
| ★ 실사 중에도 그 창고의 수불을 막지 않는다. 연 뒤의 수불 · 줄 밖의 재고는 확정 화면이 경고만 한다 | 0015 · 0021 · 0022 |
| ★ 작성 중 실사는 취소할 수 있다(재고 그대로). 확정한 실사는 고치거나 취소하지 못하고, 그 조정 전표를 취소해 바로잡는다 | 0015 · 0021 |

## 재고 현황 · LOT

| 규칙 | ADR |
|---|---|
| 재고관리는 품목별 · 창고별 · LOT별 재고이고 칸은 실재고 · 검사대기 · 불량 · 가용재고. 할당 칸 · 예상재고 · 할당 현황은 「작업지시」가 짓는다 | 0023 |
| 지금 재고만 보인다. 지난 기간은 「수불부」(기초 · 입고 · 출고 · 기말)가 보인다 | 0023 |
| 「미달」 = 안전재고 > 0 이고 가용재고 < 안전재고(실재고와 견주지 않음) | 0023 |
| ★ LOT별 재고에는 LOT 관리 품목만 보인다. 끈 품목은 창고별 재고에서 본다 | 0025 |

## BOM

| 규칙 | ADR |
|---|---|
| ★ 부모 품목 하나에 BOM 하나(대체 자재 · 대체 BOM 없음). 부모는 반제품 · 완제품, 자품목은 원자재 · 반제품 · 부자재(완제품 · 소모품 불가) | 0026 |
| ★ BOM 마다 기준수량(부모 단위). 소요량은 기준수량당 정미 양, 로스율은 줄마다. 부모 1개당 필요량 = 소요량 ÷ 기준수량 × (1 + 로스율 ÷ 100) | 0026 |
| ★ 자품목 줄마다 적용 시작일 · 종료일(비우면 계속, 종료일은 그날까지). 설계변경은 옛 줄을 끝내고 새 줄을 시작해 지난 구성을 남긴다. 펼칠 때는 기준일에 적용되는 줄만 쓴다 | 0026 |
| ★ 돌고 도는 BOM 은 적용일자와 상관없이 막는다 | 0026 |
| 정전개 필요량은 끝수를 버리지 않고 이어 세고, 보일 때만 자품목 단위 자릿수로 올린다 | 0026 |
| ★ 한 화면에서 반제품 BOM 을 펼쳐 같이 넣고, 한 번의 저장은 고친 BOM 모두를 통째로 한다. 반제품 BOM 을 고치면 그것을 쓰는 다른 제품에도 바뀐다 | 0028 |
| BOM 을 저장 · 지울 때마다 무엇이 바뀌었는지(전 → 후)를 일시와 함께 이력으로 남긴다. 「누가」는 「인사」 뒤 | 0028 |

## 생산 기준정보 — 공정 · 작업장 · 불량 유형

| 규칙 | ADR |
|---|---|
| 공정의 칸은 코드 · 공정명 · 비고 · 사용 여부. 표준시간은 공정이 아니라 라우팅에 둔다 | 0031 |
| 작업장 하나는 공정 하나를 하고, 작업장의 공정은 등록 뒤 바꾸지 않는다(다른 공정이면 새 작업장) | 0032 |
| 불량 유형은 발생 공정을 여럿 붙이고, 비우면 공통 불량이다. 생산실적에서는 그 공정의 불량과 공통 불량만 고른다 | 0033 |
| ★ 불량 대분류는 공통코드 `DEFECT_CLS`(외관 · 치수 · 접합 · 전기 특성)이고 반드시 고른다 | 0033 |

## MPS

| 규칙 | ADR |
|---|---|
| ★ MPS 수량은 완제품의 공급량(완성할 주)이다. MRP 는 완제품을 다시 넷팅하지 않고 자재로만 펼친다 | 0036 |
| ★ 수요 = 확정한 판매계획의 품목 × 주 합(수주가 생기면 주마다 max(수주, 판매계획)). 지난 주의 미충족 수요는 넘기지 않는다 | 0007 · 0036 |
| ★ 처음 재고는 지금의 가용재고. 예상재고 = 지난주 예상재고 + MPS − 수요, 늘 이번 주부터 이어서 셈한다 | 0036 |
| ★ 안: (지난주 예상재고 − 수요) < 안전재고면 모자란 만큼을 최소 생산량 → 배수 → 단위 자릿수 올림. 리드타임은 쓰지 않는다 | 0036 |
| ★ 상태는 「안」 · 「고정」. 수량을 치고 저장하면 고정(0 도), 비우면 안으로 돌아간다. 고정 칸은 다시 셈하지 않고, 안은 읽을 때마다 다시 셈한다 | 0036 |
| ★ 줄여 고정해 예상재고가 음수가 되면 다음 미확정 주의 안이 채운다. 확정 구간은 두지 않는다 | 0036 |
| ★ 「사용 안 함」 완제품은 안전재고 0 으로 보고 남은 확정 수요만 채운다. 조달구분 「구매」 완제품도 MPS 에 든다 | 0036 |

## MRP · 페깅

| 규칙 | ADR |
|---|---|
| ★ 완제품 계획오더 = MPS 수량(고정 + 안, 0 이 아닌 칸). 그 아래 품목은 주마다 이어서 넷팅한다: 예상재고 = 지난주 예상재고 + 입고예정 + 계획오더 입고 − 총소요 | 0036 · 0037 |
| ★ (지난주 예상재고 + 입고예정 − 총소요) < 안전재고면 모자란 만큼을 최소량 → 배수 → 단위 자릿수 올림으로 그 주에 계획오더 하나. 첫 주는 지금의 가용재고에서 시작 | 0037 |
| ★ 입고예정 · 할당은 원천(작업지시 · 발주)이 없어 지금 0 이다. 직접 넣은 작업지시 · 발주도 생기면 입고예정으로 센다 | 0007 · 0037 |
| ★ 아래 품목 소요 = 계획량 × 소요량 ÷ 기준수량 × (1 + 로스율 ÷ 100). 분수로 모아 품목 × 주의 합에서 한 번만 올림한다(끝수는 올림만) | 0037 |
| ★ BOM 은 윗 계획오더의 시작일에 적용되는 줄로 펼친다. 「생산」은 생산 계획오더를 내고 펼치고, 「구매」는 구매 계획오더만 낸다. 적용 BOM 이 없으면 내되 펼치지 않는다(「BOM 없음」) | 0037 |
| ★ 소모품은 총소요 0 으로 들어 안전재고(= 재주문점)에 미달하면 구매 계획오더. 「사용 안 함」 품목은 안전재고 0 | 0037 |
| ★ 시작일 = 완성일 − 리드타임(달력일, 휴일 달력 없음)을 그 날짜의 주로 센다. 완성일 = max(기준 요일로 정한 날, 오늘), 기준 요일은 회사 기준값(처음 월요일) | 0037 |
| ★ 아래 품목의 완성일은 그 주 총소요 가운데 가장 이른 필요일(= 윗 계획오더의 시작일). 시작일이 오늘보다 앞이면 오늘로 당기고 「N일 늦음」을 실행한 날 기준으로 남긴다 | 0037 · 0038 |
| ★ [MRP 실행]이 셈해 저장하고 결과는 마지막 실행 하나만 남는다. 실행하면 확정하지 않은 계획오더를 모두 지우고 새로 낸다. 계획오더는 담당자가 확정해야 작업지시 · 발주가 된다 | 0007 · 0037 |
| ★ 페깅: 실행 때 수량까지 저장한다. 품목마다 필요일이 빠른 소요부터 재고 → 그 품목 계획오더(입고 주 차례)로 채우고, 안전재고 몫은 재고가 먼저 잡는다. 남는 수량은 다음 소요로 넘어간다 | 0038 |
