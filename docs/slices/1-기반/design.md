## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- 데모 주소의 첫 화면에 메뉴 여섯 영역이 보이고, 영역마다 「준비 중」 화면이 뜬다.
- 휴대폰 폭(가로 360px)에서 메뉴가 접히고, 화면이 가로로 넘치지 않는다.
- 상태 화면은 `DATABASE_URL` 로 DB 에 닿으면 「연결됨」과 DB 의 현재 시각을, 닿지 못하거나 값이 없으면 「연결 안 됨」을
  보인다. 어느 쪽이든 오류 페이지로 죽지 않는다.
- `main` 머지는 운영 배포를, PR 은 미리보기 배포를 낸다. 미리보기는 운영 DB 가 아닌 Neon 분기 DB 를 쓴다.
- 자동 검사 다섯 가지 중 하나라도 떨어지면 CI 가 실패한다.
- DB 접속 정보는 레포에 없다 — Vercel 환경변수에만 있고, 레포의 `.env.example` 은 이름만 든다.

**보장하지 않는 것(알려진 한계)**

- 첫 접속 속도 — 무료 요금제의 DB 가 쉬고 있다가 깨어나는 동안 첫 화면이 몇 초 늦을 수 있다.
- 접근 제한 — 로그인이 없어 주소를 아는 누구나 본다.
- 동시 사용자 · 부하.
- 휴대폰에서의 업무 입력 편의 — 깨지지 않는 것까지만 본다.
- 무료 요금제 정책이 바뀌는 것.
- 상태 화면이 보이는 것은 연결 여부와 시각뿐이다 — DB 의 테이블 · 데이터는 보지 않는다.

## ③ 받는 입력

- 환경변수 `DATABASE_URL` 하나 — PostgreSQL 접속 문자열. 없거나 형식이 틀리면 상태 화면이 「연결 안 됨」을 보인다.
- 그 밖의 환경변수와 화면 입력은 읽지 않는다 — 이 조각에는 입력 칸이 없다.

## ④ 결정

**정한 것**

- 스택 — TypeScript · Next.js · PostgreSQL. 대안은 Java Spring Boot · React. ADR 0001.
- 배포처 — Vercel(앱) · Neon(DB), 미리보기는 Neon 분기 DB. 대안은 Render · Supabase · Fly.io. ADR 0002.

**열어 둔 것**

- 화면 구성 요소 라이브러리 · 시험 도구 · 패키지 관리자 — PR A 를 열기 전에 정한다.
- DB 접근 도구(ORM)와 마이그레이션 방식 — PR B 를 열기 전에 정한다.

## ⑤ 검증 계획

- **화면 틀(PR A)** — 로컬 실행 화면 캡처를 PR 본문에 싣는다: 첫 화면, 메뉴 하나를 누른 「준비 중」 화면, 휴대폰 폭(가로 360px)의 첫 화면.
- **자동 검사(PR A)** — CI 가 초록인 것과 함께, 타입 오류 · 형식 오류 · 실패하는 시험 · 문서 모양 오류를 하나씩 넣은
  사본에서 같은 검사 명령이 실패하는 것을 PR 본문에 보인다(어긋내 봐서 떨어지는 것).
- **상태 화면(PR B)** — 키 없이 도는 시험을 더한다. 시험 규칙: ② 상태 화면의 조건(닿음 · 닿지 못함 · 값 없음)마다
  시험 하나 이상, 「연결됨」 시험은 시각이 보이는지를, 「연결 안 됨」 시험은 오류로 죽지 않고 그 글자가 보이는지를 본다.
  DB 는 시험 안에서 가짜로 바꿔 끼운다.
- **배포(PR B)** — 데모 주소의 첫 화면 · 상태 화면 캡처, 머지 뒤 데모가 바뀐 것, PR 의 미리보기 주소를 PR 본문에 싣는다.
  저자가 `docs/deploy.md` 순서대로 이전 배포로 되돌려 보고 결과를 PR 에 남긴다.
- **접속 정보(PR B)** — 레포 전체에서 `postgres://` · `postgresql://` 로 시작하는 값이 없음을 검사 명령으로 보인다.
- **비용** — Vercel · Neon 의 요금 화면이 무료 요금제인 것을 저자가 확인한다(PR B).

## 2026-11-02 — PR A 를 열기 전에 정한 것

④ 의 열어 둔 것 가운데 PR A 몫이다. 업무에 영향이 없는 기술 결정이라 Claude 가 정했다(작업 규칙).

- **화면 모양** — 공장 현장에서 가져온 색(기계 도장 녹색 메뉴 판, 지금 영역을 표시하는 바닥 안전선 노랑, 콘크리트 바탕)과
  IBM Plex Sans KR 글꼴(`@fontsource/ibm-plex-sans-kr` 로 앱에 싣는다 — 빌드가 바깥 글꼴 서버에 기대지 않게). 첫 화면은

  해서 frontend-design 스킬로 다시 잡았다.
- **① 에 더하는 것** — Next.js 뼈대가 `AGENTS.md` 를 함께 만든다(Next.js 가 쓰고 고치는 안내). PR A 는 그것을 싣고, `CLAUDE.md`

## 2026-11-02 — 닫기 전 재감사로 PR C 에 더한 것

`audit-ops` 재감사(회차 4)가 NC-4 를 「일부 고침」으로 유지했다 — 머지 뒤 빌드가 실패하거나 되돌린 뒤 Undo Rollback 을
잊으면 데모가 옛 버전인 채 「연결됨」이라 정기 확인이 통과한다. 이 조각의 닫는 PR 에서 PR C 의 정기 확인을 넓힌다.

- **② 에 더하는 보장** — 정기 확인은 데모 화면의 「커밋」이 `main` 의 최신 커밋과 같은지도 본다. 빌드를 최대 10분 기다린 뒤에도
  다르면 실패하고 메일이 간다. 손으로 돌릴 때 주소를 넣을 수 있어, 없는 주소로 실패 메일이 오는지 시험할 수 있다(U-5).
- **정한 것** — 감사의 제안 둘 가운데 (a) 정기 확인에서 커밋을 견준다. (b) Vercel 계정의 배포 실패 메일은 레포 밖 설정이라
  꺼져도 아무도 모르고, 「되돌린 뒤 Undo 를 잊음」을 잡지 못한다 — 업무에 영향이 없는 기술 결정이라 Claude 가 정했다.
- **⑤ 에 더하는 검증** — 확인 스크립트를 데모에 네 경우로 돌려 본 결과: 최신 커밋(통과) · 다른 커밋(기다린 뒤 실패) · 없는
  주소(바로 실패) · 기본 가지가 아닌 실행(버전을 견주지 않고 통과).
- **재감사 회차 5 뒤에 고친 것** — 버전을 견줄지 고르는 조건이 GitHub 이벤트 내용(`repository.default_branch`)에 기대 있어
  예약 실행에서 꺼질 수 있었다. 「예약 실행이거나 `main` 에서 돈 실행」으로 이름을 적어 고르고, 견주지 않은 실행은 그 까닭(실행
  종류 · 가지)을 기록에 찍는다. 되돌린 동안 오는 실패 메일은 예상된 것이라고 배포 문서 「되돌리기」에 적었다.
- **리뷰(Codex)로 고친 것** — 기다리는 동안 다른 커밋이 `main` 에 머지돼 데모가 그것으로 바뀌면, 실행이 시작할 때의 커밋과
  견줘 「옛 버전이다」로 잘못 실패했다. 견줄 커밋을 시도마다 GitHub 에서 `main` 의 최신으로 다시 읽는다(읽지 못하면 실행이
  시작할 때의 커밋). 로컬에서 GitHub 응답을 흉내 내 다섯 경우를 돌려 봤다: `main` 이 앞으로 감(통과) · 못 읽음 + 같음(통과) ·
  못 읽음 + 다름(실패) · 다른 커밋(실패) · 주소에 닿지 못함(시작 커밋으로 통과).
