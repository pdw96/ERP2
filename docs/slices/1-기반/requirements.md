# 조각 1 — 기반 (2026-11-02 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR.

## 문제

- 레포에 코드가 없다. 채용 담당자가 결과물을 열어 볼 데모 주소가 없고, 뒤의 조각(기준정보 ~ 인사)이 화면을 올릴 자리도 없다.
- 저자는 코드를 거의 읽지 않고 화면으로 판단한다. PR 마다 화면을 미리 볼 길과, 깨진 변경을 사람 대신 막는 자동 검사가
  없으면 저자가 머지 전에 맞음을 확인할 수 없다.

## 핵심 사용자와 시나리오

- 사용자: 저자(pdw96) — 생산 · 재고 · 출하 관리 자리에 지원하는 포트폴리오 주인.
- 시나리오: Claude 가 PR 을 올린다 → 자동 검사가 초록불이고, PR 에 붙은 미리보기 주소에서 화면을 본다 → 머지한다 →
  몇 분 뒤 데모 주소에 그 화면이 보인다 → 잘못됐으면 이전 배포로 되돌린다.

## 성공 기준

1. 데모 주소(`*.vercel.app`)를 열면 ERP 화면 틀이 뜨고, 왼쪽 메뉴에 영역 여섯(재고 · 생산 · 구매 · 영업 · 회계 · 인사)이
   보인다. 메뉴를 누르면 그 영역의 「준비 중」 화면이 뜬다. 휴대폰으로 열어도 메뉴가 접히고 화면이 깨지지 않는다.
2. 데모 주소의 상태 화면이 DB 에 연결됐는지와 DB 의 현재 시각을 보인다. DB 에 닿지 못하면 오류 페이지가 아니라
   「연결 안 됨」을 보인다.
3. `main` 에 머지하면 사람 손 없이 데모 주소가 새 버전으로 바뀐다.
4. PR 마다 자동 검사(형식 · 타입 · 시험 · 문서 모양)가 돌고, 하나라도 떨어지면 PR 에 빨간불이 켜진다. PR 마다 미리보기
   주소가 붙는다.
5. 데모를 이전 배포로 되돌리는 길이 있고, 저자가 한 번 해 봤다.
6. 드는 돈이 0원이다.

## 하지 않을 일

1. 이 조각에서는 업무 화면(품목 · 창고 등록 같은 것)과 업무 테이블을 만들지 않는다 — 조각 「기준정보」부터 조각마다 붙는다.
2. 이 조각에서는 로그인 · 권한을 만들지 않는다 — 데모 주소를 아는 누구나 본다. 사용자는 조각 「인사」가 다룬다.
3. 이 조각에서는 샘플 데이터를 넣지 않는다 — 넣을 업무 테이블이 없다. 업무 조각마다 그 영역의 샘플 데이터를 함께 넣는다.
4. 레포 공개 전환 · README 꾸미기는 하지 않는다 — 조각 「포트폴리오 정리」.
5. 데모와 똑같은 확인용 사본 사이트(스테이징)를 따로 두지 않는다 — 머지 전 확인은 PR 마다 붙는 미리보기 주소에서 한다.
6. 휴대폰 전용 화면 배치는 만들지 않는다 — 휴대폰으로 열어도 깨지지 않게만 한다(성공 기준 1).

## 제약

- 스택: TypeScript · Next.js · PostgreSQL(ADR 0001). 배포처: Vercel · Neon(ADR 0002).
- 비용: 무료 요금제 안 — Vercel Hobby · Neon Free · GitHub Actions 무료 분량.
- 쿼터: Neon Free 저장 0.5GB, Vercel Hobby 는 비상업 용도, GitHub Actions 는 비공개 레포에서 월 2,000분.
- 기간: 정해진 기한 없음.
- 저자 손이 필요한 일: Vercel · Neon 가입과 GitHub 레포 연결, 되돌리기 한 번 해 보기 — Claude 의 작업 환경에서는 할 수
  없다. 설계 ⑥ 의 PR B 가 따라 할 순서를 든다.
- 리뷰 한도: 한 PR 에서 리뷰가 5회차를 넘기면 저자가 판정한다.
- 감사 회차: 닫기 전 — `audit-secrets`(DB 접속 정보 · 환경변수를 처음 다룬다) · `audit-ops`(배포와 되돌리기를 처음 세운다).
