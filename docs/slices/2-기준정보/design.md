## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- 코드는 테이블 안에서 겹치지 않는다 — DB 의 유일 제약이 막는다. 꼴은 ADR 0003 의 것만 생긴다.
- 코드와 품목 유형은 등록한 뒤 바뀌지 않는다 — 수정 화면에 그 칸이 없고, 서버도 받지 않는다. 조달구분은 유형의 기본값으로
  붙고 바꿀 수 있다.
- 공통코드의 「시스템 코드」 묶음(`ITEM_TYPE` · `PROC_TYPE`)은 화면에도 서버에도 바꾸는 길이 없다. 그 값은 프로그램이 아는
  값과 같다 — 시험이 견준다. 「사용자 코드」 묶음(`UNIT`)의 Minor 는 추가 · 이름 · 정렬 순서 · 사용 여부만 바뀌고, 코드는
  바뀌지 않으며 지워지지 않는다. 묶음(Major)을 만드는 화면은 없다.
- 품목의 단위 · 유형 · 조달구분은 공통코드에 있는 값만 받는다 — DB 의 참조 제약이 막는다. 새 품목과 단위를 바꾸는 수정은
  「사용 안 함」이 아닌 단위만 받고, 이미 「사용 안 함」 단위를 가진 품목은 그 단위 그대로 저장된다.
- 설계도 화면의 그림은 레포 안의 한 곳(`src/content/diagrams.ts`)에서 나온다 — 조각의 PR 이 테이블 · 부품 · 흐름을 바꾸면 같은
  PR 이 그림도 고친다. 그림은 누구나 보고, DB 를 읽지 않는다.
- 입력 검사는 서버에서 한다 — 화면의 검사를 건너뛴 요청도 같은 규칙으로 거절한다. 거절하면 어느 칸이 왜 틀렸는지 보인다.
- 「사용 안 함」은 목록의 기본 보기와 뒤 조각의 새 입력에서 빠지고, 지난 기록이 가리키는 행은 남는다. 지우는 길은 없다.
- 매일 밤 한 번 다섯 테이블이 샘플 데이터로 돌아간다 — 코드의 번호도 샘플의 다음 번호부터 다시 붙는다. 되돌림의 입구는
  `CRON_SECRET` 을 가진 요청만 받고, 없거나 틀리면 아무것도 바꾸지 않는다.
- 마이그레이션은 배포 빌드가 배포 전에 적용한다. 적용이 실패하면 그 배포는 나가지 않고 데모는 앞 배포에 남는다.
- 방문자가 넣은 글자는 로그에 남지 않는다 — 실패 로그는 오류 코드만 남긴다(「기반」 회차 3 의 OB-1).
- 테이블마다 등록 수에 상한이 있다 — 누가 끝없이 넣어도 무료 저장 한도(0.5GB)에 닿지 않는다.

**보장하지 않는 것(알려진 한계)**

- 같은 날 안의 장난 — 누가 이상한 글을 등록하면 그날 밤 되돌림까지 다른 방문자에게 보인다(저자 판정, ADR 0004).
- 되돌림의 정확한 시각 — Vercel Hobby 의 예약 작업은 정한 시(時) 안의 어느 때에 돈다.
- 동시에 같은 행을 고치면 나중 것이 남는다.
- 찾기는 코드 · 이름에 글자가 들어 있는지만 본다 — 초성 · 오타는 찾지 않는다.
- 되돌림은 운영 DB 만 한다 — PR 미리보기의 분기 DB 는 그 배포의 샘플 그대로 둔다.
- 설계도는 손으로 고치는 그림이다 — 코드에서 저절로 뽑지 않으므로, PR 이 고치기를 잊으면 코드와 어긋날 수 있다. 리뷰와 닫기 전
  감사가 본다.

## ③ 받는 입력

- **화면 입력** — 닫힌 목록 밖의 값은 거절한다.
  - 품목: 유형(원자재 · 반제품 · 완제품 셋 가운데 하나), 조달구분(구매 · 생산 가운데 하나), 품명(1 ~ 100자), 규격(0 ~ 100자),
    단위(공통코드 `UNIT` 의 사용 중인 값 가운데 하나), 수입검사 대상 · 출하검사 대상(켬 · 끔), 리드타임(0 ~ 365 일의 정수),
    안전재고 · 최소 발주 · 생산량(0 이상, 품목의 단위로 소수 셋째 자리까지), 발주 · 생산 배수(0 이면 배수 없음, 아니면 0 보다
    큰 수), 사용 여부.
  - 창고: 창고명(1 ~ 50자), 사용 여부.
  - 거래처: 거래처명(1 ~ 100자), 매입처 · 매출처(하나 이상), 사업자등록번호(비우거나 `000-00-00000` 꼴), 사용 여부.
  - 공통코드(사용자 코드 묶음의 Minor): 코드(대문자 또는 숫자로 시작하는 대문자 · 숫자 · 밑줄 1 ~ 20자, 등록할 때만), 이름
    (1 ~ 50자), 정렬 순서(0 ~ 999 의 정수), 사용 여부. 시스템 코드 묶음에는 입력이 없다.
  - 목록: 찾을 글자(0 ~ 50자), 거르기(위 닫힌 목록), 「사용 안 함 포함」.
  - 설계도 화면: 입력 없음 — 그림(업무 흐름의 스윔레인 · Overview, 데이터 모델, 시스템 구성)을 고르는 탭뿐이다.
  - 스윔레인 데이터(`src/content/diagrams.ts`): 칸 이름의 닫힌 목록, 단계마다 칸 · 줄 · 모양(시작 · 끝 / 작업 / 판단) · 글,
    화살표마다 앞 · 뒤 단계와 표시(예 · 아니오). 목록에 없는 칸이나 없는 단계를 가리키는 화살표는 시험이 거절한다.
- **환경변수** — `DATABASE_URL`(「기반」 그대로), `CRON_SECRET`(되돌림 입구의 비밀값, Vercel 운영 환경에만).

## ④ 결정

**정한 것**

- 코드의 꼴 · 품목 유형 · 조달구분 · 검사 대상 · 단위 · 지우지 않고 「사용 안 함」 · 창고만(위치 없음) · 거래처 하나에 매입 ·
  매출 표시 — 저자 판정. ADR 0003.
- 메뉴 「시스템 관리」와 공통코드 — 공통코드만 이 조각에서, 계산이 기대는 묶음은 「시스템 코드」로 잠금, 영문 대문자 약어 —
  저자 판정(2026-11-02). 묶음(Major)은 화면에서 만들지 않고 조각의 PR 이 더한다 — 화면이 읽지 않는 묶음은 쓸 곳이 없어서다.
  ADR 0009.
- 품목의 계획 정보(리드타임 · 안전재고 · 최소 발주 · 생산량 · 발주 · 생산 배수) — 저자 판정. 쓰는 곳은 조각 「MRP」. ADR 0003 · 0007.
- 설계도 화면 — 저자 요청(2026-11-02). 그림은 Mermaid 글로 써서 앱이 그린다(대안은 손으로 그린 SVG · 그림 파일). ADR 0006.
- 데모는 누구나 등록 · 수정하고, 매일 밤 샘플로 되돌린다 — 저자 판정. 되돌림은 Vercel Cron 이 앱의 입구를 부른다(대안은
  GitHub Actions 예약 실행 — DB 접속 정보를 GitHub 에도 두게 된다). ADR 0004.
- 마이그레이션은 drizzle-kit 이 만든 SQL 을 배포 빌드가 적용한다(대안은 앱이 켜질 때 적용 · 손으로 적용). ADR 0005.
- 샘플 회사 — 가상 반도체 후공정(패키징) 회사(저자 판정). 이름은 「(가상)」을 붙여 실제 회사로 읽히지 않게 한다.

**열어 둔 것**

- 코드 번호를 매기는 방법(같은 유형의 가장 큰 번호 + 1 과 겹칠 때 다시 시도 · DB 시퀀스)과 테이블마다 등록 상한의 수 — PR B 를
  열기 전에 정한다. → 정함, 아래 「2026-11-03 — PR B 를 열기 전에 정한 것」.
- 입력 화면을 짓는 방법(Next.js 서버 액션 · 입력 검사 도구) — PR C 를 열기 전에 정한다.

## ⑤ 검증 계획

- **설계도(PR A)** — 그림이 오류 없이 그려지는 화면 시험(그림 글이 틀리거나, 스윔레인이 없는 칸 · 없는 단계를 가리키거나, 두
  단계가 한 자리에 겹치면 시험이 실패하는 것까지)과, 미리보기 주소의 캡처(넓은 화면 · 휴대폰 폭 390px — 스윔레인은 옆으로
  넘겨 본다). 그림의 내용은 저자가 캡처로 본다.
- **코드 · 입력 규칙(PR B · C · D)** — 키 없이 도는 시험. 시험 규칙: ② 의 보장마다, ③ 의 칸마다 맞는 꼴 하나와 틀린 꼴 하나
  이상. 거절 시험은 저장되지 않은 것과 어느 칸인지를, 성공 시험은 저장된 값과 붙은 코드를 본다. 코드 시험은 유형마다 첫 번호 ·
  다음 번호 · 겹침 거절을, 조달구분 · 검사 대상 시험은 유형마다 기본값과 바꾼 값이 남는 것을, 계획 정보 시험은 범위의 경계
  (0 · 365 · 음수 · 소수 넷째 자리)를 본다. DB 는 PGlite(내 컴퓨터에서 도는 PostgreSQL)로 실제 SQL 을 돌린다.
- **마이그레이션(PR B)** — 빈 DB 에 적용 → 테이블이 생김, 두 번 적용해도 그대로, PR 미리보기의 빌드 기록에 적용 줄이 찍히고
  미리보기 분기 DB 에 테이블이 생긴 것(Neon 커넥터로 읽기만), 일부러 틀린 마이그레이션이면 빌드가 실패하는 것을 PR 본문에 싣는다.
- **되돌림(PR B)** — 비밀값 없음 · 틀림이면 거절하고 아무것도 바뀌지 않음, 맞으면 다섯 테이블이 샘플과 같아짐, 두 번 불러도 같음 —
  시험으로. 머지 뒤 데모에서 첫 예약 실행의 기록을 본다.
- **샘플 데이터(PR B)** — 실제 회사명 · 사람 이름이 없는지 목록을 PR 본문에 싣고 저자가 본다.
- **공통코드(PR B · E)** — 시스템 코드 묶음을 바꾸는 요청이 서버에서 거절되는 것, 시스템 코드의 값이 프로그램의 목록과 같은 것,
  Minor 코드의 맞는 꼴 · 틀린 꼴 · 묶음 안의 겹침 거절, 더한 단위가 품목 등록 목록에 보이는 것, 「사용 안 함」 단위가 새 품목에서
  거절되고 이미 쓴 품목에는 남는 것 — 시험으로.
- **화면(PR C · D · E)** — 목록 · 등록 · 수정 · 거절 · 「사용 안 함」의 화면 시험과, 미리보기 주소의 캡처(넓은 화면 · 휴대폰 폭 390px).
- **비용** — 새 예약 작업이 Vercel Hobby 안(하루 한 번)인 것을 PR B 본문에 적는다.

## 2026-11-02 — PR A 를 열기 전에 정한 것

업무에 영향이 없는 기술 결정이라 Claude 가 정했다.

- **주소** — 그림마다 한 주소: `/design`(업무 흐름 — 스윔레인 · Overview) · `/design/model`(데이터 모델) · `/design/system`(시스템
  구성). 탭은 그 주소로 가는 링크라, 그림 하나를 링크로 건넬 수 있다. 셋 다 빌드 때 만드는 고정 화면이다.
- **메뉴의 자리** — 메뉴 판 아래 「시스템 상태」 옆에 「설계도」. 휴대폰 폭에서는 「메뉴」를 펼치면 이 둘도 함께 보인다(지금까지
  「시스템 상태」는 휴대폰에서 보이지 않았다).

  230KB 그대로, 설계도 화면은 약 1.5MB 를 더 받는다.
- **Mermaid 의 판** — 12.2.0(2026-10-13)을 고정한다. 11.17.2 는 수식 부품(katex)의 알려진 취약점 2건(낮음)을 끌어와, 「기반」을

- **넓이** — 그림은 제 넓이 그대로 두고 칸 안에서 옆으로 민다. 줄여서 맞추면 글자가 읽기 어려울 만큼 작아진다.

  지도(`MODULE_MAP` · `MODULE_FLOWS` 데이터를 `src/components/module-map.tsx` 가 카드로 그린다. Mermaid 로 그리면 모듈 사이의

  중 · 다 그림 · 실패의 화면. 미리보기 주소의 캡처(넓은 화면 · 휴대폰 폭 390px)는 PR 본문에 싣는다.

## 2026-11-03 — PR B 를 열기 전에 정한 것

업무에 영향이 없는 기술 결정이라 Claude 가 정했다.

- **코드 번호** — 같은 머리(`RM` · `SF` · `FG` · `WH` · `BP`)의 가장 큰 번호 + 1(`src/db/numbering.ts`). 두 사람이 같은 번호를
  받으면 DB 의 유일 제약이 뒤의 것을 거절하고, 등록 쪽(PR C · D)이 번호를 다시 받아 한 번 더 넣는다. 대안인 DB 시퀀스는 실패한
  등록도 번호를 써 버려 번호가 비고, 되돌림이 시퀀스를 따로 되감아야 한다. 지우는 길이 없어 가장 큰 번호 + 1 은 비지 않고, 되돌린
  뒤에는 저절로 샘플의 다음 번호부터 붙는다.
- **등록 상한** — 품목 2,000 · 거래처 1,000 · 창고 99 · 공통코드는 묶음마다 100. 등록하는 서버(PR C · D · E)가 센다. 한 행이 1KB
  안이라 다 차도 몇 MB — 무료 저장 0.5GB 에 닿지 않는다. 매일 밤 되돌림이 다시 샘플 수로 줄인다. 창고는 두 자리 번호의 끝까지다.
- **DB 의 제약** — 코드의 꼴(품목은 머리가 유형과 같은 것까지) · 이름의 길이 · 리드타임 · 수량 · 정렬 순서의 범위 · 매입처 ·
  매출처 하나 이상 · 사업자등록번호의 꼴을 DB 도 막는다. 서버의 검사(PR C · D · E)를 고치다 빠뜨려도 틀린 행이 쌓이지 않게다.
  제약 이름(`items_code_format` 따위)으로 거절된 칸을 가른다.
- **공통코드 참조** — 품목에 늘 같은 값인 묶음 칸 셋(`item_type_group` · `procurement_group` · `unit_group`)을 두고 묶음 + 코드로
  `codes` 를 가리킨다. PostgreSQL 의 참조 제약은 고정값을 가리킬 수 없어서다(대안인 DB 트리거는 SQL 을 손으로 써야 한다).
- **기본 키** — `docs/schema.md` 의 규칙대로 다섯 테이블 모두 `id` 이고, 공통코드 묶음의 코드 · 값의 묶음 + 코드는 유일 키다.
  설계도의 「이 조각의 테이블」에서 그 둘의 표시를 PK 에서 UK 로 고쳤다.
- **첫 샘플 데이터** — 배포 빌드가 마이그레이션 뒤 DB 가 비어 있으면(공통코드 묶음 0 행) 샘플을 넣는다. 데이터가 있으면 손대지
  않는다 — 배포가 방문자의 데이터를 지우지 않는다. 성공 기준 1 의 「처음부터 들어 있다」를 첫 되돌림까지 기다리지 않게다.
- **적용의 접속** — Vercel 의 Neon 연동이 함께 넣는 직결 주소(`DATABASE_URL_UNPOOLED`)가 있으면 그것으로 적용하고, 두 빌드가 같은
  DB 에 동시에 적용하지 않게 잠금(advisory lock)을 건다. 연결 풀 주소뿐이면 잠금 없이 — 풀에서는 잠금이 다른 접속에 남을 수 있다.
- **예약 시각** — 매일 19:00 UTC(한국 04시대). 정기 확인의 03:17 과 겹치지 않는다.
- **되돌림 입구** — `GET /api/cron/reset`. `Authorization: Bearer <CRON_SECRET>` 을 해시로 견주고(길이로 새지 않게), 비밀값이
  설정되지 않았거나 틀리면 401 로 DB 에 닿지 않는다. 응답과 로그에는 테이블마다 행 수만, 실패는 오류 코드 · 등급과 스키마의 이름(테이블 · 칸 · 제약)만 남긴다 — DB 서버의 메시지에는 행의 값이 실릴 수 있어 남기지 않는다(대장 NC-6, 저자 판정 2026-11-03). 메시지는 질의가 고정된 상태 확인만 남긴다.
- **도구** — `drizzle-kit`(마이그레이션 SQL 만들기) · `tsx`(빌드 때 TypeScript 스크립트 돌리기) · `@electric-sql/pglite`(시험의
  DB). 셋 다 개발용이라 데모에 실리지 않는다 — 배포 의존성의 취약점은 0 건 그대로다. `drizzle-kit` 이 끌어오는 옛 `esbuild` 의
  알려진 취약점(보통, 개발 서버에서만)은 개발용 의존성에 남는다.
- **⑤ 에 더하는 검증** — 되돌림이 비우는 테이블이 스키마의 테이블 전부인지(테이블을 더하고 되돌림에 잊으면 실패), 되돌림이
  중간에 실패하면 아무것도 바뀌지 않는지, 틀린 마이그레이션이 실패를 던지고 잠금을 푸는지를 시험으로 본다.
