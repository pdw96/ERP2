## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- 코드는 테이블 안에서 겹치지 않는다 — DB 의 유일 제약이 막는다. 꼴은 ADR 0003 의 것만 생긴다.
- 코드와 품목 유형은 등록한 뒤 바뀌지 않는다 — 수정 화면에 그 칸이 없고, 서버도 받지 않는다. 조달구분은 유형의 기본값으로
  붙고 바꿀 수 있다.
- 공통코드의 「시스템 코드」 묶음(`ITEM_TYPE` · `PROC_TYPE`)은 화면에도 서버에도 바꾸는 길이 없다. 그 값은 프로그램이 아는
  값과 같다 — 시험이 견준다. 「사용자 코드」 묶음(`UNIT`)의 Minor 는 추가 · 이름 · 정렬 순서 · 사용 여부만 바뀌고, 코드는
  바뀌지 않으며 지워지지 않는다. 묶음(Major)을 만드는 화면은 없다.
- 품목의 단위 · 유형 · 조달구분은 공통코드에 있는 값만 받는다 — DB 의 참조 제약이 막는다. 새 품목과 단위를 바꾸는 수정은
  「사용 안 함」이 아닌 단위만 받고, 이미 「사용 안 함」 단위를 가진 품목은 그 단위 그대로 저장된다.
- 설계도 화면의 그림은 레포 안의 한 곳(`src/content/diagrams.ts`)에서 나온다 — 조각의 PR 이 테이블 · 부품 · 흐름을 바꾸면 같은
  PR 이 그림도 고친다. 그림은 누구나 보고, DB 를 읽지 않는다.
- 입력 검사는 서버에서 한다 — 화면의 검사를 건너뛴 요청도 같은 규칙으로 거절한다. 거절하면 어느 칸이 왜 틀렸는지 보인다.
- 「사용 안 함」은 목록의 기본 보기와 뒤 조각의 새 입력에서 빠지고, 지난 기록이 가리키는 행은 남는다. 지우는 길은 없다.
- 매일 밤 한 번 다섯 테이블이 샘플 데이터로 돌아간다 — 코드의 번호도 샘플의 다음 번호부터 다시 붙는다. 되돌림의 입구는
  `CRON_SECRET` 을 가진 요청만 받고, 없거나 틀리면 아무것도 바꾸지 않는다.
- 마이그레이션은 배포 빌드가 배포 전에 적용한다. 적용이 실패하면 그 배포는 나가지 않고 데모는 앞 배포에 남는다.
- 방문자가 넣은 글자는 로그에 남지 않는다 — 실패 로그는 오류 코드만 남긴다(「기반」 회차 3 의 OB-1).
- 테이블마다 등록 수에 상한이 있다 — 누가 끝없이 넣어도 무료 저장 한도(0.5GB)에 닿지 않는다.

**보장하지 않는 것(알려진 한계)**

- 같은 날 안의 장난 — 누가 이상한 글을 등록하면 그날 밤 되돌림까지 다른 방문자에게 보인다(저자 판정, ADR 0004).
- 되돌림의 정확한 시각 — Vercel Hobby 의 예약 작업은 정한 시(時) 안의 어느 때에 돈다.
- 동시에 같은 행을 고치면 나중 것이 남는다.
- 찾기는 코드 · 이름에 글자가 들어 있는지만 본다 — 초성 · 오타는 찾지 않는다.
- 되돌림은 운영 DB 만 한다 — PR 미리보기의 분기 DB 는 그 배포의 샘플 그대로 둔다.
- 설계도는 손으로 고치는 그림이다 — 코드에서 저절로 뽑지 않으므로, PR 이 고치기를 잊으면 코드와 어긋날 수 있다. 리뷰와 닫기 전
  감사가 본다.

## ③ 받는 입력

- **화면 입력** — 닫힌 목록 밖의 값은 거절한다.
  - 품목: 유형(원자재 · 반제품 · 완제품 셋 가운데 하나), 조달구분(구매 · 생산 가운데 하나), 품명(1 ~ 100자), 규격(0 ~ 100자),
    단위(공통코드 `UNIT` 의 사용 중인 값 가운데 하나), 수입검사 대상 · 출하검사 대상(켬 · 끔), 리드타임(0 ~ 365 일의 정수),
    안전재고 · 최소 발주 · 생산량(0 이상, 품목의 단위로 소수 셋째 자리까지), 발주 · 생산 배수(0 이면 배수 없음, 아니면 0 보다
    큰 수), 사용 여부. PR H 부터 대분류 · 중분류 · 소분류(각각 공통코드 사용자 코드 묶음의 사용 중인 값, 비워도 됨), 비고(글자 그대로,
    비워도 됨 — 길이는 PR H 를 열기 전에 정한다)(ADR 0012).
  - 창고: 창고명(1 ~ 50자), 사용 여부.
  - 거래처: 거래처명(1 ~ 100자), 매입처 · 매출처(하나 이상), 사업자등록번호(비우거나 `000-00-00000` 꼴), 사용 여부. PR G 부터
    국가(공통코드 `COUNTRY` 의 사용 중인 값, 기본 `KR`)와, 국가가 `KR` 이 아니면 사업자등록번호 대신 해외 사업자번호(글자 그대로,
    비워도 됨 — 30자까지, 아래 「PR G 를 열기 전에 정한 것」)(ADR 0011). PR H 부터 대표자 · 업태 · 종목 · 주소 · 전화 · 이메일 ·
    담당자(이름 · 연락처) · 비고(모두 비워도 됨 — 길이 · 전화 · 이메일의 꼴은 PR H 를 열기 전에 정한다)(ADR 0012).
  - 공통코드(사용자 코드 묶음의 Minor): 코드(대문자 또는 숫자로 시작하는 대문자 · 숫자 · 밑줄 1 ~ 20자, 등록할 때만), 이름
    (1 ~ 50자), 정렬 순서(0 ~ 999 의 정수), 사용 여부. 시스템 코드 묶음에는 입력이 없다.
  - 목록: 찾을 글자(0 ~ 50자), 거르기(위 닫힌 목록), 「사용 안 함 포함」.
  - 설계도 화면: 입력 없음 — 그림(업무 흐름의 스윔레인 · Overview, 데이터 모델, 시스템 구성)을 고르는 탭뿐이다.
  - 스윔레인 데이터(`src/content/diagrams.ts`): 칸 이름의 닫힌 목록, 단계마다 칸 · 줄 · 모양(시작 · 끝 / 작업 / 판단) · 글,
    화살표마다 앞 · 뒤 단계와 표시(예 · 아니오). 목록에 없는 칸이나 없는 단계를 가리키는 화살표는 시험이 거절한다.
- **환경변수** — `DATABASE_URL`(「기반」 그대로), `CRON_SECRET`(되돌림 입구의 비밀값, Vercel 운영 환경에만).

## ④ 결정

**정한 것**

- 코드의 꼴 · 품목 유형 · 조달구분 · 검사 대상 · 단위 · 지우지 않고 「사용 안 함」 · 창고만(위치 없음) · 거래처 하나에 매입 ·
  매출 표시 — 저자 판정. ADR 0003.
- 메뉴 「시스템 관리」와 공통코드 — 공통코드만 이 조각에서, 계산이 기대는 묶음은 「시스템 코드」로 잠금, 영문 대문자 약어 —
  저자 판정(2026-11-02). 묶음(Major)은 화면에서 만들지 않고 조각의 PR 이 더한다 — 화면이 읽지 않는 묶음은 쓸 곳이 없어서다.
  ADR 0009.
- 품목의 계획 정보(리드타임 · 안전재고 · 최소 발주 · 생산량 · 발주 · 생산 배수) — 저자 판정. 쓰는 곳은 조각 「MRP」. ADR 0003 · 0007.
- 설계도 화면 — 저자 요청(2026-11-02). 그림은 Mermaid 글로 써서 앱이 그린다(대안은 손으로 그린 SVG · 그림 파일). ADR 0006.
- 데모는 누구나 등록 · 수정하고, 매일 밤 샘플로 되돌린다 — 저자 판정. 되돌림은 Vercel Cron 이 앱의 입구를 부른다(대안은
  GitHub Actions 예약 실행 — DB 접속 정보를 GitHub 에도 두게 된다). ADR 0004.
- 마이그레이션은 drizzle-kit 이 만든 SQL 을 배포 빌드가 적용한다(대안은 앱이 켜질 때 적용 · 손으로 적용). ADR 0005.
- 샘플 회사 — 가상 반도체 후공정(패키징) 회사(저자 판정). 이름은 「(가상)」을 붙여 실제 회사로 읽히지 않게 한다.
- 시트형 등록 — 저자 판정(2026-11-03, PR C 검토). 이 조각에서 PR D 뒤 PR F 로 짓는다(대안은 PR C 에 더하기 · 뒤 조각으로 미루기).
  틀린 줄이 있으면 맞는 줄만 저장한다(대안은 하나도 저장하지 않기). 엑셀은 붙여넣기까지 — 파일 올리기는 하지 않는다. 시트의
  꼴 · 한 번에 받는 줄 수 · 붙여넣기의 칸 순서는 PR F 를 열기 전에 정한다. → 정함, 아래 「저자 인터뷰로 정한 것」.

- 같은 사업자등록번호 — 막지 않고 경고만 한다(저자 판정 2026-11-03, PR D 검토). 한 사업자를 지점별로 둘 수 있어서다(대안은
  저장 거절). 저장하면 목록의 저장 알림에, 그 거래처의 수정 화면에는 사업자등록번호 칸 아래에 같은 번호를 쓰는 다른 거래처(「사용
  안 함」 포함)를 코드와 링크로 보인다. 입력하는 동안에는 보지 않는다 — 저장한 뒤에 보인다. 시트형 등록(PR F)도 같은 규칙이다.

- 해외 거래처 — 저자 판정(2026-11-03, PR D 검토). 거래처에 국가(공통코드 `COUNTRY`, 국제 표준 두 글자 `KR` · `US` · `JP`)와
  해외 사업자번호를 둔다. 한국이면 사업자등록번호 꼴을 보고, 아니면 글자 그대로 받는다. PR F 앞의 PR G 로 짓는다(대안은 PR D 에
  더하기 · 조각 「영업」 · 「구매」로 미루기 · 해외 거래처를 다루지 않기). ADR 0011.

- 설명용 칸 — 저자 판정(2026-11-04, PR F 검토). 품목 · 거래처에 보통 ERP 의 설명용 칸(분류 · 사양 · 사업자 · 연락 정보)을 PR F 뒤의

## 2026-11-03 — PR E 를 열기 전에 정한 것

업무에 영향이 없는 기술 결정이라 Claude 가 정했다. 화면은 PR C · D 의 기준정보 화면과 같은 틀이다 — 아래는 다른 것과 새로 정한 것만 든다.

- **주소** — 묶음 목록 `/system/codes`, 한 묶음의 값 `/system/codes/<묶음>`(예: `/system/codes/UNIT`), 값 추가 `/system/codes/<묶음>/new`,
  값 수정 `/system/codes/<묶음>/<코드>`. 묶음 · 값의 코드는 바뀌지 않아 주소로 쓴다 — 한 묶음을 링크로 건넬 수 있다. 시스템 코드 묶음의
  추가 · 수정 주소는 「없는 화면」이다.
- **묶음을 고르는 법** — 묶음 목록(코드 · 이름 · 가름 · 값의 수)에서 고르고, 값 화면 위에도 묶음 단추를 두어 다른 묶음으로 바로 옮긴다.
- **값 목록** — 「사용 안 함」까지 늘 보인다(표시가 붙는다). 묶음마다 100개 안이라 거르지 않고, 「사용 안 함」인 값을 다시 「사용」으로
  돌리려면 보여야 해서다. 찾기 · 「사용 안 함 포함」 칸이 없다. 정렬 순서 · 코드 순이다.
- **메뉴** — 「시스템 관리」를 모듈 맨 끝(마스터플랜 순서)에 더하고, 그 아래 「공통코드」 · 「회사 정보」 · 「사용자」 · 「권한」을 둔다.
  메뉴는 마스터플랜의 「·」로 나뉜 것을 하나씩 두는 규칙(PR C)대로라 「사용자 · 권한」을 둘로 나눴다. 뒤의 셋은 조각 「인사」가 짓고 그때까지
  「준비 중」이다.
- **코드 칸** — 앞뒤 빈칸만 지우고, 소문자를 대문자로 바꾸지 않는다 — 꼴을 알린다(사업자등록번호에 붙임표를 넣지 않는 것과 같다).
- **정렬 순서의 기본값** — 새 값 칸에 그 묶음의 가장 큰 정렬 순서 + 10(999 까지)을 넣어 둔다 — 그대로 저장하면 맨 아래에 붙는다.
- **겹침** — 묶음 안의 겹침은 DB 의 유일 제약이 막고, 거절되면 코드 칸에 알린다. 겹친 값이 「사용 안 함」이면 새로 넣지 말고 그 값을
  「사용」으로 바꾸라고 알린다. 등록 상한(묶음마다 100)은 PR C 1회차의 경계대로 잠금 안에서 센다 — 잠금 번호 `2026110304`.
- **시스템 코드를 바꾸는 요청** — 화면에 길이 없고, 화면을 건너뛴 요청도 서버가 「시스템 코드라 화면에서 바꿀 수 없습니다」로 거절한다.
  없는 묶음에 값을 넣는 요청은 「없는 묶음」으로 거절한다 — 묶음은 만들지 않는다.
- **⑤ 에 더하는 검증** — 묶음 목록의 가름 · 값의 수, 시스템 코드 묶음 둘 모두에서 추가 · 수정의 거절, 동시에 같은 코드를 더하면 하나만
  저장되는 것, 상한 100(동시 추가 포함), 더한 단위로 품목을 등록하는 것, 「사용 안 함」 단위를 이미 쓴 품목이 그대로 저장되는 것을 시험으로 본다.

## 2026-11-04 — PR G 를 열기 전에 정한 것

업무에 영향이 없는 기술 결정이라 Claude 가 정했다. 업무 결정(국가는 사용자 코드, 처음 값, `KR` 은 「사용 안 함」 불가, 해외 샘플 둘)은 위 ④ 「저자
인터뷰로 정한 것」 · ADR 0011 그대로다.

- **칸** — 거래처에 `country`(공통코드 `COUNTRY`, 기본 `KR`)와 `foreign_biz_no`(해외 사업자번호)를 더한다. 품목처럼 늘 같은 묶음 칸
  `country_group` = `COUNTRY` 를 두고 묶음 + 코드로 `codes` 를 가리킨다. 사업자등록번호(`biz_no`)는 그대로 두고 칸을 나눈다 — 뒤 조각
  (세금계산서 · 영세율)이 한국 번호만 읽기 쉽고, 한국 번호의 꼴 검사를 DB 가 그대로 막는다. 한 칸에 둘을 담는 대안은 칸이 하나 줄지만
  꼴 검사가 국가에 따라 갈려야 한다.
- **DB 가 막는 것** — 한국이면 해외 사업자번호가 비고, 아니면 사업자등록번호가 빈다(`partners_biz_no_by_country`). 해외 사업자번호는
  비우거나 1 ~ 30자(`partners_foreign_biz_no_length`). 국가는 공통코드에 있는 값만(`partners_country_fk`).
- **해외 사업자번호의 길이** — 30자. 나라마다 꼴이 달라(미국 EIN 10자 · 일본 법인번호 13자 · 중국 통일사회신용코드 18자 · EU 부가세
  번호 14자 안팎) 글자 그대로 받고, 가장 긴 것에 여유를 둔다. 앞뒤 빈칸만 지운다.
- **겹침 경고의 범위** — 한국은 사업자등록번호가 같은 것, 해외는 **국가와 해외 사업자번호가 함께** 같은 것이다. 나라가 다르면 같은
  글자여도 다른 번호다. 경고의 자리 · 말은 PR D 그대로다(「같은 해외 사업자번호」).
- **화면** — 국가는 「거래처명 · 구분」 다음의 고르는 칸이다. 한국이면 사업자등록번호 칸이, 아니면 해외 사업자번호 칸이 보이고, 보이는
  칸 하나만 보낸다. 국가를 바꾸면 다른 쪽 번호는 저장할 때 빈다. 서버도 국가에 맞지 않는 번호 칸은 보지 않는다. 국가 칸이 아예 오지
  않은 요청은 한국으로 본다(DB 의 기본값 · PR F 의 「빈 칸은 KR」과 같다).
- **「사용 안 함」 국가** — 단위와 같다. 새 거래처와 국가를 바꾸는 수정은 사용 중인 국가만 받고, 이미 「사용 안 함」 국가를 가진 거래처는
  그대로 저장된다. 수정 화면의 국가 목록에는 그 국가가 「(사용 안 함)」으로 남는다.
- **`KR` 의 잠금** — 「시스템 관리 › 공통코드 › COUNTRY › KR」의 수정 화면에는 사용 여부 칸 대신 「늘 사용」 안내가 있고, 화면을 건너뛰고
  「사용 안 함」을 보내도 서버가 거절한다. 이름 · 정렬 순서는 고칠 수 있다. 잠긴 값의 목록은 `src/lib/master-codes.ts`
  (`ALWAYS_ACTIVE`) 한 곳이다.
- **목록** — 「국가」 칸(코드와 이름, 휴대폰 폭에서는 코드만)을 더하고, 「사업자등록번호」 칸을 「사업자번호」로 바꿔 해외 거래처는 해외
  사업자번호를 보인다(휴대폰 폭에서는 숨김 그대로).
- **마이그레이션** — 둘로 나눈다. `0001_country_codes`(손으로 쓴 것 — `drizzle-kit generate --custom`)는 데이터가 있는 DB 에만 `COUNTRY`
  묶음과 처음 값을 넣는다 — 기존 거래처가 `KR` 을 가리킬 수 있게. 빈 DB 에는 넣지 않는다 — 배포 빌드가 「묶음 0 행」을 보고 샘플 전체를
  넣는다. `0002_partner_country`(drizzle-kit 이 만든 것)가 칸 · 제약을 더한다. 기존 거래처는 기본값 `KR` 로 채워진다. 만든 SQL 은 손으로
  고치지 않는다는 규칙(`docs/schema.md`)을 지키려 데이터 쪽을 따로 둔다.
- **앞 배포로 되돌릴 때** — 새 칸은 기본값이 있어 앞 배포의 등록 · 수정이 그대로 돈다. 다만 앞 배포에서 해외 거래처의 사업자등록번호를
  넣으면 DB 가 거절해 「저장하지 못했습니다」가 된다 — 해외 거래처를 모르는 앞 배포에서 그 거래처를 고칠 일은 드물어 그대로 둔다.
- **⑤ 에 더하는 검증** — 데이터가 있는 DB 에 마이그레이션을 적용하면 국가 값이 샘플과 같게 들어가고 기존 거래처가 `KR` 이 되는 것, 빈
  DB 에는 마이그레이션이 국가를 넣지 않고 샘플이 넣는 것, 한국 ↔ 해외로 바꿀 때 다른 쪽 번호가 비는 것, DB 의 새 제약 셋을 시험으로 본다.

## 2026-11-04 — PR F 를 열기 전에 정한 것

업무에 영향이 없는 기술 결정이라 Claude 가 정했다. 업무 결정(100줄, 정해진 칸 순서와 머리글 줄 복사 단추, 고르는 값은 이름 · 코드 둘 다,
빈 칸은 한 건 등록의 기본값, 맞는 줄만 저장)은 위 ④ 「저자 인터뷰로 정한 것」 그대로다.

- **주소** — `/master/items/sheet` · `/master/partners/sheet`. 목록 머리에 「새 ○○ 등록」 옆 「시트형 등록」 단추를 둔다. 메뉴는 늘리지
  않는다 — 품목 · 거래처 화면 안의 다른 입력 방법이다.
- **칸** — 품목은 유형 · 품명 · 규격 · 단위 · 조달구분 · 수입검사 · 출하검사 · 리드타임(일) · 안전재고 · 최소 발주 · 생산량 · 발주 · 생산
  배수(한 건 등록 화면의 순서), 거래처는 거래처명 · 매입처 · 매출처 · 국가 · 사업자번호. 거래처의 사업자번호는 한 칸이고 국가가 한국이면
  사업자등록번호, 아니면 해외 사업자번호로 읽는다(한 건 등록은 국가에 맞는 칸 하나만 보인다 — 같은 규칙). 칸의 정의는
  `src/lib/sheet-columns.ts` 한 곳이고, 화면 위 「칸 순서와 넣는 값」이 같은 정의로 칸마다 받는 값을 보인다(단위 · 국가는 공통코드의 사용
  중인 값). 칸은 모두 글 칸이다 — 고르는 칸(select)은 붙여넣은 글을 받지 못해서다.
- **붙여넣기** — 시트의 어느 칸에서든 붙여넣으면 그 칸부터 오른쪽 · 아래로 채우고 모자란 줄을 더한다. 엑셀이 따옴표로 감싼 칸(안에 줄바꿈 ·
  탭)도 푼다. 첫 줄의 칸이 모두 칸 이름과 같으면(띄어쓰기는 보지 않음) 머리글로 보고 건너뛴다. 100줄을 넘는 줄과 시트보다 많은 칸은 버리고
  그 수를 알린다. 한 칸짜리 글은 가로채지 않는다(브라우저가 그 칸에 붙인다). 처음 시트는 다섯 줄, 「줄 더하기」가 다섯 줄씩 100줄까지.
- **이름 · 코드 · Y/N** — 코드는 대소문자를 가리지 않고(`kg` → `KG`), 코드가 이름보다 먼저다. 같은 이름의 단위 · 국가가 둘 이상이면
  코드로 넣으라고 거절한다(공통코드의 이름은 겹칠 수 있다). 켬 · 끔은 `Y` · `O` · 「예」 / `N` · `X` · 「아니오」. 매입처 · 매출처의 빈 칸은
  `N` 이다 — 둘 다 `N` 이면 「구분」으로 거절한다.
- **검사** — 시트의 한 줄을 이름 · 코드 · Y/N · 기본값으로 바꾼 뒤 한 건 등록의 검사(`parseNewItem` · `parseNewPartner`)를 그대로
  부른다(`src/lib/sheet-input.ts`) — 칸의 규칙이 한 건 등록과 갈리지 않게다. 「사용 안 함」 단위 · 국가의 거절도 한 건 등록과 같다.
- **저장** — 시트는 칸 key → 글자의 JSON 하나로 서버 액션에 간다. 서버는 줄이 100을 넘거나 꼴이 틀리면 DB 에 닿지 않고 통째로 거절한다.
  모든 칸이 빈 줄은 건너뛴다. 맞는 줄은 한 트랜잭션에서 테이블의 잠금(PR C 1회차의 경계 — 품목 `2026110301` · 거래처 `2026110303`)을
  쥐고 줄 차례로 센다 · 번호를 받는다 · 넣는다(`registerRowsWithCode`) — 코드가 줄 차례로 붙고, 상한에 닿은 뒤의 줄은 「등록 상한」으로
  남는다. 줄마다 저장점(savepoint) 안에서 넣어 DB 제약에 걸린 줄만 되돌아가고 앞뒤 줄은 저장된다. 제약 위반이 아닌 실패(접속 끊김
  따위)는 트랜잭션을 통째로 되돌려 아무것도 저장되지 않고, 시트는 그대로 남아 「잠시 뒤 다시 저장하세요」가 보인다. 대안은 줄마다

- **조회의 줄 수** — 등록의 목록과 같이 나눠 보이지 않고 다 보인다. 등록 상한(품목 2,000 · 거래처 1,000)과 매일 밤 되돌림이 줄 수를 막는다.
- **DB 는 그대로** — 테이블 · 마이그레이션을 바꾸지 않는다. 찾기는 읽는 쿼리의 조건만 늘린다.
