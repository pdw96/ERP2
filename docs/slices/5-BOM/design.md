## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **부모와 자품목의 유형** — 부모는 반제품 · 완제품, 자품목은 원자재 · 반제품 · 부자재다. 소모품 · 완제품은 자품목이 되지 않는다. 검사는 저장하는 순간의 품목 유형으로 한다.
- **품목마다 하나** — 부모 품목 하나에 BOM 머리가 하나다(DB 가 막는다).
- **자릿수와 범위** — 기준수량은 부모 단위, 소요량은 자품목 단위의 자릿수까지이고 둘 다 0 보다 크다. 로스율은 0 이상 100 미만, 소수 둘째 자리까지.
- **돌고 돌지 않는다** — 저장된 BOM 을 어느 품목에서 아래로 끝까지 따라가도(모든 줄, 적용일자와 상관없이) 같은 품목이 다시 나오지 않는다. 같은 순간의 두 저장이 함께 순환을
  만들지 못한다 — BOM 을 고치는 저장은 트랜잭션 안에서 하나뿐인 잠금을 잡고 검사한다.
- **적용 기간이 겹치지 않는다** — 한 BOM 안에서 같은 자품목의 줄끼리 적용 기간이 겹치지 않는다. 그래서 어느 기준일이든 한 부모 아래 같은 자품목은 많아야 한 줄이다.
- **「사용 안 함」** — 「사용 안 함」 품목을 새 부모 · 새 자품목으로 넣는 저장은 거절된다. 이미 든 줄은 그대로 저장되고 펼쳐진다.
- **BOM 에 든 품목의 단위는 바뀌지 않는다** — 부모나 자품목으로 BOM 에 든 품목은 품목 등록(한 건 수정 · 시트)에서 단위를 바꾸지 못한다. 수불이 있는 품목과 같은 규칙 · 같은
  잠금이다(ADR 0015) — 기준수량 · 소요량의 뜻이 바뀌지 않는다.
- **한 저장은 통째로** — 한 BOM 의 저장(머리 + 줄 여럿)은 다 서거나 하나도 서지 않는다. 거절되면 DB 는 저장 전과 같고, 화면에 넣은 값이 남는다.
- **남이 고친 BOM 을 덮지 않는다** — 저장 · 지우기는 화면을 연 때의 버전이 맞을 때만 선다. 그 사이 다른 사람이 같은 BOM 을 저장했으면 거절하고 다시 열라고 알린다(재고 실사와
  같은 꼴).
- **등록 상한** — BOM 하나에 줄 200, BOM 줄 전체 20,000. 누가 끝없이 넣어도 무료 저장 한도에 닿지 않는다(BOM 머리는 품목마다 하나라 품목 상한 2,000 을 넘지 않는다).
- **정전개의 필요량** — 단계마다 필요량 = 윗 단계의 필요량 × 소요량 ÷ 기준수량 × (1 + 로스율 ÷ 100), 첫 단계의 윗 필요량은 고른 수량이다. 기준일에 적용되는 줄(시작일 ≤ 기준일,
  종료일이 비었거나 ≥ 기준일)만 쓴다. 계산은 끝수를 버리지 않은 십진수로 하고 보일 때만 끝수를 정한다(④).
- **역전개** — 고른 품목을 기준일에 적용되는 줄로 쓰는 부모를 위로 끝까지 보인다. 정전개와 같은 줄을 거꾸로 읽은 것이다 — 어느 부모 · 자품목 쌍이든 정전개에 보이면 역전개에도
  보인다.
- **읽기만** — BOM 조회와 그 읽기는 DB 에 쓰지 않는다(서버 액션이 없다).
- **넣은 글자는 로그에 남지 않는다** — 실패 로그는 오류 코드만.
- **휴대폰 폭** — 390px 에서 두 화면이 가로로 넘치지 않는다. 넓은 표는 옆으로 밀고 코드 · 이름 칸이 왼쪽에 남는다.

**보장하지 않는 것(알려진 한계)**

- 끝수를 올린 계획량 · 자재별 합계 · 재고와 견주기 — 하지 않을 일 4. 정전개의 필요량은 MRP 가 쓸 계산과 식은 같지만 끝수의 처리는 조각 「MRP」의 착공이 정한다.
- 품목을 BOM 저장 뒤에 고치면 — 품목 유형은 등록 뒤 바뀌지 않지만(ADR 0003 · 0013), 「사용」 여부는 고칠 수 있다. 「사용 안 함」이 된 품목의 줄은 남는다(② 「사용 안 함」).
- 깊은 BOM — 펼치기는 20 단계에서 멈춘다. 샘플은 세 단계다.
- 고친 이력 · 대체 자재 · 투입 공정 — 하지 않을 일 1 · 3 · 7.
- 같은 날 안의 장난 — 누가 엉뚱한 BOM 을 넣으면 그날 밤 되돌림까지 보인다(ADR 0004).
- 누구나 쓰는 입구의 호출 빈도 — 「포트폴리오 정리」로 넘긴 것 그대로(마스터플랜 「범위 변경」 2026-11-03).

## ③ 받는 입력

**BOM 등록의 저장**(PR A — 서버 액션). 아래 밖의 이름은 읽지 않고, 아래 값의 틀림은 저장 전에 거절하며 칸마다 까닭을 보인다.

| 이름 | 받는 값 |
|---|---|
| 부모 품목 | 품목코드 — 있는 품목이고 유형이 반제품 · 완제품, 새 BOM 이면 「사용」 |
| 기준수량 | 0 보다 큰 수, 부모 단위의 자릿수까지, 천 단위 쉼표는 받는다 |
| 줄마다 자품목 | 품목코드 — 있는 품목이고 유형이 원자재 · 반제품 · 부자재, 새 줄이면 「사용」, 부모가 아님 |
| 줄마다 소요량 | 0 보다 큰 수, 자품목 단위의 자릿수까지 |
| 줄마다 로스율 | 비우면 0. 0 이상 100 미만, 소수 둘째 자리까지 |
| 줄마다 적용 시작일 · 종료일 | `YYYY-MM-DD` 의 있는 날짜. 시작일은 반드시, 종료일은 비우면 계속이고 시작일보다 앞서지 않음 |
| 줄마다 비고 | 0 ~ 200자 |
| 줄의 수 | 1 ~ 200, 저장 뒤 BOM 줄 전체가 20,000 을 넘지 않음 |
| 버전 | 화면을 연 때의 그 BOM 의 버전(새 BOM 이면 없음) — DB 의 버전과 다르면 거절 |

줄 지우기 · BOM 지우기는 부모 품목코드 · 버전(과 줄의 번호)만 받는다.

**BOM 조회의 주소**(PR B). 아래 밖의 이름은 읽지 않는다. 거르기 값(품목 · 기준일 · 수량)이 틀리면 버리고 알림을 낸다 — 품목이 버려지면 펼치지 않고 고르라는 안내가 보인다.

| 이름 | 받는 값 |
|---|---|
| `mode` | `down`(정전개) · `up`(역전개). 틀리면 알림 없이 `down` |
| `item` | 품목코드의 꼴(유형 머리 + 네 자리 이상의 일련) — 정전개는 BOM 이 있는 품목, 역전개는 어느 품목이든 |
| `date` | `YYYY-MM-DD` 의 있는 날짜. 비면 오늘 |
| `qty` | 정전개만 — 0 보다 크고 부모 단위의 자릿수까지, 상한 1,000,000,000. 비면 그 BOM 의 기준수량 |

## ④ 결정

**정한 것**

- 기준수량 · 로스율 · 부자재만(소모품은 BOM 밖) · 줄마다 적용일자 · 품목마다 BOM 하나 · 대체 없음 · 메뉴 「BOM 등록」 · 「BOM 조회」 둘 — 저자 판정(2026-11-12 착공 인터뷰).
  ADR 0026 의 1 ~ 6.
- 표 둘(머리 · 줄) · 수량은 `numeric` 십진수 · 순환 검사는 잠금 하나 아래 트랜잭션 · 펼치기는 재귀 쿼리 하나와 20 단계 상한 — 업무에 영향이 없는 기술 결정(Claude 추천).
  ADR 0026 의 기술 결정.
- 착공 PR 에는 결정 문서만 · 절차 · 협업 도구의 결정은 저자가 고른다 — 저자 판정(2026-11-12 착공 인터뷰, 조각 「재고 현황」 「닫으며」가 이 착공 전으로 넘긴 것). ADR 0027.
  이 조각의 구현이 아니라 모든 조각의 작업 규칙이고, `CLAUDE.md` · `Profile.md` 의 줄은 이 착공 PR 이 머지된 뒤 따로 낸 문서 PR 이 더한다(ADR 0027 결과).
- 아래 일곱은 Claude 가 낸 안을 착공 PR 검토 중에 저자가 골랐다(2026-11-12 인터뷰, 모두 추천대로). ADR 0026 의 7 ~ 13.
  - **부모는 반제품 · 완제품, 자품목은 원자재 · 반제품 · 부자재** — 품목 유형으로 가른다(조달구분이 아니라). 완제품을 다른 완제품에 넣는 묶음 판매는 상품이 없어(ADR 0019 결과)
    두지 않는다.
  - **돌고 도는 BOM 은 적용일자와 상관없이 막는다** — 기간이 겹치지 않아도 같은 두 품목이 서로의 아래에 있는 BOM 은 거절한다. 펼치는 기준일마다 결과가 갈리지 않게 하려고서다.
  - **적용 종료일은 그날까지** — 옛 줄 종료일 11-30 · 새 줄 시작일 12-01 이 이어진다.
  - **「사용 안 함」 품목의 줄은 남는다** — 새로 넣지만 막고, 이미 든 줄은 표시만 한다(지우면 지난 구성이 사라진다).
  - **BOM 에 든 품목은 단위를 바꾸지 못한다** — 수불이 있는 품목의 규칙(ADR 0015)을 넓힌다. 바꾸려면 BOM 에서 빼고 바꾼다.
  - **줄 지우기 · BOM 지우기는 된다** — 아직 BOM 을 읽어 가는 조각(작업지시)이 없다. 설계변경은 지우지 않고 적용일자로 남기라고 등록 화면이 안내한다.
  - **정전개의 필요량은 자품목 단위의 자릿수로 올려 보인다** — 자재는 모자라면 안 되니 올림이다(예: 0.0042 KG → 0.005 KG). 계산은 올리지 않은 수로 이어 가고, 단계마다 보일
    때만 올린다. 대안은 반올림 · 자릿수를 늘려 보이기. MRP 의 끝수 처리는 그 착공이 따로 정한다(하지 않을 일 4).

- **샘플 BOM**(저자 판정 — 착공 PR 검토 중 2026-11-12 인터뷰, 추천대로) — 이미 있는 샘플 품목만 쓴다. 기준수량은 자품목이 단위의 자릿수 안에서 적히게 골랐다 — 웨이퍼(EA,
  정수) 때문에 반제품 · 센서 IC 는 10,000 EA, 전원 관리 IC 는 릴 하나(2,500 EA)에 방습백 하나라 2,500 EA. 적용 시작일은 되돌린 날 D 에서 180일 전이고 종료일은 비운다 — 설계변경
  줄만 다르다.

  | 부모(기준수량) | 자품목 | 소요량 | 로스율 |
  |---|---|---|---|
  | 전원 관리 IC `FG-0001`(2,500 EA) | 몰딩 완료품 `SF-0002` | 2,500 EA | 1% |
  | | 캐리어 테이프 `SM-0001` | 10 M | 2% |

## ⑤ 검증 계획

DB 는 PGlite(내 컴퓨터에서 도는 PostgreSQL)에 레포의 마이그레이션을 그대로 적용해 실제 SQL 을 돌린다 — 키가 필요 없다. 이 조각은 펼친 필요량과 돌고 도는 BOM 의 거절을 처음
지으므로 `CLAUDE.md` 에 따라 PR A · B 는 아래 시험 없이 머지하지 않는다.

**BOM 의 시험 규칙**(PR A · B — 한 갈래의 시험이 다 지는 것)

- **B1 거절 시험**은 저장이 거절된 뒤 BOM 두 표를 통째로 읽어 저장 전과 같은지와, 거절이 그 칸의 까닭(③ 의 칸 이름)을 내는지를 함께 본다 — 까닭만 보지 않는다.
- **B2 성공 시험**은 저장 뒤 BOM 두 표를 DB 에서 다시 읽어 넣은 값(줄의 수 · 수량 · 로스율 · 날짜)과 견주고, 「돌고 돌지 않는다」 · 「적용 기간이 겹치지 않는다」를 표 전체에서
  다시 센다 — 함수의 돌려준 값만 보지 않는다.
- **B3 펼치기 시험**은 정전개 · 역전개가 낸 줄을 시험 안에서 따로 계산한 기대값(BOM 줄 전체에서 길마다 곱해 센 필요량 · 기준일에 적용되는 줄)과 견준다. 정전개와 역전개가 같은
  쌍을 보이는지(② 「역전개」)를 샘플과 정한 씨앗의 임의의 BOM 묶음으로 본다.
- **B4** ② 의 보장마다, ③ 의 이름마다 맞는 꼴 하나와 틀린 꼴 하나 이상. 돌고 도는 BOM 은 적어도 자기 자신 · 한 단계 · 세 단계 · 적용 기간이 겹치지 않는 순환 · 같은 순간의 두
  저장(A 아래 B · B 아래 A). 버전은 적어도 같은 BOM 을 연 두 화면의 차례 저장. 상한은 적어도 줄 200 · 201. 적용 기간은 적어도 하루 겹침 · 종료일 = 다음 줄 시작일 − 1 · 끝없는 줄 둘 · 종료일 < 시작일. 정전개는 적어도 로스율 0 · 로스율 있음 · 같은 자재가 두
  길로 · BOM 없는 반제품 · 기준일이 적용 시작일 · 종료일과 같은 날 · 끝수가 생기는 필요량(올림).
- **B5 변조본** — 유형 검사 · 순환 검사 · 잠금 · 버전 · 적용 기간 겹침 · 기준일의 줄 고르기 · 필요량의 식 · 올림마다 그 규칙을 바꾼 사본에서 시험이 떨어지는 것을 그 PR 에서 한 번
  보인다. 보장의 조건 → 시험의 꼴 → 변조본의 대응은 그 PR 본문이 든다.

**PR 마다**

- **BOM 등록(PR A)** — 위 B1 · B2 · B4 · B5(쓰기의 검사 · 순환 · 겹침 · 「사용 안 함」 · 한 저장은 통째로 · BOM 에 든 품목의 단위를 품목 수정 · 시트가 바꾸지 못함), ③ 의 저장 이름마다의 입력 읽기, 메뉴(「BOM 등록」은 링크 ·
  「BOM 조회」는 준비 중), 샘플 BOM 넷과 설계변경 줄이 되돌림으로 다시 채워지는 것 — 시험으로. 미리보기 캡처(넓은 화면 · 390px)는 세션 대화로 저자에게 건네고, PR 본문에는 잰
  값(표 폭 = 보이는 폭 · 390px 의 scrollWidth = clientWidth · 샘플 BOM 의 줄 수)과 샘플 BOM 의 구성 · 수량 목록을 싣는다(조각 「재고 현황」 설계 끝 「닫는 PR 재감사 뒤 정한 것」의
  꼴).
- **BOM 조회(PR B)** — B3 · B4 · B5(정전개 · 역전개 · 기준일 · 올림), ③ 의 주소 이름마다의 읽기(틀린 값의 알림), BOM 조회에 서버 액션이 없는 것 — 시험으로. 미리보기에서
  시나리오(설계변경을 넣고 기준일을 바꿔 정전개 → 필요량이 바뀜, 역전개)를 돈 캡처는 세션 대화로, 잰 값(단계마다의 필요량 · 줄 수 · 폭)은 PR 본문에.
